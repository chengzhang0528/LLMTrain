# 术语速查

课程正文中的核心术语与本页保持同一份定义。每个词条都包含一句话解释和最常见的误解。英文术语会同时显示美式音标，点击旁边的播放按钮即可朗读；浏览器不支持语音合成时，会自动播放课程自带的离线发音。

| 术语 | 一句话解释 | 不要误解为 |
|---|---|---|
| <span id="term-token"></span>**token（词元）** | 文本经过分词规则得到的离散单元，随后会映射成整数 ID | 必然等于一个字或一个完整单词 |
| <span id="term-tokenizer"></span>**tokenizer（分词器）** | 把文本切成 token，并在 token 与整数 ID 之间转换的规则和词表 | 模型自己临时决定的切词方式 |
| <span id="term-vocab"></span>**vocab（词表）** | tokenizer 可以表示的 token 集合 | 模型掌握的全部知识 |
| <span id="term-parameter"></span>**parameter（参数）** | 模型中由训练确定的数字；只有未冻结参数会被更新 | 一个参数对应一条可直接读取的事实 |
| <span id="term-vector"></span>**vector（向量）** | 按顺序排列的一组数；维数是坐标数量，长度需要另外计算 | 有 10 个坐标就表示长度等于 10 |
| <span id="term-matrix"></span>**matrix（矩阵）** | 按行列组织的一组数；在线性计算中可充当输入到输出的变换规则 | 矩阵 W 就是输入空间或输出空间本身 |
| <span id="term-embedding"></span>**embedding（嵌入）** | 把离散 ID 映射为连续向量的可训练表示 | 人工指定的固定语义坐标 |
| <span id="term-hidden-state"></span>**hidden state（隐藏状态）** | 某一层、某一位置结合当前上下文形成的向量表示 | 与静态 token Embedding 永远相同 |
| <span id="term-hidden-dimension"></span>**hidden dimension（隐藏维度）** | 每个位置的隐藏表示包含的坐标数量，常记为 $D$ | 每一维都有固定可命名的人类语义 |
| <span id="term-tensor"></span>**tensor（张量）** | 按若干轴组织的一组数，是向量和矩阵的推广 | 轴的含义可以不说明，只看总元素数 |
| <span id="term-tensor-shape"></span>**tensor shape（张量形状）** | 各轴长度组成的记录，如 `(batch, time, hidden)` | 相同数字排列代表相同轴含义 |
| <span id="term-representation-space"></span>**representation space（表示空间）** | 模型用一组坐标和方向组织隐藏表示的高维空间 | 每个坐标轴都是人工预先定义的概念 |
| <span id="term-high-dimensional-space"></span>**high-dimensional space（高维空间）** | 需要许多坐标描述一个点或向量的空间 | 能像二维平面一样完整画出和直观看懂 |
| <span id="term-vector-norm"></span>**vector norm（向量范数）** | 把向量总体幅度汇总成非负标量的规则 | 能说明向量具体朝哪个方向 |
| <span id="term-cosine-similarity"></span>**cosine similarity（余弦相似度）** | 用夹角比较两个非零向量方向是否接近 | 等同于欧氏距离或原始点积 |
| <span id="term-euclidean-distance"></span>**Euclidean distance（欧氏距离）** | 两个点之间直线距离对应的常用度量 | 在所有高维表示任务中都天然最合适 |
| <span id="term-linear-projection"></span>**linear projection（线性投影）** | 用矩阵学习输入坐标的组合并映射到输出空间 | 只是 reshape，或输出维度越大知识越多 |
| <span id="term-subspace"></span>**subspace（子空间）** | 高维空间中由较少独立方向张成的受限空间 | 从原向量机械切出的一段固定语义坐标 |
| <span id="term-matrix-rank"></span>**matrix rank（矩阵秩）** | 矩阵可表达的独立方向数量 | 矩阵元素大小或参数数量 |
| <span id="term-dimensionality-reduction"></span>**dimensionality reduction（降维）** | 把高维数据摘要到较少维度以分析、压缩或可视化 | 能无损保留高维空间的全部关系 |
| <span id="term-pca"></span>**PCA（主成分分析）** | 寻找保留较大线性变化方向的降维方法 | 前两个主成分代表全部结构或真实语义轴 |
| <span id="term-tsne"></span>**t-SNE** | 强调局部邻域可视分离的非线性降维方法 | 二维簇间距离和簇大小可直接作全局比较 |
| <span id="term-umap"></span>**UMAP** | 基于邻域图和流形假设构造低维表示的方法 | 输出图就是原高维空间的唯一真实地图 |
| <span id="term-logits"></span>**logits** | softmax 之前用于比较候选 token 的任意实数分数 | 已经是概率或正确率 |
| <span id="term-softmax"></span>**softmax** | 把一组分数转换为非负且总和为 1 的相对权重 | 会让答案自动真实或概率自动校准 |
| <span id="term-loss"></span>**loss（损失）** | 训练目标对应的误差标量，优化器尝试让它下降 | 足以代表模型的全部质量 |
| <span id="term-gradient"></span>**gradient（梯度）** | loss 对各参数的局部变化率 | 直接给出全局最优答案 |
| <span id="term-gradient-norm"></span>**gradient norm（梯度范数）** | 把一组参数梯度的总体幅度汇总成一个标量 | 数值正常就表示每个参数的更新都合理 |
| <span id="term-learning-rate"></span>**learning rate（学习率）** | 控制每次参数更新幅度的超参数 | 越大就一定训练得越快越好 |
| <span id="term-optimizer"></span>**optimizer（优化器）** | 根据梯度及内部状态计算参数更新的算法 | 负责计算前向预测或损失 |
| <span id="term-batch"></span>**batch（批次）** | 一次前向与反向计算共同处理的一组样本 | 必然等于一次更新或整个数据集 |
| <span id="term-step"></span>**step（训练步）** | 本课程默认指一次优化器更新；具体日志可能另有定义 | 所有框架里的 step 都完全相同 |
| <span id="term-epoch"></span>**epoch（轮次）** | 训练过程大致遍历一遍训练集 | 总有固定数量的 step |
| <span id="term-context"></span>**context（上下文）** | 模型本次计算能够看到的 token 序列 | 已永久写入模型参数的记忆 |
| <span id="term-transformer"></span>**Transformer** | 由注意力、MLP、残差连接和归一化等模块组成的一类架构 | 所有大模型都只能采用同一种结构 |
| <span id="term-attention"></span>**attention（注意力）** | 根据 Query 与 Key 的匹配权重，对 Value 做加权汇总 | 权重就是完整可靠的人类可读解释 |
| <span id="term-causal-mask"></span>**causal mask（因果遮罩）** | 阻止当前位置读取未来 token 的遮罩 | 会阻止读取当前位置之前的内容 |
| <span id="term-backpropagation"></span>**backpropagation（反向传播）** | 用链式法则把误差逐层传回并计算梯度 | 本身就是优化器更新 |
| <span id="term-cross-entropy"></span>**cross-entropy（交叉熵）** | 衡量目标分布与预测分布差异的常用损失 | 就是准确率 |
| <span id="term-checkpoint"></span>**checkpoint（检查点）** | 权重及恢复训练所需状态的快照 | 天然就是可直接上线的完整产品 |
| <span id="term-pretraining"></span>**pretraining（预训练）** | 在大规模数据上学习通用模式的基础训练阶段 | 数据越多，回答就必然越真实 |
| <span id="term-continued-pretraining"></span>**continued pretraining（继续预训练）** | 在已有基础模型上继续用领域无标注数据训练 | 等于用少量问答样本做 SFT |
| <span id="term-post-training"></span>**post-training（模型后训练）** | 在已有基座上继续塑造指令、偏好、推理、安全或拒答等行为的一组训练阶段 | 自动补齐事实知识并保证原有能力不退化 |
| <span id="term-knowledge-distillation"></span>**knowledge distillation（知识蒸馏）** | 让学生模型学习教师的回答、概率、特征或策略信号 | 复制教师参数或保证能力无损 |
| <span id="term-off-policy-distillation"></span>**off-policy distillation（离策略蒸馏）** | 在固定教师轨迹或预收集数据上学习 | 与学生推理时访问的状态完全一致 |
| <span id="term-on-policy-distillation"></span>**on-policy distillation（在策略蒸馏）** | 学生先生成前缀，教师再在学生访问的状态上提供逐 token 信号 | 教师更强或信号更密就保证学得更好 |
| <span id="term-exposure-bias"></span>**exposure bias（暴露偏差）** | 训练依赖理想历史，推理却接着自身输出生成所形成的状态差异 | 单步准确就不会沿轨迹累积误差 |
| <span id="term-teacher-model"></span>**teacher model（教师模型）** | 在蒸馏中提供输出、概率、特征或评估信号的较强模型 | 教师的每个答案都是真值 |
| <span id="term-student-model"></span>**student model（学生模型）** | 在蒸馏中学习教师信号、通常更小或更便宜的模型 | 学生只能通过复制参数获得教师能力 |
| <span id="term-logit-distillation"></span>**logit distillation（logit 蒸馏）** | 让学生匹配教师在候选 token 上的 logits 或软概率 | 看到最终答案就获得完整概率信息 |
| <span id="term-sft"></span>**SFT（监督微调）** | 用输入与理想输出示例训练目标行为 | 会自动完成事实核验 |
| <span id="term-lora"></span>**LoRA** | 冻结大部分基础权重，用低秩矩阵学习权重增量 | 自动压缩推理模型或保证无损 |
| <span id="term-qlora"></span>**QLoRA** | 低比特保存冻结的基础模型，同时训练 LoRA 适配器 | LoRA 适配器本身被简单量化成 4 bit |
| <span id="term-rlhf"></span>**RLHF** | 利用人类偏好信号和强化学习优化行为的一类流程 | 所有对齐都只能通过它完成 |
| <span id="term-dpo"></span>**DPO** | 直接利用偏好样本对优化策略 | 不包含偏好目标或参考约束 |
| <span id="term-rag"></span>**RAG（检索增强生成）** | 检索外部资料并放入上下文辅助生成 | 能保证资料和答案都真实 |
| <span id="term-agent"></span>**Agent（智能体）** | 模型参与工具选择、读取结果和多步决策循环的应用结构 | 可脱离权限和人工确认自主执行 |
| <span id="term-inference"></span>**inference（推理）** | 使用训练好的参数计算预测或生成结果 | 通常会继续更新模型权重 |
| <span id="term-decoding-strategy"></span>**decoding strategy（解码策略）** | 根据 logits 选择下一个 token 的规则，如 greedy、temperature、top-k 或 top-p | 负责创造模型没学到的知识，或随机性是幻觉唯一原因 |
| <span id="term-overfitting"></span>**overfitting（过拟合）** | 训练数据表现改善，未见数据表现却没有同步改善 | 训练 loss 下降就一定没有发生 |
| <span id="term-catastrophic-forgetting"></span>**catastrophic forgetting（灾难性遗忘）** | 学习新任务或分布后，模型原有能力显著退化 | 新任务分数上升后不必检查旧能力 |
| <span id="term-validation-set"></span>**validation set（验证集）** | 不参与梯度更新，用来选配置和观察泛化的数据 | 反复针对它调参不会泄漏信息 |
| <span id="term-baseline"></span>**baseline（模型基线）** | 采用复杂方法前保存的可比较起点，如规则、提示或未微调模型 | 方法升级后就可以丢弃的临时演示 |
| <span id="term-model-hallucination"></span>**model hallucination（模型幻觉）** | 生成内容与事实、给定证据或任务状态不一致 | 只由随机采样造成，关闭 temperature 就能解决 |
| <span id="term-factuality"></span>**factuality（事实性）** | 回答中的可核验主张与外部事实是否一致 | 事实正确就表示一定忠于给定证据 |
| <span id="term-faithfulness"></span>**faithfulness（证据忠实度）** | 回答中的主张是否得到当前证据或工具结果支持 | 忠于证据就证明证据本身真实且完整 |
| <span id="term-confidence-calibration"></span>**confidence calibration（置信度校准）** | 让置信程度与长期观察到的正确率更匹配 | 把未知事实自动变成正确答案 |
| <span id="term-abstention"></span>**abstention（选择性回答/模型拒答）** | 证据或置信不足时不作答，在错误风险与覆盖率间取舍 | 拒答越多就必然越可靠 |
| <span id="term-quantization"></span>**quantization（量化）** | 用更低精度表示权重或激活，以降低内存和计算成本 | 总能四倍加速且完全无质量变化 |
| <span id="term-pruning"></span>**pruning（剪枝）** | 删除权重、通道、头或层等部分结构 | 出现很多零就一定能在目标硬件上变快 |
| <span id="term-kv-cache"></span>**KV Cache（KV 缓存）** | 生成时缓存历史 token 的 Key/Value，避免重复计算 | 主要用于降低训练显存 |
| <span id="term-memory-bandwidth"></span>**memory bandwidth（显存带宽）** | 单位时间内处理器与显存间能够传输的数据量 | 与显存容量或计算峰值是同一指标 |
| <span id="term-arithmetic-intensity"></span>**arithmetic intensity（算术强度）** | 计算量与数据搬运量之比 | 越高就代表模型质量或实际速度一定越高 |
| <span id="term-roofline-model"></span>**Roofline model（屋顶线模型）** | 同时表示计算峰值与带宽上限的性能分析模型 | 脱离真实测量也能给出唯一优化方案 |
| <span id="term-collective-communication"></span>**collective communication（集合通信）** | 多设备共同参与的规约、聚合、广播或全互换等操作 | 多卡通信成本会自动被计算完全隐藏 |
| <span id="term-allreduce"></span>**AllReduce（全规约）** | 规约各设备数据并把完整结果返回每个参与设备 | 只是把数据集中到一张卡 |
| <span id="term-zero"></span>**ZeRO** | 分片训练状态以减少数据并行中的重复显存占用 | 阶段越高就必然训练越快 |
| <span id="term-hbm"></span>**HBM（高带宽内存）** | 靠近加速器、为高吞吐数据访问设计的内存 | 容量越大就自动代表所有任务更快 |
| <span id="term-inference-latency"></span>**inference latency（推理延迟）** | 推理请求从进入系统到产生所需结果的时间 | 一个平均值足以代表所有延迟体验 |
| <span id="term-inference-throughput"></span>**inference throughput（推理吞吐）** | 单位时间完成的请求数或生成的 token 数 | 吞吐越高就代表每个用户等待越短 |
| <span id="term-effective-throughput"></span>**effective throughput / goodput（有效吞吐）** | 只统计满足质量、延迟和错误率等约束的有效工作量 | 总 tokens/s 上升就必然同步上升 |
| <span id="term-slo"></span>**SLO（服务等级目标）** | 针对指定负载和统计窗口设定的可度量服务目标 | 写“响应要快”就足够验证 |
| <span id="term-ttft"></span>**TTFT（首 token 延迟）** | 请求进入系统到返回第一个输出 token 的时间 | 能代表后续每个 token 的生成速度 |
| <span id="term-tpot"></span>**TPOT（每 token 延迟）** | 首 token 之后每生成一个输出 token 的平均时间 | 包含全部排队、检索和 prefill 时间 |
| <span id="term-prefill"></span>**prefill（预填充阶段）** | 推理时并行处理完整输入上下文并建立首轮状态与 KV Cache | 会一次生成完整回答，或与逐 token decode 是同一阶段 |
| <span id="term-chunked-prefill"></span>**chunked prefill（分块预填充）** | 把长输入预填充分散到多个调度步 | 只改变调度，不必检查语义和性能权衡 |
| <span id="term-continuous-batching"></span>**continuous batching（连续批处理）** | 请求到达和结束时动态调整 batch，使设备持续处理可运行请求 | 必然同时降低单请求延迟并提高吞吐 |
| <span id="term-paged-kv-cache"></span>**paged KV cache（分页 KV Cache）** | 按固定块管理和映射 KV Cache，以降低碎片并支持动态请求 | 会改变注意力语义或增加模型知识 |
| <span id="term-memory-wall"></span>**memory wall（内存墙）** | 数据搬运速度成为整体性能主要限制的现象 | 只是显存容量不足，换更大容量就能解决 |
| <span id="term-moe"></span>**MoE（混合专家）** | 通过路由让每个 token 只激活部分专家子网络 | 多个完整模型对同一答案投票 |
| <span id="term-fixed-size-state"></span>**fixed-size state（固定状态）** | 用固定数量的数值递推压缩历史 | 能无损记住无限历史 |
| <span id="term-linear-attention"></span>**linear attention（线性注意力）** | 把注意力改写为可递推或可重排的状态计算 | 都无损等价于 softmax 注意力 |
| <span id="term-state-space-model"></span>**state-space model（状态空间模型）** | 用状态递推处理序列的一类模型 | 自动保留任意长度历史的全部细节 |
| <span id="term-outer-product"></span>**outer product（外积）** | 把两个向量组合成矩阵 | 与得到单个标量的点积相同 |
| <span id="term-quantile"></span>**quantile（分位数）** | 按排序位置描述数据分布阈值的统计量 | 在所有软件中只有一种计算定义 |
| <span id="term-softcap"></span>**softcap（平滑封顶）** | 平滑限制数值幅度，同时保留连续梯度 | 能自动解决全部溢出和质量问题 |
| <span id="term-total-parameters"></span>**total parameters（总参数量）** | 模型包含的全部参数规模 | 等于每 token 实际经过的参数量 |
| <span id="term-activated-parameters"></span>**activated parameters（激活参数量）** | 稀疏模型一次 token 计算实际经过的参数规模口径 | 可直接当作精确 FLOPs 或完整显存 |
| <span id="term-scaling-laws"></span>**Scaling Laws（缩放定律）** | 限定范围内观察到的经验缩放关系 | 参数翻倍就保证能力固定增长 |
| <span id="term-expert-parallelism"></span>**expert parallelism（专家并行）** | 分布专家并按路由跨设备交换 token | 不会引入通信和负载问题 |
| <span id="term-context-parallelism"></span>**context parallelism（上下文并行）** | 把同一长序列的片段分到多个设备 | 就是不同样本的数据并行 |
| <span id="term-prefix-cache"></span>**prefix cache（前缀缓存）** | 复用完全相同前缀的已计算状态 | 文本近似或权限不同也能复用 |
| <span id="term-speculative-decoding"></span>**speculative decoding（推测解码）** | 草稿模型提议、目标模型批量验证的解码优化 | 草稿模型可绕过目标模型决定输出 |
| <span id="term-test-time-compute"></span>**test-time compute（测试时/推理时计算）** | 在推理阶段增加采样、搜索、验证或思考预算 | 增加预算就等于改变训练参数 |
| <span id="term-rlvr"></span>**RLVR（可验证奖励强化学习）** | 使用程序或明确验证器产生奖励训练策略 | 验证器高分必然等于真实任务完成 |
| <span id="term-reward-hacking"></span>**reward hacking（奖励投机）** | 利用奖励漏洞拿高分却未完成真实目标 | 分数提高就必然是能力提高 |
| <span id="term-agent-harness"></span>**agent harness** | 包围模型的提示、工具、执行循环与上下文管理 | Agent 成绩只反映基础模型权重 |
| <span id="term-qat"></span>**QAT（量化感知训练）** | 训练时模拟目标低精度效果以适应部署 | 所有组件都须同精度且不会掉点 |
| <span id="term-native-multimodal-pretraining"></span>**native multimodal pretraining（原生多模态预训练）** | 基础预训练阶段共同学习文本和其他模态 | 训练得早就必然优于外挂方案 |
| <span id="term-multimodal-alignment"></span>**multimodal alignment（模态对齐）** | 让不同模态表示对应同一对象、事件或任务关系 | 张量维度能连接就表示语义已经对齐 |
| <span id="term-kda"></span>**KDA** | 以门控 delta 状态更新压缩历史的注意力 | 能无损替代全部全局注意力 |
| <span id="term-gated-mla"></span>**Gated MLA** | K3 中保留 token 级全局交互的门控潜在注意力 | 与 KDA 的固定状态读写相同 |
| <span id="term-attnres"></span>**AttnRes** | 按学习权重读取多个历史层或块表示 | 只是普通残差相加改名 |
| <span id="term-stable-latent-moe"></span>**Stable LatentMoE** | 在较窄潜空间做稀疏专家计算并稳定尺度与负载 | 所有资源成本都按同一比例下降 |
| <span id="term-quantile-balancing"></span>**Quantile Balancing** | 按路由分数分位位置更新专家选择偏置 | 一步就永久保证完全均衡 |
| <span id="term-mopd"></span>**MOPD** | 把多个领域与推理努力策略蒸馏回单一模型 | 教师总能被无损合并 |
