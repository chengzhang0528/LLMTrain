# 方法选择

| 需求 | 先尝试 | 何时升级 |
|---|---|---|
| 固定规则或计算 | 普通代码 | 需要理解自由文本时引入模型 |
| 输出格式不稳定 | Schema、结构化输出、提示 | 大量高质量示例仍失败时 SFT |
| 私有或常变知识 | RAG | 检索正确但行为仍不稳定时再微调 |
| 特定语气/格式/任务行为 | 提示与少样本 | 稳定评测显示差距后 LoRA/SFT |
| 多步依赖工具结果 | 受控工作流 | 分支难以预先枚举时 Agent |
| 领域语言分布差异大 | 继续预训练实验 | 必须先有数据许可和独立评测 |
| 基础能力不足 | 换更适合的基础模型 | 资源充分时才考虑重训练 |
| 强模型有效但延迟或成本过高 | 先选现成小基座做任务基线 | 教师明显更强且任务边界清楚时做蒸馏 |
| 模型有效但显存或文件过大 | 先测目标硬件上的量化 | 质量下降超线时尝试 QAT、剪枝或更换学生模型 |
| 必须离线或端侧运行 | 从硬件、内存和延迟反推模型 | 小模型适配、蒸馏与结构化压缩联合评测 |

先定义失败和指标，再选方法。方法名不是目标。

升级到更重方法前，必须同时回答：失败是否能稳定复现；是否有不参与训练的验收集；是否具备合法数据、预算和回滚方案。缺少其中一项时，先补证据链，而不是直接微调或训练。

小模型相关方法的完整对照见[小模型与蒸馏路线](../06-拓展知识库/小模型与蒸馏/)。不要把“参数更少、权重精度更低、删除部分结构、使用草稿模型加速”都叫作同一种压缩。
