# D12：对齐、强化学习与评测

> **学习导航**：承接 D11 的监督微调；本课学习如何继续塑造行为，以及怎样用独立评测约束奖励投机；完成后应能把一句模糊要求改写成可执行、可复查的评测标准。

> **主线位置**：[模型训练总纲](模型训练总纲.md) -> D08-D11 -> **D12 后训练与独立评测** -> D13 应用系统。完成本课后回到总纲，重画从真实问题到部署的完整生命周期，而不只重画 loss 循环。

## 今日目标

能解释 SFT 之后为什么还会做偏好优化，并设计独立评测避免“只优化分数”。

## 为什么要学这一课

训练让参数更擅长续写或模仿示范，不代表生成行为会稳定遵循人的真实目标。偏好、奖励和安全规则都可能被投机，训练分数也可能与上线价值脱节。本课帮助你把“希望模型更好”改成可执行标准，并保留独立测试防止自我证明。

## 对齐在解决什么

预训练模型擅长续写，不自动等于有帮助、遵循指令或符合安全要求。后训练用示范、偏好比较、可验证奖励和安全数据塑造行为。

### RLHF 的典型高层流程

1. SFT 得到能按指令回答的模型。
2. 收集人类对多个回答的偏好。
3. 训练奖励模型近似偏好。
4. 用强化学习优化策略，同时常用参考模型约束偏离程度。

这是典型流程，不是唯一实现，也不保证“对齐了所有人类价值”。

### DPO 与 GRPO

第一次学习不需要记算法推导。先抓住共同结构：准备多个候选输出，依据人类偏好或可验证结果产生训练信号，再检查模型是否把分数漏洞当成捷径。DPO、GRPO 是实现这条结构的不同方法名。

- **DPO** 直接利用偏好对优化策略目标，避免显式训练并在线使用单独奖励模型的完整 RLHF 流程。
- **GRPO** 是一类基于同组多个输出相对奖励来估计优势的策略优化方法。它常见于可验证任务和推理训练讨论，但不是对所有任务普遍优于其他方法的定律。

### 在策略蒸馏：密集教师信号也有可学习性条件

另一条后训练路线是让学生先生成自己的轨迹，再由教师对学生实际访问的每个前缀给出下一 token 分布。这种在策略蒸馏提供比最终对错更密的信号，也减少只在固定教师答案上训练造成的状态错位。

但“教师更强”仍不等于“学生一定学得更多”。近期一项数学推理研究发现，教师与学生在高概率 token 区域是否兼容、教师是否真的提供学生未见的新能力，会影响训练是否前进；长轨迹尾部的逐 token 信号还可能先失真。这里先把它记为蒸馏和策略优化之间的连接，完整证据见 [在策略蒸馏论文深读](../06-拓展知识库/在策略蒸馏深读/)。

算法名称不能替代奖励和数据设计。奖励有漏洞时，模型可能学会投机，即 reward hacking。

可验证任务也不等于奖励天然可靠。代码执行器、数学判题器和搜索环境共同构成 agent harness；环境若过窄、超时策略不一致或答案可被格式漏洞绕过，模型可能优化“过判题器”而不是解决真实任务。训练奖励与最终评测应保持独立。

## 评测金字塔

1. **训练和验证 loss**：检查学习与泛化趋势。
2. **任务指标**：准确率、F1、pass@k、人工规则等。
3. **固定行为集**：关键提示、边界情况、拒答与格式。
4. **人工评测**：依据明确量表比较可用性。
5. **线上监测**：真实分布、延迟、成本和事故。

LLM-as-a-Judge 可扩展评测，但可能受位置、措辞、长度、模型家族和自我偏好影响，应随机交换顺序、隐藏模型身份、校准人工样本并报告不确定性。

## 评测四条纪律

- 训练集、开发集、测试集职责分离。
- 比较模型时统一提示、解码参数和预算。
- 报告样本数、均值之外的波动或置信区间。
- 防止测试数据污染训练数据；旧 Benchmark 高分不自动代表真实新任务。

读技术报告时，再追问九件事：评测版本、提示模板、采样参数、最大输出长度、工具权限、推理预算、样本是否污染、裁判如何校准、失败样本是否公开。缺少这些条件的单个榜单数字，只能作为有限证据。

课程写作也采用六级证据标签：`[一手事实]`、`[作者实验]`、`[作者主张]`、`[教学推导]`、`[工程估算]`、`[待核查]`。它们区分“来源强弱”，不把解释口吻伪装成论文结论。

## 安全不是一项总分

分别测试隐私泄露、提示注入、有害指导、偏见、越权工具调用和不可逆操作。一个平均分会掩盖低频高损害问题。
