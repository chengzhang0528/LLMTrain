# D07：模型如何生成文字

## 今日目标

理解自回归生成循环、温度、top-k、top-p、KV Cache 和停止条件。

## 一步一步生成

提示词编码为 `[12, 8, 31]` 后，模型输出下一个 token 的 logits。经过选择得到 ID `5`，新序列变成 `[12, 8, 31, 5]`，再预测下一步，直到遇到停止 token、长度上限或外部停止规则。

```text
上下文 -> logits -> 选择 token -> 追加 -> 再运行
```

模型不是先在内部写完整答案再一次显示；流式界面只是把逐步生成的结果尽早发送。

## 四种常见选择

- **Greedy**：每步选最高概率。确定性强，但不保证整段序列全局最优。
- **Temperature**：先用温度缩放 logits。较低通常更集中，较高通常更多样。
- **Top-k**：只在概率最高的 k 个候选中选择。
- **Top-p**：取累计概率达到阈值的最小候选集合，再从中选择。

top-k、top-p 和温度可以组合。它们改变输出分布，不能把事实错误自动变正确。

## 手工模拟

候选概率为：

| token | 概率 |
|---|---:|
| 蓝 | 0.50 |
| 晴 | 0.30 |
| 灰 | 0.15 |
| 雨 | 0.05 |

- Greedy 选“蓝”。
- top-k=2 只保留“蓝、晴”，随后重新归一化。
- top-p=0.8 时，排序后“蓝、晴”的累计概率刚好为 0.8。

## KV Cache 为什么有用

生成第 100 个 token 时，前 99 个位置的 Key/Value 在每层已经算过。KV Cache 保存这些中间结果，避免每步全部重算。它用内存换速度，所需内存随层数、序列长度、KV 头数、头维度、batch 和数据类型变化。

## 幻觉从哪里来

训练目标要求预测可能的下一个 token，不要求每句话都经过外部事实核验。数据矛盾、上下文不足、采样、任务分布变化都会导致自信但错误的回答。RAG、工具和验证器可以降低部分风险，但不能给出无条件保证。
