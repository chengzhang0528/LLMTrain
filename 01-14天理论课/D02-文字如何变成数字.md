# D02：文字如何变成数字

## 今日目标

理解 token、token ID、词表、Embedding 和位置信息的区别。

假设一个玩具词表是：

| token | ID |
|---|---:|
| 我 | 0 |
| 爱 | 1 |
| 学 | 2 |
| 习 | 3 |
| 学习 | 4 |
| `<eos>` | 5 |

“我爱学习”可能编码成 `[0, 1, 4, 5]`。这里的 `4` 只是编号，不代表“学习”的大小或价值。

真实 tokenizer 可能以字节、字符或子词为基础。一个汉字不保证等于一个 token，一个英文单词也可能被拆成多个 token。上下文窗口按 token 数计算，不按字数计算。

## Embedding 把 ID 变成可计算的向量

ID 只是索引。Embedding 表可以想成一张表，每个 token 对应一排会被训练的数字：

```text
ID 0 -> [ 0.2, -0.1,  0.7]
ID 1 -> [-0.3,  0.8,  0.1]
ID 4 -> [ 0.6,  0.4, -0.2]
```

开始训练时这些数通常没有我们想要的语义。训练不断调整它们，使模型更善于完成预测目标。相近含义是否靠近，要看训练和度量，不能只凭一张二维投影图断言。

## 顺序从哪里来

单纯把 token 放进注意力计算，不足以区分顺序。因此模型需要位置信息。原始 Transformer 使用正弦位置编码；许多现代 Decoder 模型使用 RoPE 等方案。具体方案不同，但共同目标是让模型处理先后和距离。

## 一个重要边界

Tokenizer 决定了模型能看到的最小符号和序列长度成本。换 tokenizer 通常会改变词表大小、Embedding 和 token ID，不能把任意 tokenizer 直接替换进已有模型而保持含义不变。

## 动手任务

给“机器学习”设计两种切分：

- 字符级：`机 / 器 / 学 / 习`
- 子词级：例如 `机器 / 学习`

比较词表大小、序列长度和遇到生词时的表现。不存在对所有语言和任务都最优的唯一切法。
