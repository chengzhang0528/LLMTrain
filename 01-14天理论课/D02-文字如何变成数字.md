# D02：文字如何变成数字

> **学习导航**：承接 D01 的“文本先变成 token 才能进入模型”；本课追踪文字到 token、ID、初始向量和上下文化表示；完成后应能看着一个例子指出每次变化后的对象类型。

## 今日目标

能沿着 `文字 -> token -> ID -> Embedding -> 隐藏状态` 追踪一次表示变化，并区分 token、token ID、词表、Embedding、上下文化隐藏状态和位置信息。

## 为什么要学这一课

模型的计算接口不会直接接收汉字或英文字符串；它接收 tokenizer 产生的整数 ID，再通过 Embedding 查表得到向量。这个接口限制不等于模型不能形成语义表示：语义相关的规律会在后续训练和上下文计算中体现出来。分词方式会改变序列长度、训练成本、多语言表现和生成边界；Embedding 负责把离散 ID 接入连续计算。不理解这条转换链，后面看到张量形状、注意力输入和词表采样时就只能背名词。

假设一个玩具词表是：

| token | ID |
|---|---:|
| 我 | 0 |
| 爱 | 1 |
| 学 | 2 |
| 习 | 3 |
| 学习 | 4 |
| `<eos>` | 5 |

“我爱学习”可能编码成 `[0, 1, 4]`；若模型约定在句末加入特殊 token，才会再追加 `<eos>` 对应的 `5`。这里的 `4` 只是编号，不代表“学习”的大小或价值。

真实 tokenizer 可能以字节、字符或子词为基础。一个汉字不保证等于一个 token，一个英文单词也可能被拆成多个 token。上下文窗口按 token 数计算，不按字数计算。

编码和解码通常能在同一 tokenizer 规则下往返，但不要把它理解成“任意切法都能无损恢复原始排版”。规范化、未知字符处理和是否自动加入特殊 token 都由具体 tokenizer 配置决定。

## Embedding 把 ID 变成可计算的向量

ID 只是索引。Embedding 表可以想成一张表，每个 token 对应一排会被训练的数字：

```text
ID 0 -> [ 0.2, -0.1,  0.7]
ID 1 -> [-0.3,  0.8,  0.1]
ID 4 -> [ 0.6,  0.4, -0.2]
```

开始训练时这些数通常没有我们想要的语义。训练不断调整它们，使模型更善于完成预测目标。相近含义是否靠近，要看训练和度量，不能只凭一张二维投影图断言。

真实模型的 Embedding 往往有数千维。这里的“维”是描述一个表示需要多少个坐标，不代表每一维都对应一个能命名的人类概念。二维、三维小例子只是为了能画图和手算。

## Embedding 只是表示旅程的起点

同一个 token ID 会先查到同一行 token Embedding，但这不是它在所有上下文中的最终表示。加入位置信息并经过 Transformer 层后，每个位置都会结合上下文形成新的隐藏状态：

`token ID` → 初始 Embedding → 第 1 层隐藏状态 → … → 最后一层隐藏状态

例如“苹果很好吃”和“苹果发布新品”可能从相同的“苹果”Embedding 出发，后续隐藏状态却因周围 token 不同而变化。讨论“某个词的向量”时，应继续追问：哪一个模型、哪一层、哪个位置、什么上下文？

ID 到 Embedding 是查表，不是把整数 ID 当作连续数值做“升维”。真正的线性投影发生在线性层中：模型用矩阵把一种表示映射成另一种表示，例如生成 Query、Key、Value，或把隐藏状态映射到词表 logits。

数学补充：[高维表示、投影与降维](../03-数学急救包/08-高维表示、投影与降维.md)。

## 顺序从哪里来

单纯把 token 放进注意力计算，不足以区分顺序。因此模型需要位置信息。原始 Transformer 使用正弦位置编码；许多现代 Decoder 模型使用 RoPE 等方案。具体方案不同，但共同目标是让模型处理先后和距离。

## 一个重要边界

Tokenizer 决定了模型能看到的最小符号和序列长度成本。换 tokenizer 通常会改变词表大小、Embedding 和 token ID，不能把任意 tokenizer 直接替换进已有模型而保持含义不变。

## 站内观察

比较页面预设的两种“机器学习”切分：

- 字符级：`机 / 器 / 学 / 习`
- 子词级：例如 `机器 / 学习`

先预测哪种切分会让序列更短，再对照词表大小、序列长度和遇到生词时的表现。不存在对所有语言和任务都最优的唯一切法，也不需要安装或运行分词器。
