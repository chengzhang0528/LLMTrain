# D01：大模型到底是什么

> **学习导航**：从日常对话体验出发；本课建立“输入、固定参数计算、候选概率、逐 token 输出”的总框架；完成后应能画出一次推理流程，并指出训练与推理在哪一步不同。

## 今日目标

能把大语言模型描述为“根据已有 token 预测下一个 token 概率的参数化模型”，并区分训练和推理。

## 为什么要学这一课

后面的 tokenizer、注意力、微调、RAG 和推理引擎分别处在不同层。如果没有一张总框架，初学者很容易把“资料放进上下文”误认为重新训练，把“回答变了”误认为参数变了，或把部署平台当成模型知识的来源。本课先建立共同地图，后续每个概念才能放回正确位置。

### 三个角色

- **Tokenizer**：把文本切成 token，再映射为整数 ID。
- **模型参数**：训练中调整的大量数字。它们共同决定输入经过模型后得到什么 logits。
- **生成策略**：把 logits 转成概率后，决定选概率最高的 token，还是按某种规则采样。

“大”通常指参数量、训练数据和训练计算的规模大，不代表模型必然正确，也不代表所有参数都保存了一条可直接查询的事实。

更完整地说，一个大语言模型至少包含两部分：**网络结构**规定数字怎样流动，**训练得到的参数**规定每一步具体怎样变换。输入上下文经过这些计算得到 logits，再转换成下一个 token 的候选概率。它是在训练数据中学到统计规律后进行条件预测，不是从内部逐句检索一份原文数据库。

## 训练与推理不是一回事

**训练**时有参考答案。模型预测下一个 token，计算预测与答案的差距，再用梯度更新参数。

**推理**时通常不更新参数。模型根据当前上下文反复预测和追加 token。把一段资料放入上下文能临时影响回答，但不等于模型已经把资料训练进参数。

| 阶段 | 有参考答案 | 更新参数 | 常见输出 |
|---|:---:|:---:|---|
| 训练 | 是 | 是 | loss、检查点 |
| 验证 | 是 | 否 | 验证 loss、指标 |
| 推理 | 通常没有 | 否 | 生成文本 |

## 它不是什么

- 不是实时更新的百科数据库，知识可能过时或混杂。
- 不是每次都按固定规则查到唯一答案的普通程序。
- 不能仅凭流畅语气证明事实正确。
- 是否具有意识属于哲学和科学争议，不能从“会对话”直接推出结论。

## 站内观察

观察页面给出的候选 token 分布，再在纸上或浏览器答题区预测哪一个会被选中，并检查概率之和是否为 1。这里练习的是读懂分布，不需要调用任何模型或外部服务。
