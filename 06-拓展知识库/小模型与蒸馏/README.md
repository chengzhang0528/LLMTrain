# 小模型与蒸馏路线

这条路线解决一个实际问题：强模型已经能完成任务，但成本、延迟、隐私或离线部署要求不允许一直调用它。目标不是盲目追求最少参数，而是在明确硬件和质量底线下得到更合适的模型系统。

## 路线能力

完成后应能审查一份预设小模型实验包：任务说明、冻结测试集、教师与学生基线、训练配置、蒸馏或压缩对照、延迟与显存报告、失败分类和模型卡。

## 学习顺序

1. [从问题到小模型](01-从问题到小模型.md)：判断从零训练、适配、蒸馏、压缩和 RAG 的边界。
2. [训练一个可用的小模型](02-训练一个可用的小模型.md)：从任务、数据和硬件约束设计训练闭环。
3. [模型蒸馏](03-模型蒸馏.md)：学习回答、logit、特征与策略蒸馏，并完成数字例子。
4. [压缩、部署与对照实验](04-压缩部署与对照实验.md)：把模型变成可测量的服务，而不是只比较文件大小。

## 贯穿案例

假设要把售后对话转换成固定 JSON：

```json
{
  "category": "refund",
  "urgency": "high",
  "reason": "重复扣款"
}
```

验收至少包含 JSON 合法率、类别 Macro-F1、关键字段遗漏率、每请求延迟、峰值显存和失败样例。这个任务边界清楚，既能先用规则和提示做基线，也适合比较小模型 SFT 与蒸馏。

本路线不要求学习者训练模型、配置环境或运行命令。训练与部署过程以预生成记录、参数卡和对照表呈现；学习者负责判断证据与方法边界。
