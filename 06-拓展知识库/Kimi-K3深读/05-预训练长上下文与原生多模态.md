# 预训练、长上下文与原生多模态

## 学习目标

理解“1M 上下文”和“原生多模态”都不是单一结构开关，而是架构、数据、训练课程和系统共同作用的结果。

## 缩放比较要各自调优

K3 报告比较余弦衰减与 WSD 时发现，两者的最优峰值学习率和 batch size 明显不同。若强迫它们共享同一组超参数，比较会偏向更适配这组参数的方法。因此作者为两种调度分别做缩放搜索，再比较各自较优配置。

这是可迁移的方法：比较 A/B 前先问“是否给了每种方法合理的调优预算”，而不是只追求控制变量表面一致。

## 长上下文的四块拼图

1. **架构**：KDA 用固定状态混合长序列，Gated MLA 保留全局交互。
2. **位置**：报告称 K3 不使用显式位置嵌入，位置线索由 KDA 的递推门控和衰减隐式携带。
3. **数据**：长文档需要去重、质量过滤和结构校验；仅上采样长文档仍可能只学到局部模式。
4. **课程**：窗口在预训练阶段从 8K 扩到 64K，在 cooldown 阶段从 256K 扩到 1M，把昂贵长序列集中在部分预算中。

因此“最大上下文是 1M”不能单独证明模型会可靠使用任意 1M-token 信息。还需要检索定位、跨段推理和干扰鲁棒性评测。

## 原生多模态是什么意思

报告的训练配方从一开始就联合优化语言和视觉，文本 token 与视觉表示进入同一个下一 token 预测目标，而不是先训练完整语言模型、再事后接入视觉编码器做对齐。

MoonViT-V2 把图像和视频编码后，经轻量投影进入共享 embedding 空间。2×2 pixel-shuffle 将视觉 token 数减少到四分之一。作者报告从零训练视觉编码器在该规模上能追平预训练初始化，并强调这是特定规模下的观察，不应写成“视觉编码器永远应该从零训练”。

## 四级练习

**L1 · 直接应用**：2×2 pixel-shuffle 理论上把 token 数变为原来的多少？

<details><summary>参考答案</summary>

空间两轴各合并 2 倍，因此 token 数约变为 $1/(2\times2)=1/4$。

</details>

**L2 · 变形迁移**：同样训练 token 预算下，为什么两种学习率调度仍可能需要不同 batch size？

<details><summary>参考答案</summary>

调度形状改变不同阶段的有效更新幅度和噪声，较优峰值学习率、batch 与训练稳定区间会随之改变。共享预算不等于共享最优超参数。

</details>

**L3 · 构造反例**：构造一个 1M-token 输入，使模型即使“装得下”也很难答对。

<details><summary>一种构造</summary>

在大量相似干扰段落中放入两个相互依赖、位置很远且名称近似的随机事实，最后要求精确组合。容量声明不保证定位和抗干扰能力。

</details>

**L4 · 多概念综合**：为什么不能把约 2.5 倍缩放效率提升归因于原生多模态？

<details><summary>参考答案</summary>

报告把架构、数据和训练改动共同纳入新模型族，曲线只给组合结果；没有单独移除原生多模态并保持其余条件一致的消融，就无法确定其单项贡献。

</details>
