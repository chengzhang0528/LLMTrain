# 领域助手后训练案例

> **学习导航**：汇总基座审计、SFT、偏好和回归；本课审阅一条预设的领域助手后训练方案；完成证据是能指出方案卡、数据卡、回归矩阵和模型卡是否相互支持。

## 本课目标

根据课程提供的冻结记录，解释每个版本怎样比较、何时停止，以及哪些证据不足以进入下一阶段。

## 为什么要学这一课

单独知道 LoRA、DPO 或 RLVR 的定义，仍不足以完成项目。真实后训练必须先证明需求，再组织数据、训练、评测、部署和回滚，任何一步缺失都会让“模型变好了”无法复查。

## 预设项目档案

档案中的目标是技术支持工单助手。输入是用户问题、产品版本和允许使用的资料；输出包含问题分类、需要追问的信息、建议回复和证据。信息不足、资料冲突或越权时必须拒答或升级人工。

## 对照版本

1. 基座 + 固定提示。
2. SFT 或 LoRA。
3. SFT + 偏好优化（只有偏好数据质量足够时）。
4. 可选：加入检索，但必须作为系统变量单独比较。

## 项目里程碑

| 阶段 | 预设材料 | 进入下一阶段的条件 |
|---|---|---|
| 任务冻结 | 问题合同、测试集、资源上限 | 目标和失败代价可评测 |
| 基座审计 | 配置、基线、失败分类 | 确认训练能解决主要缺口 |
| 数据准备 | 数据卡、分桶、泄漏检查 | smoke 和单 batch 测试通过 |
| 训练对照 | 检查点、日志、版本表 | 目标任务有稳定改善 |
| 回归验收 | 能力矩阵、安全与可靠性结果 | 未超过预设退化和风险阈值 |
| 复现审查 | 模型卡、部署与回滚说明 | 他人能够复核实验结论 |

## 档案必须包含的成本

课程记录同时给出训练显存和时间、适配器大小、推理显存、TTFT、TPOT 以及合并或加载适配器的方式。质量提高但目标硬件无法部署，不算完成需求。

## 本课验收

1. 为什么检索版本不能与模型训练版本混成一个变量？
2. 哪个里程碑负责证明“确实需要后训练”？
3. 目标任务变好、通用能力下降时怎样决定是否接受？
4. 项目结束时为什么还要保留基座和提示基线？

## 方法边界

课程只展示经过脱敏的预设数据、训练记录和结果，不要求学习者生成私有数据、运行训练或做业务上线操作。真实项目还需许可证、隐私、合规和组织责任审查。
