# 基座审计与任务边界

> **学习导航**：承接 D10-D12；本课在训练前固定基座、任务和回归集；完成后应能证明为什么需要后训练，以及基座原本会什么、不会什么。

## 本课目标

建立一张基座审计表，固定模型版本、tokenizer、chat template、精度、解码参数、任务基线和原能力回归集。

## 为什么要学这一课

如果训练前没有基线，后训练后的变化无法归因；如果不固定模板和 tokenizer，模型行为差异甚至可能与参数更新无关。基座审计还会发现很多问题用提示、检索或普通代码就能解决，根本不需要训练。

## 先写任务边界

以技术支持助手为例，不先写“做 LoRA”，而先写：

- 用户是谁，输入包含哪些信息。
- 输出必须包含哪些字段。
- 哪些问题必须追问或拒答。
- 失败代价是什么。
- 知识来自参数、上下文还是工具。
- 延迟、显存和部署环境有什么上限。

## 固定基座资产

| 项目 | 为什么必须记录 |
|---|---|
| 模型与权重版本 | 同名模型可能有不同检查点 |
| tokenizer 与特殊 token | 会改变编码、模板和输出边界 |
| chat template | 同一权重在不同模板下行为可能明显不同 |
| 精度与量化 | 会影响显存、速度和数值结果 |
| 解码参数与 seed | 会影响生成路径和可重复性 |
| 推理引擎版本 | 用于复现执行与性能差异 |

## 三组训练前评测

1. **目标任务集**：当前最想改善的行为。
2. **通用回归集**：不希望丢失的语言、格式、推理和安全能力。
3. **不可回答集**：信息不足、越权和冲突输入。

后训练后的任何“变好”都必须同时对照这三组，而不是只看训练数据附近的题。

## 预设案例观察

课程提供同一基座在三组评测上的冻结结果、配置和失败样例。根据证据判断目标缺口，再选择一句可反驳假设，例如：“加入 500 条高质量格式示范后，字段合规率提高，同时通用回归下降不超过 2 个百分点。”

## 本课验收

1. 为什么 chat template 变化不能直接算作后训练收益？
2. 目标任务分数提高时，哪组数据负责检查灾难性遗忘？
3. 哪类知识时效问题应优先考虑 RAG，而不是 SFT？
4. 一个无法被评测的“更有帮助”目标还缺什么？

## 方法边界

基座审计不能证明后训练一定有效，它只让后续比较有共同起点。模型许可证、数据权限和目标风险仍需单独检查。
