# GLM：生成式预训练的空白填充

> 学习导航：这篇论文回答“为什么语言模型不必只有下一 token 预测”。先看任务场景和可见信息，再看目标函数；不要把 GLM 的原始目标直接说成所有后续 GLM 都完全照用。

```paper-lesson
glm-foundation
```

## 论文回答什么

2021 年的 GLM 论文面对两个看似冲突的要求：BERT 想让一个位置同时看到左右文脉，GPT 想让模型按顺序生成。初学者常把“能双向理解”和“能自回归生成”当成二选一，论文的贡献是设计一个可切换的空白填充目标，把两者放进同一预训练框架。

## 先建立场景

句子“北京是中国的首都”被挖去“首都”。如果只做下一 token 预测，模型在生成“首都”前只能看到左侧；如果把挖空位置当成需要补全的 span，模型可以读取左右上下文，再按 span 内部的顺序生成。训练目标改变的是可见区域和损失位置，不是凭空增加事实知识。

```mermaid
flowchart LR
  A[原句：北京是中国的首都] --> B[挖空：北京是中国的 MASK]
  B --> C[上下文位置读取左右文脉]
  C --> D[按顺序生成 首 → 都]
  D --> E[只在被挖空 token 上计算损失]
```

## 信息流：同一个序列里的两种角色

论文把输入分成上下文 token 和目标 span。上下文位置可以互相看见，目标 span 内部则保持生成顺序；因此“看到右边”只对上下文编码成立，并不表示模型在生成第二个目标 token 时能偷看它自己的未来答案。用注意力 mask 画出可见边界，比背“GLM 是自回归空白填充”更可靠。

## 训练与推理分开

训练时，模型一次看到带 mask 的完整样本，并对目标 span 的每个位置计算交叉熵。推理时，若做文本续写，仍然可以使用常规自回归解码；若做补全，则先给定上下文和空白，再逐 token 生成 span。训练目标提供能力偏好，但不决定部署时的 temperature、top-p 或工具循环。

## 数字证据账本

| 记录 | 证据层级 | 初学者应问 |
|---|---|---|
| 空白填充目标与二维位置编码 | 一手论文事实 | 哪些位置能互相看见？ |
| 与 BERT、GPT 等基线的下游比较 | 作者实验 | 数据、模型规模和微调是否一致？ |
| “兼得理解与生成” | 作者主张 | 是否有单项消融证明每个组件都必要？ |
| 目标 span 长度和可见区域的关系 | 教学推导 | 这个算式是否只是帮助复核 mask？ |

一个小算例：目标 span 有 3 个 token，训练损失通常是这 3 个位置的平均，而不是把上下文位置也当作要预测的答案。若把上下文 7 个 token 也错误地计入，损失口径就变了，不能直接和论文表格比较。

## 代价与边界

- 复杂的 mask 和位置编码增加实现、缓存和迁移成本，不能只看目标函数的直觉优势。
- 空白填充更擅长“给定上下文补中间”，不等于自动解决长链推理、事实校准或工具调用。
- 论文的下游提升受数据配方、模型规模和微调影响；不能把后续 ChatGLM 的对话能力回溯成 GLM 目标单独带来的结果。

## 本课验收

**L1 · 直接应用**：在“我喜欢吃 [MASK]”中，目标 span 是“苹果”，训练损失应该覆盖哪些 token？

<details><summary>参考答案</summary>

只覆盖目标 span 中的“苹果”（若 tokenizer 切成多个 token，就覆盖这些子 token），上下文“我喜欢吃”用于提供条件，不作为本例答案损失。

</details>

**L2 · 变形迁移**：为什么“上下文能看到右侧”不等于“生成时能看到未来 token”？

<details><summary>参考答案</summary>

上下文位置和目标 span 位置使用不同的可见规则；目标 span 内部仍按顺序生成，未来目标 token 在当前步不可见。

</details>

**L3 · 构造反例**：给出一种情况，GLM 目标表现好但最终回答仍然会幻觉。

<details><summary>参考答案</summary>

训练语料中缺少某个最新事实，或者提示需要外部数据库；模型可以很好地补全语言模式，却没有可验证的事实来源。

</details>

**L4 · 多概念综合**：比较 GLM 目标、SFT 和 RAG 分别改变了哪一层。

<details><summary>参考答案</summary>

GLM 目标改变预训练时的监督位置和可见关系；SFT 改变任务示范后的行为分布；RAG 在推理时把外部证据加入输入。三者不是同一层的替代品。

</details>

## 方法边界

这是原始 GLM 论文的教学复原。后续 GLM-130B、ChatGLM、GLM-4/5 的 tokenizer、训练数据和后训练均有变化；遇到具体版本，必须回到该版本报告确认目标函数和 mask，而不是默认继承本页。
