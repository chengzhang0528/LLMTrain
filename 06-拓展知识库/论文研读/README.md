# 论文研读

论文研读不是记模型名称和缩写，而是训练一种研究能力：从作者想解决的问题出发，复原方法、实验、证据和代价，再判断结论能否迁移到别的模型或场景。

## 为什么放在推荐路线后段

技术报告通常默认读者已经理解注意力、训练目标、后训练、评测和软硬件约束。如果这些基础还没有建立，初学者很容易只记住“新模块更强”“上下文更长”“参数更多”，却无法回答它改了哪一层、比较是否公平、代价是什么。

建议先完成理论基础和至少一条项目路线，再进入论文研读。遇到陌生公式时回到数学急救包；遇到陌生训练或系统机制时回到对应专题，不要求一次读懂全部细节。

## 一篇论文按什么顺序读

| 顺序 | 先回答的问题 | 应留下的证据 |
|---:|---|---|
| 1 | 它要解决什么可观察问题，旧方法为什么不够 | 问题定义、基线与适用场景 |
| 2 | 输入、输出、张量形状和信息流怎样变化 | 一张不省略关键接口的数据流图 |
| 3 | 新方法真正改了架构、数据、目标、训练还是系统 | 方法变化表，而不是缩写列表 |
| 4 | 关键数字能否对账，比较条件是否一致 | 参数量、数据量、算力、上下文和评测条件 |
| 5 | 哪些是实验事实，哪些是作者解释或未来设想 | 事实、主张、推导、未证实项四栏笔记 |
| 6 | 方法换来什么，又牺牲什么 | 质量、速度、显存、训练成本和工程复杂度 |
| 7 | 最小复核或反例怎样设计 | 预生成实验记录、对照表或无法复核的明确原因 |

## 当前案例

### Kimi K3 技术报告

[Kimi K3 技术报告深读](../Kimi-K3深读/)用一份真实的大模型技术报告练习架构分析、数字对账、反例构造与证据审计。它是论文研读案例，不是所有学习者都必须掌握的基础课程，也不代表课程只关注这一种架构。

推荐按路线中的 7 个单元顺序阅读：先学证据分层，再看三维信息流、混合注意力、MoE、预训练与多模态、后训练、基础设施和评测。读完应能说明每项改动解决了什么、证据在哪里、结论不能推广到哪里。

### 在策略蒸馏机制论文

[在策略蒸馏论文深读](../在策略蒸馏深读/)用一篇后训练机制论文练习另一种读法：先从“强教师为什么失败”的反常现象出发，再检查 student-visited states 上的 top-k 重叠、熵差与消融，最后审查冷启动、提示对齐和长轨迹边界。

这条路线强调三种分离：教师分数与可学习性分离、全局奖励信息与局部可优化性分离、作者实验证据与 Agent 场景推广分离。读完应能审查一份教师/学生方案，而不是只复述 OPD 缩写。

## 完成标准

课程为每个论文案例提供问题与基线、方法信息流图、关键数字对账表和实验摘录。完成标准是能从这些材料复核核心实验、提出至少一个反例，并说明适用边界和仍未确认的问题；不要求下载代码或复现实验。
