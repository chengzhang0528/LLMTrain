# DeepSeek LLM：开放基座的训练账本

> 学习导航：这篇报告先建立一个可比较的基座。它回答的不是“哪个模型最好”，而是开放模型怎样记录数据、规模、训练和评测，供后续 MoE、代码和推理分支对照。

## 论文回答什么

一个开放基座要能在不同语言、知识和推理任务上工作，关键不只在 Transformer 结构，还在数据筛选、tokenizer、训练 token、模型尺寸和后训练。DeepSeek LLM 报告的学习价值，是让初学者看到这些变量必须一起写进实验合同。

```mermaid
flowchart LR
  A[网页/书籍/代码语料] --> B[清洗、去重、配比]
  B --> C[tokenizer]
  C --> D[稠密 Transformer 预训练]
  D --> E[基座评测]
  E --> F[SFT/对齐分支]
```

## 核心机制

- **数据配比**决定不同语言、领域和长度的曝光机会。
- **词表**决定同一文本被切成多少 token，影响训练效率和上下文容量。
- **规模与 token 数**共同影响拟合能力，不能只看参数。
- **后训练**把基座的续写分布改成指令、对话或推理行为。

“开放”主要意味着权重/报告/代码等公开程度，不意味着数据许可证、全部清洗规则和每个训练事故都公开。

## 训练与推理分开

预训练更新权重，推理只用固定权重生成 token。解码随机性来自采样规则和随机数，不是 vLLM 重新训练模型；部署引擎主要影响吞吐、缓存、并行和实现精度。若模型答错，先查知识、提示、检索和验证，再查采样。

## 数字证据账本

| 项目 | 初学者要记录 |
|---|---|
| 模型尺寸 | 参数量、层数、宽度、词表 |
| 训练数据 | token 数、语言/领域配比、去重 |
| 基准成绩 | 数据集版本、模板、shot、解码预算 |
| 对齐成绩 | 基座还是 chat 版本，是否有工具 |

教学复核：同一篇中文文本若 tokenizer A 产生 100 token、tokenizer B 产生 80 token，固定上下文窗口下 B 可容纳约 $100/80=1.25$ 倍文本；这只是长度效率，不代表 B 的语义能力自动高 25%。

## 代价与边界

- 数据来源和配比不完整时，不能把 benchmark 改善归因到架构。
- 基座分数不能代替对话、安全、代码或长上下文验收。
- 公开版本会继续更新，数字必须绑定发布日期和模型卡。

## 本课验收

**L1 · 直接应用**：参数量、训练 token 和词表分别影响什么？

<details><summary>参考答案</summary>

参数量影响容量，训练 token 决定看过多少数据，词表影响文本切分和上下文效率；三者不能互相替代。

</details>

**L2 · 变形迁移**：为什么 vLLM 的采样实现不会重新决定模型知识？

<details><summary>参考答案</summary>

知识主要写在固定权重与输入证据中；引擎执行前向、缓存和解码，能改变随机选择与效率，但不在请求时更新权重。

</details>

**L3 · 构造反例**：一个基座中文分数高，为什么客服仍可能答非所问？

<details><summary>参考答案</summary>

它可能没有指令/对话后训练、领域知识或合适模板；语言建模分数不等于遵循业务流程。

</details>

**L4 · 多概念综合**：为比较两个开放基座写出最小实验合同。

<details><summary>参考答案</summary>

固定版本、tokenizer、提示/shot、上下文、解码预算和硬件；同时记录数据、参数、评测脚本与失败样例。

</details>

## 方法边界

本页只使用报告公开的训练与评测框架建立审计方法，不把作者自评等同于独立复现，也不把 DeepSeek LLM 的稠密基座直接当成 V2/V3 的 MoE 结构。
