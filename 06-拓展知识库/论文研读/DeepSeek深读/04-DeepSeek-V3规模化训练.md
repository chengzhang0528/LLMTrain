# DeepSeek-V3：规模化训练系统

> 学习导航：V3 最适合学习“模型能力是架构、数据、精度、并行和训练配方的乘积”，而不是一个新模块的单独功劳。

```paper-lesson
deepseek-v3
```

## 论文回答什么

V3 试图在更大的 MoE 容量和可控训练成本之间取得平衡。报告同时讨论 MLA、细粒度专家、FP8 混合精度、并行系统、数据配方和 Multi-Token Prediction（MTP）。初学者应先把这些改动分栏，再看组合结果。

```mermaid
flowchart LR
  A[数据与 tokenizer] --> B[MoE + MLA 主干]
  B --> C[FP8/混合精度训练]
  C --> D[并行、通信与负载均衡]
  D --> E[MTP/训练稳定性]
  E --> F[检查点与后训练]
  F --> G[分层评测]
```

## 核心机制

- **FP8** 以较低数值精度表示部分计算，减少带宽和显存，但需要缩放、累加和异常值处理。
- **MTP** 在训练中为同一前缀增加多个未来位置的预测目标，也可以在部署时作为候选生成/验证的辅助；它不是把一次生成变成“直接看见答案”。
- **MoE + MLA** 继续分离容量、激活计算和缓存。
- **系统协同** 把算子、并行、通信和故障恢复纳入训练效率，而不是只报理论 FLOPs。

## 训练与推理分开

训练省下的 FLOPs 不一定等于服务低延迟：FP8 kernel、MTP 头和并行拓扑可能只在特定硬件有效。推理时要分别测 prefill、decode、KV Cache、专家通信和批处理。模型权重静态，采样算法只选择当前分布的 token。

## 数字证据账本

| 证据 | 复核问题 |
|---|---|
| 训练计算/时长 | 计入哪些阶段和故障重试？ |
| FP8 结果 | 哪些算子用 FP8，精度损失如何测？ |
| MTP 提升 | 训练目标还是推理加速，基线是否相同？ |
| benchmark | 是否为 base/chat/reasoning，预算是否一致？ |

教学复核：若 MTP 头在训练中为同一前缀提供 2 个额外预测位置，它增加的是监督信号数量，不等于每次推理一定少生成 2 个 token；推理接受率和实现决定真实收益。

## 代价与边界

- 低精度训练可能出现溢出、异常值或特定任务回退，必须看稳定性和质量双指标。
- 组合报告难以证明每个组件的独立贡献；没有消融就只能写“组合结果”。
- 训练系统效率依赖硬件、网络和 kernel，不能迁移成另一平台的保证。

## 本课验收

**L1 · 直接应用**：FP8 解决的是知识问题还是数值/系统问题？

<details><summary>参考答案</summary>

它主要减少计算、带宽和显存成本并带来数值稳定挑战；不会直接补充训练语料中的知识。

</details>

**L2 · 变形迁移**：MTP 多预测位置为什么不等于“模型一次吐出多个正确答案”？

<details><summary>参考答案</summary>

训练中的额外预测提供监督；推理时仍需验证候选 token 是否符合真实自回归分布，接受率和实现才决定是否加速。

</details>

**L3 · 构造反例**：FP8 训练 loss 正常但下游能力下降，如何排查？

<details><summary>参考答案</summary>

检查关键算子精度、缩放/累加、异常值、数据和后训练回归，并与同数据同预算的高精度基线比较。

</details>

**L4 · 多概念综合**：为什么 V3 的“训练效率提升”不能直接换算成线上价格下降？

<details><summary>参考答案</summary>

线上还包括权重、KV Cache、专家通信、调度、网络、并发和质量约束；训练和推理是不同负载。

</details>

## 方法边界

V3 技术报告是组合系统的公开说明；本课用它训练拆账能力，不声称 FP8、MTP 或某种并行单独解释了全部 benchmark 变化。
