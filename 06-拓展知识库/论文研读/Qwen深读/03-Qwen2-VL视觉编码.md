# Qwen2-VL：任意分辨率的视觉输入

> 学习导航：这篇论文把“图片能看懂”拆成分辨率、视觉 token、空间位置、视频时间和语言连接器，帮助初学者理解多模态成本从哪里来。

## 论文回答什么

固定大小的图片缩放会丢小字，固定数量视觉 token 又难覆盖不同尺寸。Qwen2-VL 采用动态分辨率等设计，让输入 token 数随图像内容和尺寸变化，并加入时间/空间信息以处理视频和文档。

```mermaid
flowchart LR
  A[原始图像/视频帧] --> B[动态分辨率与切块]
  B --> C[视觉编码器]
  C --> D[空间/时间位置对齐]
  D --> E[连接器]
  E --> F[语言主干与文本 token 融合]
  F --> G[回答/定位/工具]
```

## 核心机制

视觉 token 不是文本词表里的普通汉字 token。图像切块后形成连续特征，再通过投影/连接器进入语言层；有些模型也会使用离散视觉 token。动态分辨率在小字任务上保留更多细节，但也增加序列长度。视频还要决定采样哪些帧，时间位置错了会把动作顺序读反。

## 训练与推理分开

训练需覆盖图文问答、OCR、定位、视频和多轮交互，并让连接器把视觉特征对齐到语言任务。推理时，图片尺寸、帧数、图像压缩、视觉缓存和上下文预算共同决定成本；同一个 Qwen2-VL 在不同分辨率下不是同一个输入负载。

## 数字证据账本

| 记录 | 不能遗漏 |
|---|---|
| 视觉 token 数 | 图像尺寸、切块/合并规则 |
| OCR/定位分数 | 字体大小、布局、语言和坐标定义 |
| 视频分数 | 帧率、采样帧数、时间跨度 |
| 延迟 | 视觉编码、语言 prefill/decode 分开 |

教学复核：一张图从 16×16 patch 改成更密的 8×8 patch，单边 patch 数翻倍，patch 数约增加 4 倍；实际还会合并/压缩，所以必须查报告中的 token 规则，不能只按像素猜。

## 代价与边界

- 动态分辨率带来可变长度和显存峰值，服务 batching 更复杂。
- OCR 能力受字体、旋转、低清晰度和语言影响，不能用通用 VQA 分数代替。
- 视觉输入可能包含提示注入和隐私，模型回答正确不等于系统安全。

## 本课验收

**L1 · 直接应用**：为什么视觉 token 不应直接称为“图像词表”？

<details><summary>参考答案</summary>

视觉 token/特征的生成方式、粒度和词表可能与文本不同；它们是编码接口，不等于文字 token 的离散字典。

</details>

**L2 · 变形迁移**：增加分辨率会同时改变哪两个量？

<details><summary>参考答案</summary>

保留的空间细节可能增加，视觉 token 数、prefill 计算、显存和延迟也会增加。

</details>

**L3 · 构造反例**：模型图像问答很强但小字 OCR 很差，可能为什么？

<details><summary>参考答案</summary>

输入分辨率或 patch 合并抹掉细节，OCR 数据覆盖不足，或连接器只学到全局语义而没有字符级监督。

</details>

**L4 · 多概念综合**：设计视觉模型的最小分层评测。

<details><summary>参考答案</summary>

分别测全局问答、字符/OCR、空间定位、视频时间关系、工具调用与隐私/提示注入，并记录图像尺寸和帧数。

</details>

## 方法边界

Qwen2-VL 的动态分辨率是该版本的设计，不能推断 Qwen3-VL 或 Omni 使用完全相同的视觉接口。多模态比较必须逐报告画输入信息流。
