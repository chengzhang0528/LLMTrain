# Qwen：多语言通用基座起点

> 学习导航：Qwen 报告是家族主线的起点。本课用它建立“词表、数据、规模、后训练和评测各自负责什么”的基线。

## 论文回答什么

一个通用基座要覆盖多语言、知识问答、代码和数学，先要解决的是数据和表示，而不是先堆一个神秘的 Agent。Qwen 技术报告公开了模型规模、词表、训练语料与评测，让读者能把“多语言能力”拆成可检查的变量。

```mermaid

  A[多语言/代码语料] --> B[清洗与配比]
  B --> C[文本 tokenizer]
  C --> D[因果语言模型]
  D --> E[基座权重]
  E --> F[指令/偏好后训练]
```

## 核心机制

- **文本词表**把字符串切成 token id；它影响长度、稀有词覆盖和嵌入/输出头大小。
- **多语言配比**决定不同语言在训练中的曝光，不能仅凭“支持语言数”判断均衡程度。
- **长上下文与数据质量**共同决定模型能否处理长文档；窗口变长不自动增加证据。
- **后训练**让基座遵循指令、输出结构化答案，但也可能改变开放续写风格。

Qwen 的视觉、音频和图像生成分支不一定复用文本词表；它们先经过各自编码器或离散化，再通过连接器进入主干。

## 训练与推理分开

预训练和后训练更新权重；推理时 tokenizer、提示模板、采样、工具和检索决定本次行为。部署平台可以高效执行，但质量首先受模型、输入证据和评测合同约束。

## 数字证据账本

| 记录 | 正确问题 |
|---|---|
| 词表大小 | 各语言平均 token 长度、特殊 token 是否占用 |
| 数据规模 | token 数、去重、语言/代码配比 |
| 模型尺寸 | 层、宽度、上下文和精度 |
| 评测结果 | 基座/chat、模板、shot 和解码预算 |

教学复核：同一句中文被 tokenizer A 切成 20 token、B 切成 15 token，窗口 3,000 token 下理论可容纳的字数比例约为 $20/15\approx1.33$；这只说明编码效率，不是能力提升比例。

## 代价与边界

- 多语言数据配比可能造成高资源语言与低资源语言的能力差异。
- 词表扩充会增大嵌入/输出参数和训练成本，缩小词数也可能损失细粒度表达。
- 基座报告不是安全、事实性或真实应用的完整验收。

## 本课验收

**L1 · 直接应用**：文本词表首先解决什么？

<details><summary>参考答案</summary>

它把文本切成模型能计算的 token id，并影响序列长度和嵌入/输出头；不直接提供世界知识。

</details>

**L2 · 变形迁移**：为什么“支持 100 种语言”仍需看配比？

<details><summary>参考答案</summary>

支持只说明出现过相关数据，训练量、质量、去重和任务覆盖决定实际能力，语言之间可能严重不均衡。

</details>

**L3 · 构造反例**：词表更大但中文长文处理更慢，为什么？

<details><summary>参考答案</summary>

词表增大嵌入/输出头和 softmax 成本，且中文切分不一定更短；要同时测 token 长度与每 token 计算。

</details>

**L4 · 多概念综合**：画出 Qwen 文本模型与视觉模型接口的差异。

<details><summary>参考答案</summary>

文本直接经 tokenizer 进入语言主干；视觉先经视觉编码器和连接器变成特征/视觉 token，再与文本表示融合，具体词表需查版本报告。

</details>

## 方法边界

Qwen 初代报告是主干起点；后续 Qwen2、2.5、3 改变了数据、规模和后训练。本页的词表与基座框架不能替代具体版本的 tokenizer/model card。
