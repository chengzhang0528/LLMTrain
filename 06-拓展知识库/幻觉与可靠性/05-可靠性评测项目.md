# 可靠性评测案例

> **学习导航**：汇总前四课；本课审阅一个带引用问答项目的预设问题、证据、输出和指标；完成证据是能解释可靠性报告，而不是只看几个成功截图。

## 本课目标

检查问题集、证据集、版本配置、逐题结果、指标汇总、失败分类和上线建议七类材料是否互相一致。

## 为什么要学这一课

可靠性只有放进固定问题、明确证据和版本对照中才可检查。项目能暴露“概念都懂，但不知道怎样冻结测试集、怎样记录失败、怎样决定是否上线”的断层。

## 项目场景

课程已经从公开材料准备 60 道题：30 道明确可回答、10 道多段证据、10 道证据冲突、10 道不可回答，并冻结题目与证据版本。学习者只审查分桶和证据，不访问外部系统。

## 四个版本

1. 基座直接回答。
2. 加入“无证据则拒答”的提示约束。
3. RAG 检索后回答并给引用。
4. RAG 加主张核验、拒答和高风险人工确认。

每个版本固定模型、解码参数和问题顺序。若必须更换模型，单独开一组实验，不能把多个变量混为一个版本。

## 里程碑

| 里程碑 | 完成证据 |
|---|---|
| M1 问题与证据冻结 | 数据说明、可回答性标签、证据版本 |
| M2 基线完成 | 逐题输出、初始失败分类 |
| M3 方法对照 | 四版本配置与统一指标 |
| M4 风险复核 | 高代价错误、权限和注入测试 |
| M5 报告审查 | 结论、适用边界、回滚条件 |

## 报告必须回答

- 主要失败来自检索、证据利用、模型推理还是拒答策略？
- 改进换来了多少延迟、成本或覆盖率损失？
- 哪些问题仍需人工确认或禁止自动回答？
- 下一次模型或知识库升级时，哪些回归集必须保留？

## 本课验收

1. 为什么问题集要在改系统前冻结？
2. 一个版本同时换模型和检索器，会破坏什么结论？
3. 为什么逐题记录比只保存汇总分更重要？
4. 什么条件下项目结论只能写“当前证据不足以上线”？

## 方法边界

这是教学规模的可靠性评测，不替代高风险行业的专业验证、合规审查和持续监控。报告必须限制在选定领域、时间、模型与系统版本内。
