# 幻觉与可靠性

学习导航：承接 D07 的生成过程、D12 的评测和 D13 的应用系统；本路线通过预设问题、证据和输出，把“回答不可靠”拆成可定位、可测量、可缓解的失败类型。

## 先回答本质问题

模型幻觉不是“随机采样导致模型偶尔发疯”，也不是一个能够靠关闭 temperature 永久修好的单点故障。语言模型的基础目标通常是根据上下文预测更可能出现的 token，而不是查询一个始终最新、完整且经过证明的事实数据库。只要训练数据不完备、问题缺少证据、多个说法互相冲突，或者模型学到“像答案的表达”比“承认不知道”更常见，它就可能生成流畅但错误的内容。

在固定模型、固定输入和确定性计算设置下，前向计算会得到一组 logits。解码策略再从这组分数中选择 token：greedy 取最高分，temperature、top-k、top-p 可以引入随机选择。随机性改变“走哪条生成路径”，却不创造模型原本没有的事实核验能力；即使完全确定性的 greedy 解码也会稳定地产生错误答案。

vLLM 等推理引擎负责高效执行模型前向、KV Cache、批处理，以及请求指定的解码策略；引擎提供的是这些算法的实现和调度，不是替模型决定“应该使用哪种策略”。引擎的实现正确性、数值精度和配置会影响输出与性能，但参数中可表达的规律、当前可用信息和回答倾向主要来自模型权重、上下文和后训练。不能把回答质量简单归因于部署平台，也不能忽略引擎配置造成的差异。

## 一组现象，不是一个原因

| 可观察现象 | 可能发生的层 | 先做什么实验 |
|---|---|---|
| 编造不存在的人名、论文或链接 | 参数知识、训练数据、解码 | 要求给出处，再独立核验；比较 greedy 与多次采样 |
| 给了资料仍然答错 | 长上下文利用、检索排序、指令冲突 | 检查证据是否进入上下文，并做逐条引用对齐 |
| 同一问题每次答案不同 | 解码随机性、提示敏感性 | 固定 seed 和解码参数，记录答案分布 |
| 总是很自信，不愿说不知道 | 后训练偏好、校准、产品提示 | 增加不可回答样本，测拒答精确率与覆盖率 |
| 工具结果正确，最终总结却错 | Agent 工作流、结果解析、生成忠实度 | 分开保存工具输出与最终回答，逐步评分 |
| 基准分很高，上线仍失败 | 评测污染、场景漂移、指标代理 | 建独立时间切分和真实失败回归集 |

## 预设案例：带引用的领域问答

课程提供一个资料范围明确的领域、冻结问题集和四个版本的预生成结果：直接回答、提示约束、RAG、RAG 加引用核验与拒答。问题集包含可回答、证据冲突和不可回答三类；每个版本同时给出答案正确率、引用忠实度、拒答精确率、覆盖率、延迟和成本。

学习者要检查问题集、证据集、系统配置、逐题结果、失败分类、风险边界和上线建议能否互相对上。单独展示几个“看起来不错”的回答不算验收。

## 方法边界

- RAG 能提供当前证据，不能保证检索结果正确，也不能保证模型忠实使用证据。
- 校准能改善“置信程度与正确率是否匹配”，不能把未知事实自动变成已知。
- 拒答会减少冒险回答，也可能降低覆盖率；必须按失败代价选择阈值。
- 多次采样、搜索或验证能提高部分任务质量，却增加延迟，并可能让错误获得更多包装。
- 高风险医疗、法律、金融或控制任务不能把“模型自检”当作独立外部验证。
