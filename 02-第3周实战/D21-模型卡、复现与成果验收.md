# D21：审阅模型卡与复现证据

> **学习导航**：承接 D15-D20 的全部预设案例；本课审阅一份预生成模型卡摘要，不要求打包或提交文件；完成后应能发现模型来源、评测、限制和复现证据中的缺口。

## 今日目标

能根据模型卡判断一个教学模型从哪里来、测过什么、不能做什么，以及别人是否有足够信息复查结论。

## 为什么要学这一课

权重文件本身不会说明训练数据、配置、最佳检查点、失败模式和适用边界。模型卡把这些证据放在一起，防止把“能加载”误写成“可使用”，也防止把教学演示误投到真实业务。

## 预设案例：模型卡摘要

| 字段 | 冻结记录 | 审阅意见 |
|---|---|---|
| 模型 | 2 层字符级 Decoder-only Transformer | 结构清楚，但与现代商用 LLM 差距巨大 |
| 数据 | 1331 字符课程原创文本 | 许可清楚，覆盖极窄 |
| tokenizer | 字符级，约 418 个字符 | 适合教学，不代表 BPE/Unigram 方案 |
| 训练 | 固定 seed，800 steps | 需要同时提供最佳验证点而非只给最后一步 |
| 评测 | train/val loss、固定提示样例 | 没有外部领域、事实性或安全评测 |
| 最佳记录 | step 500 的 val loss 最低 | 应说明选择规则在实验前是否固定 |
| 限制 | 可能记忆、重复、输出乱码、不能用于业务 | 边界与证据一致 |
| 不允许用途 | 客服、医疗、法律、内容自动发布 | 教学模型不承担真实决策 |

## 复现证据审查

一份记录至少应能对应到：代码版本、数据版本、配置、tokenizer、随机种子、训练日志、最佳检查点选择规则、评测脚本版本和已知失败。课程只训练你审查这些证据，不要求在空白环境中重新执行流程。

## 最终口试

1. 数据怎样变成错开一位的输入与目标？
2. 因果遮罩保护了什么性质？
3. loss、梯度和参数更新的顺序是什么？
4. train loss 与 val loss 分别能说明什么？
5. prefill、decode 与 KV Cache 在推理时怎样连接？
6. 为什么单 batch 过拟合不能证明泛化？
7. 为什么这个案例不是通用大语言模型？

能不用运行代码而根据预设证据准确回答这些问题，就完成了训练过程案例的学习目标。
