# D15：先看未训练基线

> **学习导航**：承接 D14 完成的生命周期闭环；本课从一份预生成环境快照和未训练输出开始，不要求安装或运行；完成后应能解释为什么“坏输出”是必要对照，以及哪些信息决定结果能否被复查。

## 今日目标

能从预设案例中找出环境、配置、随机种子、参数量、测试状态和未训练输出，并说明它们各自控制什么不确定性。

## 为什么要学这一课

如果只看训练后的漂亮样例，就无法判断改善来自训练、初始化、提示词还是人工挑选。未训练基线把“参数还没有从数据中学到模式”固定下来，后面的变化才有参照物。

## 预设案例：运行前快照

下面是课程冻结的教学快照，不是要求学习者复现的环境：

| 项目 | 记录值 | 观察重点 |
|---|---|---|
| Python | 3.12 | 软件版本会影响可复现性 |
| PyTorch | 2.x，CPU | 硬件与数值实现必须写清 |
| 配置 | `smoke.yaml` | `seed=42`、1 层、2 头、隐藏宽度 32 |
| 数据 | 1331 个字符 | 只能验证管线和局部记忆 |
| 单元测试 | 全部通过 | 说明已检查形状、遮罩和基础接口，不说明模型质量好 |
| 权重状态 | 随机初始化 | 还没有通过训练数据形成稳定语言模式 |

冻结的未训练输出示意：

> 小束页岸疑巡，空既灯的石……

这段文字看似偶尔出现中文字符，但没有稳定语义。字符来自词表，顺序主要由随机权重和解码过程决定；不能因为出现了“灯”或“石”就说模型理解了物体。

## 怎样读这个基线

- 测试通过：代码满足被测试的局部性质。
- 输出很差：符合未训练模型的预期。
- 固定 seed：减少一次比较中的随机变化，不代表所有硬件都逐位一致。
- 小配置：让案例容易观察，不代表真实模型的规模和能力。

## 今日验收

1. 为什么未训练输出不是“失败”，而是后续比较的对照？
2. 单元测试全部通过，为什么仍不能说明生成质量好？
3. 若训练后输出改变，但配置和提示也一起改变，为什么无法归因？
4. 这份快照缺少哪些信息时，别人无法判断它是否可复查？
