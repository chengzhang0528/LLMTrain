# D19：读懂一次完整训练记录

> **学习导航**：承接 D18 的最小管线检查；本课审阅一份预生成完整训练记录和检查点清单，不要求等待计算；完成后应能从整段 train/val loss、配置与恢复信息判断实验发生了什么。

## 今日目标

能找出最佳验证点、过拟合起点和检查点恢复所需信息，不再用终端最后一行代表整次训练。

## 为什么要学这一课

训练不是“等一个低 loss”。一份可信记录必须同时回答配置是什么、数据怎样切、指标怎样变化、最佳点在哪里、失败后能否恢复。否则即使留下一个权重文件，也不知道它来自哪次实验。

## 预设案例：800 step 教学记录

| step | train loss | val loss | 教学解读 |
|---:|---:|---:|---|
| 0 | 6.08 | 6.04 | 随机初始化 |
| 100 | 4.21 | 4.36 | 训练与验证都改善 |
| 300 | 3.02 | 3.41 | 仍有泛化改善 |
| 500 | 2.31 | 3.18 | 当前最佳验证点 |
| 700 | 1.82 | 3.27 | train 继续降，val 开始回升 |
| 800 | 1.63 | 3.39 | 过拟合迹象更明显 |

这组数值是冻结的判读材料，不是对某块 CPU 或 GPU 的性能声明。若要选用于验证集的检查点，应优先考虑 step 500，而不是因为 step 800 的 train loss 最低就自动选最后一步。

## 检查点至少要能回答什么

| 信息 | 缺失后的问题 |
|---|---|
| 模型权重与架构配置 | 无法正确加载张量 |
| tokenizer 与词表 | ID 无法还原为同一套符号 |
| optimizer 与当前 step | 无法从同一优化状态继续训练 |
| 随机种子与数据版本 | 难以解释重跑差异 |
| 当前和最佳指标 | 不知道保存点为什么被选中 |
| 软件与硬件记录 | 无法判断数值或性能差异来源 |

## 今日验收

1. 哪一步的验证表现最好？
2. 为什么最后一步不是自动最优？
3. 只有 `checkpoint.pt`，没有 tokenizer，会发生什么？
4. train loss 下降而 val loss 回升，最直接说明什么？
5. “可恢复”与“可复现”为什么不是同一个要求？
