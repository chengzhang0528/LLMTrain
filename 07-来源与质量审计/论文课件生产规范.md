# 论文课件生产规范

本文件只供课程维护者使用。它规定如何把论文、技术报告、模型卡和官方代码转译成初学者课件；不得登记为学习单元，也不得出现在用户侧栏或课程推荐路线中。

## 一、先决定是否制作课件

候选材料先分为三类：

1. **完整课件**：改变了重要研究问题，证据足够，能够构造具体例子、信息流和失败边界。
2. **系列伴读**：帮助解释主论文中的某个机制，但不足以单独承担完整课程。
3. **目录记录**：模型卡、博客或发布说明，只用于记录版本和官方主张。

GitHub Star、社交媒体热度和产品发布时间不能决定课程优先级。已经弃用、长期停更、许可证不清或依赖下线服务的项目只作历史证据。

## 二、三层论文研究

### 快速筛选

核对问题、基线、主要图表、结论和来源类型，决定停止、排队或深入。摘要只能提供候选主张，不能作为最终证据。

### 证据扫描

沿“输入与数据 → 架构或训练改动 → 输出与指标 → 代价和失败”建立信息流。至少记录一个可复算数字、一个适用条件和一个反例。

### 深入复核

对进入主线的论文继续核对版本、官方实现、配置、测试和冲突材料。多个改动一起发生时，只能表述组合结果，不能把全部收益归因给单一模块。

AI 工具只能用于发现、定位、切分和组织候选证据。所有关键结论必须通过出处、支持、冲突和隐私四个闸门。

## 三、课件输出契约

一篇用户可见的论文课件必须完成以下教学转译：

1. 用真实失败现象说明为什么需要这篇论文。
2. 标出论文在模型生命周期和系统中的位置。
3. 用同一个具体输入贯穿旧方法、新方法和输出差异。
4. 把机制画成信息流，说明训练参数与推理状态。
5. 复杂公式先拆成具体数字，再回到通用符号。
6. 选择一张关键图表，说明比较对象、条件、数字和不能推出的结论。
7. 给出成本、失败案例和不可外推范围。
8. 连接前置论文、后续工作和同类替代方案。
9. 使用预测、解释、反例和综合判断检验学习结果。
10. 在正文前建立“问题 → 关键改动 → 训练/运行 → 证据 → 边界”五节点认知骨架，并让学习者能够隐藏解释后主动回放。
11. 在系列路线和单篇页首同时提供站内深读、论文原文、上一篇与下一篇，链接名称必须明确区分课程与一手材料。

课程正文不展示“证据四元组”“速研工作台”“许可证检查”等作者流程。内部核查的结果应转化为清楚的来源说明、条件限定和具体反例。

## 四、公式与实现映射

存在官方代码时，内部记录必须包含：论文版本、仓库版本、公式或伪代码对应模块、关键配置与形状、测试或预生成结果。参考实现、教学实现和性能实现分别标记。

没有公开实现时明确记录缺口。不能因为仓库存在就称为复现，也不能用第三方实现代替作者实现后省略说明。

## 五、模型系列与研究问题双索引

- 按研究问题连接预训练、容量效率、长上下文、推理后训练、多模态和 Agent/系统可靠性。
- 按模型系列记录 GLM、Kimi、DeepSeek、Qwen 的历史演进。
- 每篇完整课件同时属于一个主要研究问题和一个模型系列。
- 发布说明保留在论文库，但不伪装成完整论文课件。

## 六、提交前验收

- 用户侧栏、学习进度和搜索中没有内部审计页面。
- 课程开头是问题或现象，不是编辑方法说明。
- 关键数字注明版本、条件和来源。
- 动效承担真实的信息变化，并在移动端可读。
- 主线课件的 `paper-lesson` ID 与论文库唯一对应；系列路线中的站内链接、原文链接和前后顺序均可到达。
- 学习者无需安装、编程、训练、上传论文或调用外部 API。
- 运行 `pnpm docs:check` 与 `pnpm docs:build`，再用真实浏览器检查桌面与移动端。
