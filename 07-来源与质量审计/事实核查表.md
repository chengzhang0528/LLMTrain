# 事实核查表

| 主题 | 容易写错的说法 | 本课程口径 | 状态 |
|---|---|---|---|
| Transformer | “彻底取代 RNN” | Transformer 是当前 LLM 主流；RNN 仍存在于其他模型和场景 | 已修订 |
| 因果注意力 | “每个位置看到所有位置” | 训练 Decoder LM 时因果遮罩禁止看到未来 token | 已修订 |
| 注意力权重 | “就是词的重要程度” | 是特定层、头和输入下的计算权重，不能自动当作完整解释 | 已修订 |
| QLoRA | “4-bit 所以总显存减少 75%，而且所有乘法都直接用 4-bit” | 4-bit 主要描述冻结基础权重的量化存储；矩阵运算通常按块反量化到计算精度，总显存还含激活、梯度和优化器状态 | 已修订 |
| loss | “越低模型越好” | 仅在相同数据、tokenization 和计算方式下比较；还需验证集和任务指标 | 已修订 |
| 参数量 | “越大一定越好” | 能力取决于数据、训练计算、架构、后训练和评测条件 | 已修订 |
| RAG/微调 | “加入新知识就微调” | 频繁变化或需引用的知识通常先考虑检索；微调更适合行为和格式 | 已修订 |
| 训练/推理 | “生成时还在学习” | 常规推理不会更新参数；上下文变化不等于权重学习 | 已修订 |
| 蒸馏教师 | “教师越大、分数越高，学生一定学得越好” | 还要检查教师新增能力、学生可达状态、分布兼容、词表与训练目标 | 已修订 |
| 在策略蒸馏 | “逐 token 奖励更密，所以长轨迹一定更可靠” | 学生前缀偏离后，教师信号可能随深度退化；长度必须分桶验证 | 已修订 |
| Prefill/Decode | “prefill 永远计算受限，decode 永远带宽受限” | 这是常见倾向；batch、形状、模型、kernel 和硬件会移动瓶颈 | 已修订 |
| 推理吞吐 | “tokens/s 越高，在线服务一定越好” | 还要检查 TTFT、TPOT、P95/P99、错误率、质量与满足 SLO 的有效吞吐 | 已修订 |
