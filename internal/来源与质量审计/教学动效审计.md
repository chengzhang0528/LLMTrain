# 教学动效审计

动效只有在“状态变化本身就是知识”时才成立。审计顺序固定为：先写学习者看完应能回答什么，再写眼睛应该盯住什么，最后才决定是否播放、用二维还是三维。

## 当前逐项结论

| 位置 | 希望用户吸收什么 | 必须看什么 | 形式判断 | 改造结论 |
|---|---|---|---|---|
| D01 大模型 | 推理读取固定参数，每轮从上下文得到一个新 token | 文本、ID、候选概率与新 token 的形态变化；参数没有被更新 | 因果顺序重要，空间关系不重要 | 保留二维；把“固定参数”写进节点与反思问题 |
| D02 分词与 Embedding | token、ID、向量是三种不同表示，ID 只用于查表 | 同一内容如何被切块、编号、定位并读成浮点向量 | 表示转换顺序重要 | 保留二维；每步明确观察对象与常见误解 |
| D04 参数更新循环 | backward 产生梯度，optimizer.step 才改变参数 | 同一组输入怎样经过预测、loss、梯度和参数回写再进入下一 step | 参数状态按因果顺序变化 | 新增二维程序动效；逐步暂停后回到训练伪代码，不跳转外部 Playground |
| D05 注意力汇总 | Q/K/V、遮罩、softmax 与 Value 的职责边界 | 分数如何被遮罩、归一化，再按权重搬运 Value | 分数到上下文的顺序本身就是知识 | 新增二维程序动效；用同一组 `[4,2,0]` 数字连接正式公式 |
| D03 点积 | 对应维相乘后求和，两个向量压成一个标量 | 数字如何配对，结果如何从两项缩成一个数 | 原数据只有二维且教学目标是算术；旋转不提供信息 | 删除伪三维，改为二维计算链 |
| D03 向量下标与范数 | 区分维数、数学下标、Python 索引和向量长度 | 同一个坐标的两套编号；各坐标如何平方、汇总并开方 | 位置映射与逐步汇聚本身就是知识 | 新增 `pencil-vector`；使用 10 维具体向量，最后停在维数 10、范数 13 的对比 |
| 数学急救包 02 矩阵映射 | 区分输入空间、具体输入向量、矩阵规则、输出向量和输出空间 | W 位于两个空间之间，不是任何一个空间本身 | 关系是固定结构，不依赖时间播放 | 使用静态 `pencil-flow`，配合对象类型与形状表，不增加播放 |
| D07 一次模型运行 | 区分应用层、模型、推理引擎与硬件责任，并把一次 token 选择串成完整链 | 消息模板怎样变成 ID、隐藏表示、logits 和输出 token；权重在推理中保持静态 | 数据形态与责任边界按顺序变化 | 保留第一组二维分步流；总览用于串联 tokenizer、Transformer、采样和回到文本 |
| D07 单 token 算法显微镜与计算高楼 | 一个输出 token 仍会触发全部层的主要计算；历史缓存、当前位置状态、固定权重、Attention、MLP、残差、LM Head 与解码选择有可追踪的因果顺序；层内大量乘加并行，层间依赖仍逐层推进 | 先在同一 Block 内分开历史 K/V 与当前位置 x，再沿带动作文字的箭头追踪 Q/K/V 投影、QK 打分、softmax、加权汇总 V、两次残差和 LM Head；每一步同时显示通俗动作与正式方法名，舞台内只保留一个当前旁白，固定 8 步路径保持视线锚点；最后看到 8 个具体 logits 都参与比较、greedy 只接受最大项。随后缩远观察同类计算怎样重复 32/80 层 | 单看高楼只能表达规模，不能解释算法；顶部指南、中央画面和底部解释若同时变化会迫使视线来回跳，因此必须使用单焦点镜头与稳定路径 | 复用课程 L0 的 `D=4、M=8、T=4、V=8`，默认自动播放八步“算法显微镜”；顶部只保留播放、暂停、步号和进度，当前步骤的观察、作用、关键理解与反思贴在舞台下缘；每条关键箭头由 Markdown 提供动作文字。结束后自动进入原生 Three.js 高楼并完成四步规模观察，全程不循环。高楼继续用整面波前表达层内批量并行、逐层上移表达 Block 依赖，未选 logits 退暗后只留下一个 token；右侧反馈/支持入口不得遮挡候选分数。全屏时规模视图说明固定在视口底部并可滚动阅读，退出按钮保持高对比度固定显示；普通显微镜说明嵌入舞台，移动端动作箭头改为纵向并保留页面滚动 |
| D07 prefill 与 decode | 首次处理整段输入和后续逐 token 循环不是同一阶段，KV Cache 保存的是中间状态；`decode 前向` 不等于 logits 采样 | prefill 一次读取输入并产生首轮 logits、写入提示 K/V；解码策略接受 ID 后，decode 前向每轮读取历史 K/V、写入新 K/V 并产生下一轮 logits，流式输出与下一轮输入是已接受 ID 的两条用途 | 缓存与序列状态随轮次变化 | 保留第二组二维分步流；用分叉箭头显式区分“显示”和“下一轮前向”，禁止画成 KV Cache 直接产生 logits；移动端优先显示当前步骤，静态总览保持完整链路 |
| 软硬件瓶颈 Token 生成速度与并行解码 | 区分“计算并行”和“结果按因果接受”，并定位一个输出 token 的时间去向 | 上方普通路径一次接受一个 token，下方候选路径先提出、再由目标模型批量验证；方框只标执行阶段，线只表示依赖或候选交接 | 并行边界和接受顺序本身就是问题核心，二维对照足够表达，不需要伪造参数点阵或三维空间 | 保留一张双泳道 `pencil-flow`；按普通因果、层内并行、接受一项、候选提议和批量验证依次推进，自动播放到末步停止；正文用 30 ms 教学数据解释 TPOT，明确不是 Benchmark；移动端让当前步骤节点回到文档流，静态模式保留两条完整路径 |
| D06 完整 Transformer | Embedding、Attention、MLP、残差和 LM Head 在同一条数据流中的分工 | `(B,T,D)` 如何在子层间保持兼容，最后变成 `(B,T,V)` | 结构与形状需要同步定位 | 运行地图直接嵌入正文；提示学习者在图与形状表之间往返核对；窄屏保留纵向页面滚动，不启用滚轮缩放 |
| K3 三维信息流 | 序列、深度、宽度是并列架构轴，不是串行流水线 | 三条箭头从同一原点向独立方向展开 | 三个独立方向本身就是知识 | 用三维替换误导性的线性 Mermaid；逐轴说明收益与新代价；移动端允许从画布内部继续纵向翻页 |
| Wiki 核心术语预览 | 首次遇到术语时，把定义绑定到一个可见结构或变化 | 向量格子、表示转换、概率柱或三步计算链 | 只使用 1 到 3 秒的微视觉，不承担完整教学 | 向量、Embedding、张量形状、范数、投影、softmax、梯度和注意力增加视觉预览；减少动态效果时保持最终静态状态 |

## 符号与标题闭环审计

| 位置 | 原共性风险 | 统一处理 |
|---|---|---|
| D03 与数学急救包 02 | 把矩阵、空间和具体向量放在同一句里，容易误读为 W 就是空间 | 明确 `R^D -> W -> R^D_out`，并分别定义 x、X、W、y |
| D05 注意力 | Q/K/V 有时被称作向量，有时用于矩阵公式 | 区分单位置小写 q/k/v 与堆叠后的大写 Q/K/V，并以形状为最终依据 |
| D10 训练规模 | D 容易被沿用为隐藏维度 | 明确本页 D 是 data token 数量标量 |
| D11 LoRA | W/A/B/α 看似需要死记，且不同资料可能交换 A、B | 就地标注矩阵与标量类型，强调名字可换、形状关系不可换 |
| 数学急救包 04 | 大写 L 容易被误判为矩阵 | 明确 L 是标量 loss，梯度形状与参数兼容 |
| 数学急救包 06 | 右上角 T 容易被当成新变量 | 明确 T 是转置操作，k/v/q 是向量，S 是状态矩阵 |
| 数学急救包 07 | q 与注意力 Query 重名 | 明确本页 q 是平均负载标量，局部定义优先 |
| 数学急救包 08 | y=xW+b 没有直接回应“空间投影” | 分开定义 x、W、b、y，并用输出坐标来自 W 各列回扣标题 |
| K3 报告与 KDA | B、I、S、α、β 的大小写和字母来源容易被误当成类型规则 | 增加局部符号身份表，明确论文命名只提供提示 |

## 静态图边界

其余 Mermaid 图用于展示固定结构、阶段清单或分支关系，没有时间状态，也没有播放控件。静态图不因“看起来不够生动”自动升级为动效；只有当学习目标依赖状态变化时，才进入上表并改用铅笔视图。

## 顺序连线规范

流程动效统一使用“节点出现、连线到达、下游节点确认”的因果顺序。当前步骤若包含多条边，必须按数据实际经过的先后逐段描线，箭头只能在线身到达终点后出现；已经走过的路径继续保留，当前路径最清晰，尚未发生的路径弱化。这样学习者看到的是计算依赖如何建立，而不是一组元素依次淡入。

- 自动播放只负责推进讲解步骤，到末步停止，不循环；手动前进或后退时重播当前步骤的新连线。
- 移动端继续只放大当前步骤，避免为了保留全图而产生横向溢出；同一步中的已画路径仍然保留。
- `prefers-reduced-motion` 下直接展示完整静态关系，不执行描线、节点到达或自动播放。
- 外部 GIF 只用于提炼教学方法。站点使用原生 SVG 或 Three.js 表达课程自己的节点、数据与因果关系，不引入第三方视频画面。

## 算法因果分镜模板

后续算法动效统一按下面顺序设计，先完成内容合同，再编写绘图组件：

0. **先定一张画板**：所有分区共享一个舞台背景；区域标题、方法条和旁白透明嵌入，数据节点只用低透明度填充加边界区分。若必须使用实色底，必须说明它隔离的是哪一种对象，不能让每个步骤都变成一张互不相连的卡片。
1. **锁定作用域**：写清正在观察哪一层、哪一轮、哪个位置；跨层、跨时间的对象不能放在同一组而不标边界。
2. **盘点对象身份**：至少区分输入、固定规则或参数、本轮临时状态、跨轮缓存和输出。节点先写日常语言身份，再补局部符号与形状。
3. **拆成原子动作**：每个分镜只回答“谁对谁做了什么，产生了什么”。一个步骤可包含同一动作内部的批量并行，但不能把有依赖的多个算子说成同时完成。
   每个步骤必须再压成一条 `focus` 关系句，例如“一份 x → 8 个并行 logits”。学习者扫完这一句就应知道眼睛盯哪里；若一句中出现两个无依赖的观察目标，继续拆步。
4. **给箭头写动作**：箭头标签使用“固定权重做矩阵乘法”“按权重逐格相加”等可复述短句；禁止只写“处理”“下一步”或画一条无来源、无终点的运动线。
5. **当前场景优先**：逐步模式只展示本步输入、动作和结果；已完成状态只在理解本步确有必要时保留，未来状态隐藏。静态总览另行承担全链回忆。
6. **数值只服务验证**：每组数字出现前先回答它用来比较、相加、汇总还是筛选什么；具体数值必须能核对当前动作，例如 softmax、残差或最大值选择。向量默认使用紧凑序列，只有坐标运算本身是观察目标时才拆成独立格。无法从玩具数据推导的内部矩阵只标出动作与边界，不伪造精确过程。
7. **分开批量计算与最终选择**：先让学习者看见全部参与计算的对象，再单独播放筛选、路由或接受动作，避免把“只留下一个”误读成“只算了一个”。
8. **再缩放到真实规模**：局部显微镜解释因果，规模视图解释层数、并行度与资源量级；两级视图必须复用对象名称、颜色和形状。

`PencilActionArrow.vue` 只负责可复用的横向或纵向描线、箭头与减少动态效果；箭头文字、对象名称、数值、步骤说明和简化边界仍全部来自 Markdown JSON。新增算法优先复用这一因果箭头和现有 `PencilFlow` 节点状态，不在课程组件里硬编码另一套讲解文案。

## 页面密度验收

空间预算也是动效正确性的一部分，按下面顺序验收，不把“看起来有呼吸感”当成固定留白的理由：

1. **先测当前内容**：逐步模式分别记录舞台、当前场景和旁白的实际高度；短步骤不使用统一最低高度，容器明显高于内容时优先删除占位。
2. **浮层只做局部避让**：桌面浮动指南可以覆盖舞台的一个角落，但只能让受影响的路径或标签局部让出空间，不能推动整张画板下移。
3. **窄屏回到文档流**：当浮层宽度接近画板宽度时，把它排在画板内容之前，再纵向排列路径、场景和旁白；不要用 `padding-top` 猜一个“刚好够用”的空白。
4. **全屏仍可退出**：全屏说明可以固定在底部，但舞台本身仍按内容增长；退出按钮固定在视口右上角，不能因密度优化而消失。
5. **宽屏收住镜头**：全屏背景可以铺满视口，单步输入、动作和结果仍要共享一个居中的最大阅读宽度。测量同一动作两端的距离；若需要明显转头或扫视，先缩短关系链的横向跨度，再考虑增加画布。
6. **记录密度合同**：使用 `token-compute-tower` 时，Markdown 的 `animationContract` 必须声明 `density: "content-driven"` 与 `guideReservation: "local-only"`，让内容检查在新增动效时提醒维护者复用这套预算。

控件密度也按同一原则验收：一个动作只能有一个操作入口。顶部工具栏承担播放、暂停、前后步与视图切换；可移动指南只显示当前状态、步号和进度，不复制控制按钮。发现两个入口会改变同一播放状态时，必须删除其中一个，而不是通过颜色区分主次。

## 成熟交互项目的转译规则

Transformer Explainer、CNN Explainer、GAN Lab、TensorFlow Playground、LLM Visualization、Embedding Projector 与 BertViz 提供的是设计证据，不是可直接拼进课程的素材包。课程页内嵌动效是学习入口，本站统一按以下顺序转译：

1. 先写学习者要回答的问题，再选择外部项目中与该问题对应的观察机制。
2. 让站内全局图和局部放大共用同一个输入、对象名称、颜色与形状；不能在不同视图中悄悄更换样例。
3. 控件一次只改变一个可解释变量，并同时显示当前参数、受影响的中间状态和最终结果。
4. 二维图负责因果顺序与精确标签；三维图只补充轴、层级、参数点阵或遮挡关系，并提供静态退化视图。
5. 玩具模型必须写清任务、规模与简化条件；观察到的现象不能自动外推到所有现代模型。
6. 外站只作可选观察材料。站内不嵌 iframe，不复制图片、GIF、SVG、文案、题目、内置数据或交互实现。

具体项目、论文、许可证与采用结论见[交互可视化素材审计](交互可视化素材审计.md)。

## 拒绝条件

- 说不出看完后学习者应能回答的问题。
- 只做淡入、描边、轮播或逐个高亮，却没有新的状态含义。
- 三维旋转后没有出现二维图无法表达的关系。
- 自动播放快于说明文字的正常阅读时间，或到末步后无限循环。
- 颜色是唯一状态线索，或者手机端流程图回边、标签、浮动入口遮住正文。
