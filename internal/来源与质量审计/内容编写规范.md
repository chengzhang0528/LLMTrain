# 内容编写规范

这套课程按 Wiki 方式维护。课程正文负责循序讲解，术语目录负责跨文章连接，二者不能各写一套互相漂移的定义。

## 用户课程与内部资料分层

- `course/` 是唯一的用户课程源目录，只放学习者实际阅读、观察和作答的内容。
- `internal/来源与质量审计` 存放生产规范、来源审计、版本记录、验收报告和维护命令；它不属于课程源目录，因此不会进入网站构建、侧栏、学习进度或站内搜索。
- 内部检查清单不能伪装成正式课程。课程正文直接呈现已经核查后的场景、机制、数字、边界和练习，不要求学习者代替作者完成内容审计。
- 学习者需要掌握的批判性判断必须通过具体论文案例教学，不能把许可证核查、版本登记、证据卡模板或编辑流程当作前置课。
- 用户页面可以链接原始论文、官方文档和模型卡，不直接链接内部审计文件。

## 导航与目录分工

- 顶部导航只负责跨区域移动，保留“开始、基础课程、专题课程、论文研读、查阅工具”等稳定入口，不平铺所有文章。
- 左侧目录在所有课程页面使用同一棵全站课程树，必须始终保留“从这里开始、基础课程、专题课程、论文研读、查阅工具、支持课程”六个一级入口，不能再按当前 URL 替换成互不相见的局部侧栏。
- 全站课程树按一级区域、二级课程或主线、具体页面逐层缩进。一级区域始终可见，当前页面所在分支自动展开，其他分支允许折叠；站内跳转时保留用户已经展开的分支。分组使用传统树形标题和缩进，不使用矩形卡片切割目录。
- 入口页先给零基础学习者一个默认学习动作，再为已有明确问题的学习者提供查找表。查文章时不应要求用户先理解仓库的文件编号和维护分类。
- 零基础入口必须先给出唯一默认动作并直达 D01；学科地图和知识图谱只在已有明确问题时使用，不能共同成为开始学习的前置步骤。全站侧栏的“从这里开始”只保留统一开始页、问题地图、关系图谱和学习记录，不为自测、安排说明、能力清单或硬件说明各建一页。
- 已经填充完整内容并发布的审查卡、案例摘要或辅助页必须有明确站内入口；与某一课直接配套时，作为普通条目紧邻对应课程，不为少量辅助页另建矩形分组，也不能继续沿用“空模板”规则把它排除在目录之外。
- 入口页的阅读顺序、正文手工“下一课”链接和侧栏/pager 必须表达同一条相邻路径；插入配套审查卡或辅助页时三处同步更新，不能让正文跳过侧栏中的下一项。
- 学习顺序、知识领域、案例类型和论文索引不能混在同一层级。全站侧栏负责稳定呈现课程层级与当前位置，跨区域知识关系仍交给学科地图和知识图谱。
- 页面只有在拥有独立问题与决策、独立交互或本地状态、高频查阅职责、动态数据，或必须稳定标识的来源对象时，才拥有独立导航入口。仅重复子页目录、把结论与证据拆开、解释站点维护历史或套用统一模板的页面必须合并或删除。
- 重组目录时，若用户或产品没有明确要求旧地址兼容，直接删除旧页面、别名、迁移逻辑和对应检查；同时更新站内链接、侧栏、分页、学习记录清单与构建验证。不得为了“可能有人收藏”永久保留低密度入口。
- 只有明确要求兼容时才提供兼容页；兼容页必须直接进入当前可执行学习入口，不向学习者解释“旧版、迁移、已合并”等维护历史。

## 术语链接规则

1. 核心术语统一登记在 `.vitepress/wiki-terms.mjs`。
2. 每个术语必须同时在 [术语速查](../../course/05-速查表/术语速查.md) 中拥有稳定的 `term-*` 锚点。
3. 构建时会自动链接正文里的登记词和别名，并提供“定义 + 沟通使用示例 + 常见误解”的悬停预览。
4. 标题、行内代码、代码块和已有链接不会被自动改写。
5. 不在正文中粘贴 `localhost` 等环境相关的绝对地址；手工链接使用相对路径。
6. 复合术语必须按完整词组登记，自动链接按“最长别名优先”匹配；例如 `Agent Swarm` 不能退化成只链接 `Agent`。首次用加粗英文词组引入术语时，内容检查会验证完整词组已登记。

新增术语时，必须在同一次修改中完成以下事项：

- 写清标准名称、必要别名、一句话解释、沟通使用示例和常见误解。
- 给出稳定目标锚点，不能链接到笼统的目录首页。
- 英文术语必须在注册表中给出美式音标、可供语音合成读出的文本和对应离线音频；缩写要明确按字母读还是按单词读。
- 检查别名不会误伤普通词或更长的专有名词。
- 在桌面端验证鼠标悬停和朗读按钮，在键盘模式验证 Tab 聚焦，在手机端验证预览、音标和按钮不造成横向溢出。

普通动词、过于宽泛的词和只出现一次的临时缩写不应登记为术语。自动链接的目标是降低查找成本，不是让整页文字都变成链接。

每个术语必须提供一句可以直接出现在实验讨论、方案评审或排错记录中的“沟通时这样说”。例句应包含具体对象、动作和必要口径，帮助学习者像造句一样掌握术语；不能只重复定义，不能写成“X 很重要”“需要了解 X”，也不能把教学数字伪装成推荐参数、质量阈值或跨系统结论。注册表是例句的唯一来源，正文悬停和术语速查必须从该字段呈现，不在组件中复制例句正文。

课程不能只登记某个上位概念下面的算法名。正文频繁使用“监督、微调、推理、部署、评测、多模态”等基础概念前，必须先用桥接段落说明它是什么、参与者是谁、输入和输出是什么、与相邻概念有什么区别；随后再进入 SFT、LoRA、RLHF、RAG 等具体方法。桥接解释、Wiki 注册项和术语速查词条必须在同一次修改中补齐。

判断是否需要桥接解释时，以初学者能否回答三个问题为准：这个词指对象、过程还是目标；它在完整模型生命周期的哪一段；后文提到的具体方法与它是什么关系。仅靠悬停词条不能代替正文中的首次系统讲解。

自动链接别名只登记不改变含义的精确名称、缩写和常用译名。不要为了提高链接覆盖率登记“训练、模型、服务、数据”等普通词，也不要把上下位概念互设为别名。

容易混淆为函数、单次数值、向量、张量形状、整数计数或时间指标的术语，定义必须先说清对象类型，再在句末给一个带单位或形状的具体示例。例如，`loss` 要区分“损失函数”与“一批数据上算出的标量”，再给出 `loss = 2.31`；学习率、batch size、step、TTFT 等也要分别写出合法示例。示例用于展示形式，不得伪装成推荐配置、质量阈值或跨模型统一标准。

术语定义必须先说明适用口径：`batch` 同时存在于训练和推理，`inference` 的模型执行不等于 reasoning 能力，验证集不等于冻结测试集，总参数量不等于可训练或激活参数量，PagedAttention 也不等于分页 KV Cache 的通用名称。相关但不等价的概念必须拆成独立词条，不能靠别名合并。

“验收集”若未说明用于开发选择还是最终测试，属于角色不清。开发评测集用于比较配置、Prompt、RAG、微调、阈值和检查点；冻结测试集只能在方案与选择规则冻结后用于最终估计，查看结果后继续改方案会使它变成开发证据。

MTP 必须先定义为多未来 token 监督的通用类别，再说明并行预测头、串联预测模块等论文特定实现。不能把某一种结构写成所有 MTP 的定义，也不能把训练监督直接等同于推理时接受多个 token。

## 讲解规则

- 课程是持续维护的开放知识系统，不以固定天数或“全部看完”作为结课标准。D01-D21 是基础闭环的稳定模块编号，不得在新页面中写成学习者必须按自然日完成的承诺。
- 课程不按日历推进时使用“本课验收”，不用“今日目标”“今日验收”等暗示当天必须完成的标题。页首目标、承接与完成证据统一压进一行“学习导航”，不再另设重复的“主线位置”和“本课目标”。
- 课程按四层组织：理论基础解释稳定机制，案例闭环展示项目证据，专题课程整理跨章节共性，研究前沿记录仍在变化的瓶颈。新增内容必须先判断属于哪一层，不能把论文名、产品名和基础概念平铺在同一级目录。
- 理论基础按六段主线组织：模型原理、模型架构与运行、数据准备与模型训练、模型评估与优化、推理部署与应用、监控反馈与持续迭代。多模态与软硬件系统属于横跨生命周期的专题，不得伪装成主线最后一步。
- D01-D14 必须在页首“学习导航”中链接所属总纲并标明当前位置。D09 只表示一次训练任务内部动作完整，任何页面都不得把一个 `step`、loss 循环、训练完成或部署上线称为完整模型生命周期。
- 六段主线共用教学模型 L0：`V=8、D=4、N=2、H=2、D_h=2、M=8、T=4`。修改配置、词表、简化假设或参数量时，必须同步检查三张总纲和引用该模型的 D 课，避免同一教学对象在不同页面漂移。
- 线上迭代必须分开服务健康、输出质量、任务效果与安全治理；用户点击和模型自信不能直接当真值标签。反馈回流前必须说明许可、脱敏、裁决、去重和测试隔离，发布方案必须包含停止与回滚条件。
- 学科地图允许按生命周期、现象、项目和研究四个角度进入同一知识体系。真正的专题课程群至少写明课程目的、现象或问题集合、单元大纲、实际产物、失败边界和基础课连接；榜单、地图、索引和资料库直接服务检索，不强行补齐课程段落。
- 每条路线必须有前置条件和站内可检查的完成证据，但不必各自拥有路线首页。课程首页先给零基础学习者一个直达 D01 的默认入口；[学科地图](../../course/00-从这里开始/学科地图.md)负责按真实问题分流，[全局知识图谱](../../course/00-从这里开始/全局知识图谱.md)负责概念关系，不再维护第三份能力路线目录。
- 正式课程单元开头用一行“学习导航”说明所属主线、承接内容、本课任务和可观察的完成证据；同一信息不得再拆成“主线位置”“本课目标”等连续页首栏目。目录、地图、榜单、论文索引、速查和资料库页面不套用课程模板，而应直接展示入口、来源、图表或检索方法。
- 正文一段只讲一个核心判断，先写结论，再写原因、例子或边界。能删一字不损失含义就删；能用短句就不用多层并列句。链接、公式和必要证据可例外，但不能借例外堆叠主题。
- 标题、导航和目录不要用无助于理解的数量包装内容；“入口页面”“学习规则”“专题课程群”比“三张入口图”“六个课程群”更耐维护。只有数量参与计算、对照、固定步骤或明确验收合同时才保留，并在增删内容时同步核对。
- 精炼不能压成术语提纲。首次概念、具体数字、关键因果、反例、适用条件和承接关系必须保留；正文、表格与动效若重复同一句话，应让三者分别承担解释、对照和状态变化。
- 功能定义不能冒充执行过程。使用“预测下一个 token”“查询向量最相近结果”或“更新一次参数”等简化表述时，必须在首次出现处说明它概括的是输入输出还是内部计算，并在主线课程中至少展开一次实际层级、数量级与硬件约束，避免学习者把输出很小误读为计算很少。
- 理论学习单元在学习导航之后直接给出 3-4 条可复述的核心判断；短案例页可只给一条与当前证据直接对应的粗体判断。判断本身应覆盖本课解决的真实误判及其后续连接，不再另设“为什么要学”长段重复概念。不能只写“这是基础”“很重要”或把目录改写成句子。
- 一页同时承担多个概念时，二级或三级标题直接标明“第一次必看”“场景需要时再读”“进阶”或“随用随查”。跳读边界进入标题、粗体结论和编号，不新增“如何阅读本页”说明段，也不能让拓展知识伪装成进入下一课的门槛。
- 首次阅读应能只沿核心判断和必看标题完成因果主线；已经学过的读者应能只扫粗体、编号、表格与结论恢复结构。一个观点在同页第二次出现时，后文必须增加数字、机制、反例或边界，否则删除或改成链接。
- 每次全局内容审计先回答五问：本页独有的学习问题是什么；附近没有的新证据是什么；熟悉内容的读者能否从标题、粗体、编号和表格判断跳读；合并到相邻页面是否减少点击且不混淆任务；本页哪句话若错误最会误导学习者。前两问为空时合并或删除；最后一问无法回答时不得发布。
- 不能用字符数机械判断密度。保存浏览器学习状态的短页面、高频速查表、现实榜单、动态论文路由和支持页面可独立存在；长页面若只是重复仍须压缩。
- 连续正文优先控制在一个核心因果链内；超过约 180 个汉字时，先检查能否拆为编号步骤、对照表或两个独立结论。公式推导、来源限定和不可分割的证据论证可以更长，但必须有明确的粗体结论或小标题作为扫描锚点。
- 先给直觉和具体数字，再给公式与术语。复杂公式必须先拆成小算式，每一步只承担一个运算动作；先代入具体数字算出结果，再说明符号并展示通用写法。
- 每个块级公式前必须有 `formula-story` 关系图。图先给日常身份，再给符号；明确源对象、带动作名称的连线、参与项、结果、可手算数字、删项或错误替换后的直接后果，以及公式成立边界。连续几行属于同一推导时可以由一张图覆盖；不同机制不得用一张宽泛图虚报覆盖。
- `formula-story` 的 `flow` 只用于顺序变换，`branch` 只用于同一对象分出不同职责，`merge` 只用于多个真实贡献汇聚。线必须表示矩阵乘法、逐项乘、求和、归一化、条件追加、存储轴展开等实际关系，不能用装饰线、颜色或“处理”“然后”代替运算。纯算术账本也要画真实量纲关系，例如“参数数 × bytes/参数 -> bytes”，不能画成空洞的“公式 -> 答案”。
- 类比必须与公式共用同一组角色关系，但不能越界替换真实对象。注意力的 Query 可类比岗位需求，Key 可类比可匹配标签，Value 应表示当前被读取并加权汇总的内容，不能写成尚未发生、模型也无法观测的未来业绩。类比后的边界句必须把学习者带回张量、概率、状态或参数的真实身份。
- 首次出现 $a_i$、求和上下界或数组索引时，必须说明数学下标采用的起点，并与 Python 等代码索引分开；“维数”和“向量长度”不得混用。
- 公式首次同时引入三个及以上符号时，必须就地说明每个符号的对象类型、形状和作用。大小写、希腊字母和英文首字母只能作为记忆提示，不能被写成不可更改的数学规则；局部定义优先。
- 核心公式必须回答问题来源、构造过程、参数职责、删项或特殊值后果、最小数字反例和成立边界。数学恒等式可以直接推导；局部近似必须写明邻域、光滑性或步长等条件；部件反例只能证明该部件的机制作用。“质量更高、训练更快、泛化更好”等效果结论必须由受控对照或消融实验支持，不能从公式外形直接推出。
- 新公式、新目标或新算法不得直接写入 `course/`。先集中登记在 `internal/来源与质量审计/公式与算法创新待评审.md`，记录来源、推导、可反驳条件、与既有方法差异、评审与实验需求及状态；只有状态明确为“通过”后，才可按正常事实核查流程进入学习者内容。
- 必须区分“空间或集合”“空间中的具体向量”“执行映射的矩阵”和“映射后的结果”。标题提出抽象概念后，例子结尾必须用一句明确结论回扣标题，不能只完成算术就离开。
- 关键记忆点优先形成“视觉定位、跟随一次变化、立即回答一个问题”的闭环。动效只用于位置选择、状态变化或逐步汇聚本身就是知识的场景，不能用来替代例题和主动回忆。
- 同一概念若同时提供全局图和局部放大，必须复用同一个教学输入、对象名称、颜色和形状；从局部返回全局时，学习者应能重新定位该对象。外部交互项目只能提供设计证据，课程概念必须由正文后的站内原生动效承载，不能把外部页面作为运行依赖。
- 首次引入概念时说明输入、动作、输出和适用边界。
- 每个训练或部署专题必须从一个真实问题、开发评测集和单独冻结的测试集开始，先用开发证据比较最小基线，再说明为什么需要训练、蒸馏、压缩或检索；方案冻结后才用测试集做最终估计。页面结尾必须回到任务指标和失败边界。
- 讨论模型方法时，必须写清训练了哪些参数、冻结了哪些参数、数据如何进入、输出由谁产生，以及该方法不负责什么。
- 解释模型幻觉时，必须分开训练目标与数据、静态模型权重、本次上下文、解码策略、推理引擎和应用系统。不能把“随机采样”写成唯一原因，也不能把部署引擎写成模型知识质量的主要来源。
- 解释自回归运行时，必须先声明 `decode` 的口径：`decode phase` 可指 prefill 之后反复生成 token 的整个阶段，而本课程用 `decode 前向` 专指其中的模型前向。必须把 `decode 前向` 与“解码策略/采样”拆成两个动作：前者读取当前新位置与历史 KV Cache，写入新 K/V 并产生 logits；后者在 logits 上选择已接受 token。KV Cache 是模型前向的输入/输出状态，不能画成或写成 logits 的独立生产者。
- 路线图同时呈现 `prefill` 与后续生成时，必须把“未停止 → Decode 单步前向 → 下一轮原始 logits → 选择 ID”画成有终点和回边的条件操作；decode 不能只作为带 `↩` 的说明文字。图中必须就地标出 prefill 的整段提示形状，以及 decode 的单位置形状、历史 K/V 和“不重新 prefill 整段提示”的边界。
- 自回归流程图必须分开原始 logits、temperature 缩放后的 logits、softmax 概率、top-k/top-p 候选集合与最终接受的 token ID。Greedy 是直接取最大项的分支；temperature、top-k/top-p 和随机采样可以组成采样流水线，不得写成四个互斥同级选项。下一预测对象统一写 `token`，不能偷换成“词”；位置信息必须按架构写成“加入或作用”，不能把 RoPE 等机制统一画成向 Embedding 相加。
- 自回归图只要保留 batch 轴，就必须把 `(B,V)` 写成每条活跃序列各接受一个 ID 的 `(B,)`；只有明确固定 `B=1` 的图才可写成 1 个 ID。必须分开已接受 ID 记录、下一轮模型输入和增量文本缓冲：记录可以保留 EOS，但终止 token 不再作为该序列的下一模型输入，通常也不显示。生成循环通常检查 EOS 与长度，停止字符串依赖 token 或增量文本缓冲跨轮匹配，应用还可因内容过滤、工具调用或权限规则中止或转交；模块划分依框架，不得将所有停止条件固定归为应用层。只有未停止序列才进入下一轮；已停止序列不再产生有效 token，但移出活跃 batch、使用 mask 或保留占位均可能是合法实现。
- 位置机制必须按架构标出真实接入点：token ID 查 Embedding 得到初始表示；位置 Embedding 可在 Block 前与 token 表示结合；RoPE 在注意力内部作用于 Q/K；相对位置偏置作用于注意力分数。不得用一条 `position → embedding` 边概括所有位置机制。
- 长路线图必须让第一次阅读者先沿一条连续主线建立顺序，再用不同线型连接阶段细节；主线、旁支与条件回环必须有图例并保持固定语义。图、表和正文不得三次复述同一条流程，正文只补图中无法承载的实现差异与方法边界。
- 路线图中的注释连接线不得伪装成数据流：若旁支包含“边界”“别混淆”或“停止条件”，图例必须明确它是注释而非额外计算步骤；top-k 可按分数或概率排名过滤，top-p 才需要概率累计质量，不能把二者写成同一前置动作。
- 后训练专题必须区分继续预训练、SFT、偏好优化、可验证奖励、校准与拒答，并保留基座能力回归集；新任务变好不能替代灾难性遗忘检查。
- 多模态专题必须说明每种模态的原始输入、编码器或离散表示、连接器、主干模型和输出头。张量形状对齐不能替代语义对齐，文本词表也不能被描述成所有模态共用的万能词表。
- 软硬件专题必须分开算法、框架算子、编译运行时、推理服务、集群和硬件，并同时报告软件版本、硬件、输入/输出长度、并发、精度、TTFT、TPOT、尾延迟、吞吐和显存口径。
- 新增蒸馏内容时，至少区分回答、logit、特征和策略蒸馏；新增压缩内容时，至少区分量化、剪枝、QAT 和推测解码，不能用“模型变小”概括所有方法。
- 前沿内容按瓶颈组织，并标注事实、工程实践、作者实验、教学推导和待核查事项；新方法必须有代价、失败模式和可反驳的评测问题。
- 知识图谱边必须注明关系类型，例如“前置于、组成、产生、实现于、解决、局限、替代或互补”；术语链接不能代替依赖关系。
- 出现张量形状或维度变化时，说明每条轴代表什么，并区分查表、线性投影、reshape/转轴、网络内部压缩和分析可视化降维。
- 讨论 Embedding 或隐藏表示时，说明模型、层、位置和上下文；不能把静态 token Embedding 当作所有层中的固定语义向量。
- 使用二维或三维表示图时，写清样本、层、归一化、度量、降维方法与参数，并明确低维图不能保留全部高维关系。
- 把“事实”“工程经验”“近似估算”和“仍有争议的观点”明确区分。
- 不用单一 loss、排行榜分数或生成样例代替完整评测。
- 配套图解必须包含看前预测或看后立即回答；仅让学习者顺序浏览四格，不算形成主动回忆。
- 工程案例必须使用课程提前准备的配置、日志、张量记录、输出、指标、模型卡或有明确来源的公开材料；数字例子要标注“教学示例”“预生成记录”或具体来源，不能伪装成通用 Benchmark。
- 冻结案例引用仓库提交时，必须确认该提交实际包含所述路径；由文本文件推导字符数、词表和切分时，必须使用训练代码的读取与换行口径，不能把工作区 CRLF 字节数直接写成模型输入规模。参数量必须同时绑定词表、维度、层数、bias、Norm 和权重共享约定。

## 模型算法图解规则

- `09-模型算法图解/` 是跨课程的视觉索引，不复制理论课、专题课或论文课的完整讲解；每章只解释一个稳定算法或算法家族。已有直接对应正式课程时必须回链；尚无专门课程时不得把相邻课程冒充对应课程，必须在总览收录边界中明确缺口与本章能承担的深度。
- 每章至少包含一张机制主图、一张边界对照图和一张生命周期位置图。图承担“输入或初始状态、关键动作、输出或新状态、易混边界与使用节点”；短正文和表格负责解释条件、证据、代价与简化边界，不能重复抄写图中文字。
- 每章必须包含“为什么不是随便设计的”，用该算法独有的状态转移、约束、最小公式或反例解释关键部件，并至少给出两项删减、固定值或错误替换后的直接后果。公式是核心机制时可给最小可核对推导并回链正式课程；公式不是核心时不得为了模板硬塞公式。图解仍不复制正式课程的完整长推导，验收以沿图复述对象、因果和删项后果为主。
- Mermaid 图必须能在移动端缩放阅读，节点文字保持短句；内部 HTML 标签必须保持与 Mermaid 布局计算一致的行高，并允许中日韩回退字体的字形外伸，不得继承正文段落行高或使用隐藏溢出裁掉节点末字。不得用一张巨图塞入实现细节，也不得用图片中的小字代替 Markdown 正文。
- 计算或控制流使用实线，解释、属性和边界使用虚线，两者必须在图例中分开。同一对象有多条用途时，先画共同主干再从一个节点分叉；条件判断必须分别画出结束与继续结果，不能用一段图外说明补救错误连线。
- 每章必须写明方法边界，不能从机制图直接推出质量、速度、显存或安全收益；涉及硬件、数据和评测的结论必须回到正式课程核对。
- 每章必须包含“同一位置的不同选择”，只比较作用于相同生命周期节点和相同对象的方法，并分别说明效果与代价。模型结构、训练优化、后训练、压缩和在线解码不得混成一组排行榜。
- 每章必须包含“采用判断”表，并分别写明主要优势、主要局限、适合考虑、不适合直接采用和采用后必须检查。优势必须对应具体条件，局限必须能转成评测、监控或回退动作，不能写“视情况而定”。
- 每个独立算法章必须在页面右侧提供固定“采用判断”书签，点击后使用章节锚点跳到本章判断表；总览页不显示该书签。桌面端书签保持常驻，手机端使用紧凑样式，并且不得遮挡正文、图解、反馈入口或支持入口。
- 是否采用算法必须从现有基线的失败证据出发：先定位数据、结构、训练、部署或解码节点，再比较同节点方案；对照前冻结验收集、资源预算、安全红线和回退条件。
- 采用后的持续检查至少覆盖目标质量、真实资源成本、已知失败切片和版本回退。理论 FLOPs、参数量、bit 数、稀疏率或单一平均分都不能单独作为采用证据。
- 总览页必须维护“数据与编码 → 架构设计 → 预训练或任务训练 → 后训练与适配 → 压缩部署 → 在线推理 → 评测监控”的算法定位图，并注明同一算法可能跨越多个节点。总览还必须公开当前收录口径、刻意不重复拆章的跨算法机制和没有对应正式课程的内容缺口；不得把“当前目录完整”写成“已经收录全部模型算法”。
- 完整性验收分三层：目录层核对总览、注册表和 Markdown 文件一一对应且链接有效；章节层核对机制、对照、生命周期、同位选择、采用判断、复述与边界都有实质内容；决策层核对优势带条件、局限能转成检查或回退动作。缺少任一层，不得只凭文件数或图数量宣称完整。
- 新增算法章只在 `.vitepress/course-data.mjs` 的 `algorithmLessons` 中登记，侧边栏、学习单元与进度记录由该注册表派生，不再手工重复维护；同时更新总览收录口径和内容检查。只有写作合同发生变化时才修改本规范；新增可复用术语仍要同步术语注册表和术语速查页。

## 铅笔视图规则

- Markdown 使用 `pencil-flow`、`pencil-vector`、`pencil-formula-plane` 或 `pencil-3d` JSON 围栏描述教学场景，绘图实现留在主题组件中。
- 二维静态或分步视图用于流程、对比和公式拆解；只有向量空间、多轴信息流等空间关系确实重要时才使用三维。
- 公式可视化优先把公式项与可核对的平面曲线、向量、投影、区域或三维空间对象并列，并用带动作名称的连线建立一一对应。坐标轴、方向、长度、距离和夹角只有在数值与公式确实支持时才能承载数学含义；若图只是布局摘要，必须明确写出边界。不能为了“所有公式都能画”而虚构几何意义，单次代入、固定结构或无空间关系的公式继续使用小算式、表格或二维流程。
- `pencil-formula-plane` 的 Markdown 数据必须声明坐标范围、向量端点、公式对应连线、完整等价式、读图边界和逐步 `focus`。同一分镜只突出一个几何量到一个公式项的对应，连线标签要说明“分量配对相乘”“贡献相加”“用长度和夹角核对”等实际关系，禁止无标签装饰线。
- 每个场景必须提供 `ariaLabel`。逐步讲解至少包含 2 个步骤，并同时提供流程总览和减少动态效果支持；自动播放必须给阅读说明留出足够时间，并在最后一步停止。
- 复杂动效不能把首次操作责任留给学习者。核心理解依赖状态变化时，场景进入可视区域后应自动完成一轮带同步讲解的验证，或提供等价的显式引导；自动流程必须可暂停、继续、重播和切回手动控制，离开可视区域时不得在后台悄悄播完。
- 每个场景必须先在 Markdown JSON 中回答 `learningGoal`（学完应能做什么）和 `watchFor`（眼睛重点看什么）。没有可检验学习目标的图保持静态，不增加播放控件。
- 每个步骤必须提供 `title`、`watch`、`purpose`、`detail`、`reflection` 和 `active`：图中标出当前状态，图下直接解释观察位置、作用、关键理解和反思问题。算法显微镜还必须提供一条可扫读的 `focus`，只写本步最重要的对象关系，不把完整说明搬进焦点句。只改变高亮或播放顺序、没有新增解释信息的动效不合格。
- 算法动效必须先列出当前作用域中的输入对象、固定规则、临时状态、缓存状态和输出对象，再按“输入节点 → 带文字的动作箭头 → 结果节点”拆分镜。每一步只承担一个主要状态变化；逐步模式隐藏尚未发生的后续场景，不能让整张低透明度总图与当前动作争夺注意力。动作箭头必须说明实际运算或状态操作，不能只写“处理”“计算”或依赖颜色表达含义。
- 首次出现数学符号时，节点先给日常语言身份，再在同一节点补充符号；同一画面不得把 token、向量、参数矩阵、缓存和候选分数画成无法区分的同类方块。省略中间实现时，箭头必须明确写出被折叠的动作和简化边界。
- 每个形象化对象必须能回答“点、线、外框、方向、长度和运动分别代表什么”。字符串、token、ID、数值张量、KV Cache、logits、已选 ID 与输出文本不得复用同一种点阵盒；只有数值数组才能使用数值点阵，并标明点是一一对应、抽样还是聚合。分类轴若没有实测距离与大小，必须移除数值网格和分量线，并声明方向、长度与正交只用于排布。
- 运动标记必须声明身份。流程焦点、数据对象和 token 不得共用同一个移动圆点；若标记只表示播放进度，就使用独立的焦点符号，并明确它不代表正在传输的数值。无法为图形编码写出稳定含义时，删掉图形，不用免责声明掩盖。
- 人眼单焦点：同一时间只能有一个随步骤更新的旁白区；每一步还必须明确一条“本步只看”的对象关系。播放、暂停只能有一个操作入口，浮动指南只报告状态与进度，不得再放第二套继续、暂停或重播按钮。跨步骤必须保留固定路径或稳定输入/结果锚点，让观众看到同一条数据流推进，而不是连续替换的孤立幻灯片。
- 数字关系优先：向量默认写成带括号与分隔符的紧凑序列，整体边界只说明“这是一份向量”。只有逐坐标配对、比较或相加本身就是本步学习目标时，才把相关标量单独成格并高亮正在核对的坐标；不得为了装饰把每个数都做成同等醒目的方框。
- 统一画板：算法动效把舞台当作一张连续画板，区域说明、方法名和旁白透明嵌入；只给向量、分数、缓存和输出节点保留低透明度边界，避免多个实色卡片遮住同一条数据流。新增 `token-compute-tower` 必须在 JSON 中声明 `animationContract`，固定使用 `single-stage`、`transparent-embedded`、`single-changing-narration`、`stable-path`、`auto-with-manual-controls`、`document-flow`、`fixed-exit`、`content-driven` 和 `local-only` 九项合同值；其中 `content-driven` 表示场景高度由当前内容决定，`local-only` 表示浮动控件只能在局部避让，不能给整条舞台预留空带。
- 页面密度：桌面端不得用统一 `min-height` 拉齐短步骤，也不得为右上角指南预留整条顶部空间；指南只占它实际覆盖的局部区域。窄屏端把浮动指南放回画板文档流，再让场景纵向排列，确保说明、箭头和页面滚动连续可见。验收每一步至少核对舞台、当前场景和旁白的实际高度，若可见内容明显少于容器高度，先删掉布局占位再加装饰。
- 三列以上的审查表在窄屏不得把解释列压成单字竖排，也不能依赖整页横向滚动；只对这类字段记录页改成“字段、冻结记录、审查重点”的纵向连续布局，普通数值对照表继续保留表格关系。
- 大画板不等于把关系拉满视口。全屏可以铺满背景、路径和全局控件，但单步输入、动作箭头、结果与旁白必须限制在一个中心阅读宽度内；宽屏验收要测输入到结果的实际视线距离，不能让同一动作的两端分别贴住屏幕左右边缘。
- 场景标签、步骤说明和数值属于课程内容，必须写在 Markdown JSON 中，不能藏进前端组件。
- Three.js 与 Rough.js 使用固定版本的本地 ESM 文件，不在课程运行时访问外网；文件哈希由内容检查锁定。
- 三维画布必须延迟初始化、限制像素比、离开页面后释放资源，并在桌面与手机视口检查非空像素、构图、拖动和控件遮挡。手机端还要验证手势从画布内部开始时仍能纵向翻页；窄屏或粗指针设备不得用滚轮缩放拦截页面滚动。
- 全屏教学视图必须在视口固定位置提供高对比度退出按钮，不能只依赖 `Esc`、双击或滚动后才出现的工具栏；退出后必须恢复原页面位置与交互状态。
- 用点阵表达大规模参数、激活或缓存时，必须标明点阵是抽样、聚合还是一一对应，并显示从可见点数到真实数量级的换算；若换算只用于比较规模，必须说明它不代表真实空间归属。残差等信息通路不能画成参数分区。用楼层表达 Transformer 深度时，楼层数必须对应明确的 Block 数，不能用“无限高”暗示模型层数没有上限。

当前动效的逐项判断与保留理由见[教学动效审计](教学动效审计.md)。新增或改变动效时，必须同步更新该审计。

## 纯前端展示规则

- 课程正文、题目、专题名称、路线说明和学习产物只写在 Markdown 内容源中；Vue 组件只能提供通用布局、交互和无障碍行为。
- 组件通过 Markdown props 接收结构化内容，不得把某一课的讲解文字、课程顺序或答案复制进前端源码。
- `lesson-board` 只用于压缩一课已经建立的因果链：标题先给结论，分区分别呈现对象、过程、对照或边界，底部用四个可复述点和一句收束帮助回忆。它不替代正文、例题、公式拆解、动效或验收题。
- 看板必须是原创网页内容，不复刻第三方图、文案、图标组合或海报版式；保留其有效的教学结构，但以本站术语、示例和证据重新组织。
- 看板内容必须留在 Markdown 的结构化 JSON 中，并具备 `ariaLabel`、标题、副标题、至少两个有内容的分区、四个 takeaways 和结论。桌面端可用网格组织信息，移动端必须单列展开；不得为了模拟海报把正文缩小到不可读。
- 浏览、标签页、进度和术语预览在客户端完成。若状态只保存在当前浏览器，页面必须避免暗示已经存在账号同步、云端训练或后端持久化。
- 新增交互必须支持键盘、减少动态效果和移动端布局；固定格式控件要使用稳定尺寸，不能因标签或动态内容发生跳动。

## 评测榜单规则

- 模型评测专题优先使用 `benchmark-leaderboard` JSON 围栏呈现可筛选的多指标矩阵；只有一个主指标时使用 `benchmark-chart` 围栏渲染紧凑排名表。榜单标题、列、数值、单位、状态与边界全部留在 Markdown，Vue 组件只负责筛选、排序、热度底色和无障碍呈现。
- 同一张榜单表只能放入同一机构、同一数据集或 release、同一运行口径的数据。不同榜单、指标定义、分母、方向、推理预算或 Agent harness 不得拼进同一排序。
- 排名表必须同时显示精确值；热度底色只帮助扫读，不能通过截断轴或夸张色差放大微小领先。现实模型数据写明日期、版本和官方来源；预生成数字紧邻声明其不是现实 benchmark。
- 榜单表不能替代样本量、置信区间、成对结果、失败切片、成本、安全红线、许可证与数据边界。点估计最高但硬约束失败的候选必须在表内或紧邻正文明确标出。
- 桌面端优先让模型名和关键指标同屏；移动端允许表格在自身区域横向滚动，但页面本身不得横向溢出，也不允许反馈或支持入口覆盖数值与脚注。
- 榜单页不追加独立术语课程；指标含义直接写在图表副标题、表格列名或读图提示中，避免把榜单入口变成另一套术语学习路线。
- 模型评测目录的主任务是汇聚现实榜单：每一行必须给出负责机构、官方直链、页面可见更新时间、测量对象、当前前列、可信度和主要限制；不同榜单不得拼接成综合排名。Hugging Face 已标记 Archived 的榜单只能作为历史资料。
- 现实榜单快照在 Markdown 中使用 `<!-- benchmark-snapshot: YYYY-MM-DD -->` 标记；动态页面是实时来源，仓库快照只承担可追溯记录。快照超过 45 天由仓库检查和定期 GitHub Actions 提醒复核，不得静默把旧结果写成最新结果。
- 含现实数值的动态榜单必须用图表内唯一 `evidenceId` 关联仓库逐源记录。每条记录包含官方 URL、页面/release 日期、提取日期、模型身份、指标、运行条件与逐行数值；检查脚本只证明课程图表与仓库记录一致，不得声称已经联网核实官方页面。只有保存了官方不可变导出或归档时，才记录 `sourceArtifact` 与 `sourceArtifactSha256`；否则明确写明没有不可变源工件。课程 Markdown 不得暴露内部审计路径。
- 榜单位置必须服从来源的统计口径：来源给出 rank spread 或置信区间时显示区间，不得压成确定名次；主指标同分且没有公开 tie-break 时显示并列；筛选、搜索或改按其他列排序后的数组序号只能称“当前视图顺序”，不得冒充官方排名。聚合分必须写明包含哪些分项，隐藏部分分项时明确不能由可见列复算总分。
- 证据记录必须覆盖会改变选型判断的可见字段，不只保存主分数。至少同步核对模型完整身份、机构、推理档位、开放权重或许可证标签、成本、显示精度、名次/区间与运行条件；组件不得从数组下标生成看似官方的名次。

## 学习记录规则

- 学习记录只写入当前浏览器的 `localStorage`，不得发送到服务器，也不得暗示存在账号、云端同步或跨设备恢复。学习记录页必须说明清除网站数据会同时删除记录。
- 单元反思与阅读、答题记录使用同一套浏览器状态。只为最近学习单元提供简短的“最模糊的一点”输入，不再维护按天打卡或第二套手工完成表。
- “暂时跳过”和“完成本次学习”属于学习收尾操作，必须出现在正文与验收内容之后、上一课和下一课导航之前。页首只提供进入课程所需的信息，不能让学习者尚未开始阅读就先面对完成按钮。
- 阅读进度与知识掌握是两个独立维度。阅读状态使用“未开始、学习中、已读完、已跳过”；掌握状态使用“未检测、练习中、待复习、已掌握”。界面必须允许出现“已读完 · 待复习”。
- 续读入口保存课程单元、最近二级或三级标题和滚动位置。只有学习者主动点击续读入口时才恢复位置；外部链接与带锚点链接不得被强制改写。
- 题目必须保存草稿、选项、尝试次数、最近结果和下次复习时间。答错或未作答安排 1 天后复习，部分正确为 3 天，首次答对为 7 天，连续答对逐次翻倍且最多 30 天，答错后首次答对为 3 天。
- 概念状态必须由可查看的作答证据推导，使用“未检测、待巩固、补救中、已稳定”，不得显示无法解释来源的掌握百分比。答错后仅展开答案不算掌握；完成针对性补救并通过迁移题后，原题才进入间隔复习。
- 学习记录页应展示最近证据、活跃误解、前置影响和建议动作。下一步推荐按“到期复习、重复误解、影响后续的脆弱前置、当前补救、静态课程顺序”依次判断，所有规则保持纯前端、确定性和可解释。
- 同一次展示答案后的自评只计为一次尝试。通过复习入口进入题目时，应提供空白重答界面，同时保留历史结果用于安排后续复习。
- 可长期维护的交互题应显式提供稳定 `id`。未提供时允许组件按来源路径与题干生成兼容标识，但修改题干可能使旧记录无法继续关联，内容维护者必须把这视为一次学习记录迁移。
- 学习单元登记以 `.vitepress/course-data.mjs` 的 `learningUnits` 为准。正式课程、项目和逐篇研读单元必须同步登记；目录、地图、榜单参考页和资料库不得登记为学习进度单元，数学和图解等按需材料可标为非推荐单元。

## 证据标签

前沿模型、技术报告和排行榜内容必须区分：一手事实、作者实验、作者主张、教学推导、工程估算和待核查事项。不能把“作者给出的设计理由”自动升级为“经过消融证明的结论”，也不能把多个改动共同产生的结果归因给单个模块。

模型评测与选型内容还必须把稳定方法和有日期的现实快照分开。现实模型条目写具体仓库/版本、核查日期、许可证来源、模态与资源口径；模型卡、许可证元数据和其他会变化的网页证据必须固定到可复核的 commit SHA 或等价不可变 revision，不能用会随 `main` 更新的页面支撑历史快照。“值得考虑”只表示进入候选池，不表示综合冠军。总参数、激活参数、上下文上限、下载量、作者自报分数和托管服务表现均不得单独升级为本地质量结论；不同 prompt、推理预算、量化、工具或 Agent harness 的结果不得省略条件后横向排序。预生成教学数字必须紧邻声明其不是现实模型 benchmark。

评测案例中的统计分母必须对应事件真正有机会发生的样本。安全指标要在看结果前冻结事件、严重度、可接受的风险上界和由此反推的样本量；只要求零观察但不比较上界，不能作为最终统计放行。只有来自定义明确总体的概率抽样，才能在相应假设下使用二项区间估计发生率；固定回归题与刻意构造的红队题只报告覆盖和失败，不得套用总体风险上界。反复参与候选、提示或阈值选择的开发集区间与检验只作探索性描述，确认性估计来自方案与分析规则冻结后的独立测试。性能验收必须同时规定请求成功率与“成功且按时完成”的联合门槛；只在成功请求中计算的 p95 只能作诊断，快速报错不得改善验收结果。性能案例若使用预生成数字，必须列出完整的虚构冻结账本并明确不能在现实硬件复现；现实记录则必须填写真实型号、revision、哈希、种子、长度分布和超时。系统内存、独立显存和统一内存必须分开记录，模型卡的 `memory` 不得在没有硬件证据时改写成 `VRAM`。

检索指标不能互相代称。Recall@k 写明“前 k 项中的相关项数 / 全部相关项数”及跨查询聚合；Hit@k 只表示至少命中一个相关项；回答依赖多个证据时，另报全部必要证据齐全率。只有每个查询恰好一个相关项时，单查询 Recall@k 才退化为 0/1 并与 Hit@k 相同。

使用二手教程时，先记录其版本、许可和准确性声明，再回到论文、模型卡或官方代码独立撰写。二手材料中的题目、图像、措辞和交互实现不能在未核对许可与署名义务的情况下复制。

使用开源课程或源码仓库时，必须分别记录代码许可证、书籍/图片版权、模型权重许可证和数据许可证；GitHub Star 不得作为教学正确性或推荐顺序的证据。作者已经标记弃用、长期无维护或依赖已下线服务的项目，只能作为历史样本，并在正文中指向当前替代方案或明确证据空白。

论文速研分为快速筛选、证据扫描和深入复核。AI 工具可以帮助发现、定位、切分和整理候选证据，但“已总结”不能作为“已复核”；所有关键主张必须通过出处、支持、冲突和隐私四个闸门。未发表论文、审稿材料和内部文档默认不得上传外部模型服务。

论文涉及官方代码时，证据卡必须记录论文版本、仓库版本、公式或伪代码对应模块、配置/形状以及测试或预生成结果。教学实现、参考实现和性能优化实现要分开标注；无法运行或没有公开代码时记录缺口，不能用“仓库存在”代替复现。

论文课件的完整调研、转译和验收流程见[论文课件生产规范](论文课件生产规范.md)。

模型系列论文目录采用“双索引”：按研究问题组织主学习路线，按模型系列记录演进。每个条目必须标明正式论文、技术报告、仓库随附报告、机制伴读或发布说明；没有独立论文时必须明确写出证据空白，禁止把博客、模型卡或第三方评测冒充系列论文。论文阅读状态仅保存于当前浏览器，只有完成数字对账、代价和反例后才标为已复核。

- 每篇主线论文课件必须使用唯一的 `paper-lesson` ID 连接 `.vitepress/wiki-terms.mjs` 之外的论文规范数据源 `06-拓展知识库/论文研读/01-论文库.md`，由其中的 `problem`、`mechanism`、`training`、`evidence` 和 `boundary` 生成统一五节点认知骨架；不得把单篇论文讲解硬编码进 Vue 组件。
- 系列路线必须把“站内深读”和“论文原文”拆成两个明确入口。单篇页首提供原文、阅读方法、系列路线和前后篇导航，页尾来源仍保留完整标题；不得只在正文末尾埋一个来源链接。
- 五节点图承担位置、形状和因果方向记忆，正文中的机制图承担具体信息流，两者不能互相替代。闭卷回放只记录当前浏览器的最近核对时间，不自动等同于已读完、已复核或已掌握。
