# 服务性能对照案例

> **学习导航**：汇总指标、容量、计算、引擎和并行；本课审阅一次预生成服务对照；完成证据是能解释性能报告和瓶颈树，而不是只看单个 tokens/s 数字。

## 本课目标

在固定质量与 SLO 条件下阅读两组冻结服务记录，同时比较延迟、完成吞吐、有效吞吐、显存、错误率和输出回归。

## 本课核心判断

**性能对照必须冻结输入、输出、warm-up、并发和质量门槛，否则差异无法归因。**

## 预设实验合同

这是一组预生成的教学记录，不是公开模型 Benchmark。环境固定如下：

| 项目 | 固定值 |
|---|---|
| 模型与接口 | 课程教学模型 `Serve-3B-v1`；`serve-tokenizer-v1`；模板 `route-v3`；greedy 解码 |
| 软件 | Ubuntu 24.04、NVIDIA Driver 570.133.20、CUDA 12.8、vLLM 0.10.1 |
| 硬件 | 单张 NVIDIA L4 24 GB；同一台主机 |
| 缓存与精度 | KV Cache 使用 BF16；基线权重 BF16；方案 A 仅将权重改为 INT4 weight-only |
| 负载 | 并发 8；先 warm-up 20 次，再测 60 秒；使用同一组短输出路由请求 |

请求输入分布为：128 token 占 50%、1,024 token 占 30%、4,096 token 占 20%。输出上限均为 128 token；基线实际输出长度的平均值/P50/P95 为 5.8/5/11 token，方案 A 为 6.7/6/13 token。量化改变了少量生成结果与停止位置，因此两组实际输出长度并不完全相同。`tokens/s` 统计实际生成的输出 token，不含输入 token；TTFT 与 TPOT 报告完成请求的中位数，P50/P95 则指端到端延迟。

单请求计入有效吞吐的条件预先写为：端到端延迟小于 750 ms、请求无错误且输出通过冻结质量检查。测量窗口还要单独满足两条分布级 SLO：中位 TTFT 小于 150 ms、P95 端到端延迟小于 750 ms。单个请求只有自己的延迟，没有自己的“P95”；表中的 P50/P95 都是整个测量窗口的端到端延迟分位数。

## 可选对照

- 单请求与连续批处理。
- BF16 与目标量化格式。
- 前缀缓存关闭与开启。
- 不同 KV Cache 配置。
- 单卡与多卡并行。

每组预生成对照只改变一个主要变量，其他配置保持一致。学习者负责检查材料是否真的满足这一条件。

## 报告表

| 配置 | 中位 TTFT | 中位 TPOT | P50/P95 端到端 | 完成请求/s | 有效请求占比 | 有效请求/s |
|---|---:|---:|---:|---:|---:|---:|
| 基线 BF16 | 128 ms | 31 ms | 420/710 ms | 8.0 | 97.5% | 7.8 |
| 方案 A：INT4 权重量化 | 156 ms | 25 ms | 438/760 ms | 9.1 | 78.0% | 7.1 |

| 配置 | tokens/s | 峰值显存 | 错误率 | 冻结质量回归 |
|---|---:|---:|---:|---|
| 基线 BF16 | 46 | 12.8 GB | 0.2% | 通过 |
| 方案 A：INT4 权重量化 | 61 | 11.4 GB | 0.3% | 长输入桶下降 4 个百分点，未通过 |

有效吞吐按单请求条件复算：基线为 `8.0 x 97.5% = 7.8 请求/s`；方案 A 为 `9.1 x 78.0% ≈ 7.1 请求/s`。窗口级 SLO 再单独判断：A 的中位 TTFT 为 156 ms，P95 端到端延迟为 760 ms，两项都未通过；长输入质量也退化。A 的总 tokens/s 与显存更好，仍不能宣布它胜出。

## 瓶颈树

从预设现象逐层排查：排队与并发、输入 prefill、decode 搬运、KV Cache 容量、kernel 支持、通信与硬件。每个结论都要引用表格证据，不写“GPU 没吃满所以换更强 GPU”之类跳步结论。表中数字是教学示例，不是通用性能基准。

## 本课验收

1. 为什么量化实验必须保留输出质量回归？
2. warm-up 不一致会怎样污染结果？
3. P95 比平均延迟多提供什么信息？
4. 一个配置吞吐更高但 TTFT 更差，应怎样结合场景决策？
5. 为什么有效吞吐可能与总 tokens/s 给出相反排序？

## 方法边界

这组记录只适用于上面标注的模型、软件、硬件和负载。学习者不运行服务；真实项目还要由负责团队完成长时间稳定性、容量峰值、故障和成本测试。
