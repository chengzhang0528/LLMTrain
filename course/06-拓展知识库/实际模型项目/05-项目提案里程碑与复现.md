# 项目档案、里程碑与复现

> **学习导航**：汇总项目路线；本课审阅一套预设提案、基线、里程碑和最终报告；完成后应能判断另一个人能否据此复核关键实验并理解项目边界。

## 本课目标

找出预设项目提案、里程碑检查表、实验记录、最终报告和复现说明中的证据缺口。

## 本课核心判断

**Demo 不是项目证据；提案、阶段检查和最终报告要在成本可控时暴露目标漂移、数据问题与失败结论。**

## 五个阶段

| 阶段 | 核心问题 | 应出现的证据 |
|---|---|---|
| 提案 | 问题值得解决且可评测吗 | 问题合同、两套评测集、风险与资源 |
| 基线 | 最简单方案表现怎样 | 至少两个基线、失败分类 |
| 里程碑 | 数据流和主要方法可运行吗 | 接口图、smoke 结果、初步对照 |
| 最终实验 | 哪个变量带来什么变化 | 冻结测试结果、质量/性能/安全矩阵 |
| 复现审查 | 别人能否验证和正确使用 | 配置、数据卡、模型卡、复现说明 |

## 允许失败，但不能没有证据

预设项目可以得出“训练没有超过规则基线”“量化导致关键类别退化”或“数据不足以支持结论”。只要记录可复查、归因清楚，这些都是有效结论。反过来，一个效果漂亮但没有冻结测试和版本记录的 Demo 不能通过验收。

## 最终报告结构

问题与边界、相关方法、数据、系统设计、实验设置、结果、失败分析、伦理与安全、成本、限制、下一步。主张必须能回到表格、日志或样本，不用宣传语代替证据。

## 预设案例观察

四份提案摘要如下。每份只缺一个关键证据：

| 提案 | 已有内容 | 关键缺口 |
|---|---|---|
| 工单路由 | 问题合同、冻结集、规则与模型基线 | 没有高代价误分的回滚条件 |
| 带引用问答 | 数据许可、检索基线、忠实度评测 | 没有记录索引与文档版本 |
| 低成本学生模型 | 教师基线、蒸馏配置、目标硬件 | 没有独立于教师生成数据的测试集 |
| 图文理解 | 分层任务、样本卡、零样本基线 | 没有保存视觉预处理器配置 |

例如，学生模型即使复现了训练损失，没有独立测试集也无法证明泛化；图文项目缺少预处理器配置，则同一权重也可能因裁剪和归一化不同而得到不同输入。

## 本课验收

1. 为什么项目提案应在数据和训练投入前完成？
2. 一个未超过基线的项目怎样仍然形成有效成果？
3. 哪些文件共同支持复现？
4. Demo 成功为什么不能替代最终报告？

## 方法边界

教学项目的资源和数据规模有限，结论必须限制在当前样本、模型和硬件。不能从一次小实验外推所有模型或生产流量。
