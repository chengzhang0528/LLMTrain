# 前沿瓶颈地图

这页不是论文名录，而是一个按问题组织的入口。前沿方法会快速变化；阅读时要区分稳定原理、已发布实现、作者实验结论和课程推导。一个新名字只有在能说明“它缓解了什么瓶颈、代价是什么、证据是什么”时才值得进入主线。

## 按瓶颈寻找方法

| 主要瓶颈 | 代表路线 | 必须同时检查的代价 |
|---|---|---|
| 数据质量、重复和污染 | 许可治理、去重、数据配比、合成数据、数据课程 | 错误回流、评测污染、合成数据坍缩 |
| 训练成本和容量 | Scaling Laws、稀疏 MoE、混合精度、并行训练 | 通信、负载不均、总参数存储和故障恢复 |
| 长上下文计算 | FlashAttention、滑窗/稀疏注意力、MLA、线性注意力、SSM、混合架构 | 精确检索能力、并行性、信息压缩和位置外推 |
| 推理能力 | 过程监督、验证器、RLVR、搜索、测试时计算、离策略与在策略蒸馏 | 奖励投机、教师/学生可学习性、长轨迹信号退化、延迟和测试泄漏 |
| 推理控制与服务行为 | 思考预算、动态 effort、模型路由、上下文压缩、工具循环和回归集 | 服务端默认值、版本切换、上下文丢失、质量/成本/延迟权衡 |
| 低成本部署 | 量化、QAT、剪枝、低秩、模型合并、推测解码 | 质量下降、算子支持、硬件依赖和复现差异 |
| 当前知识与行动 | RAG、工具调用、Agent、记忆、环境反馈 | 权限、提示注入、检索错误和循环失控 |
| 跨模态理解与生成 | 视觉/音频编码器、连接器、原生多模态、扩散、自回归视频 | 模态对齐、分辨率、数据配比、感知错误和安全 |
| 可靠性与治理 | 校准、鲁棒性、红队、可解释性、隐私、版权和版本治理 | 指标被投机、能力与安全互相牵制、责任边界不清 |

## 读图顺序

读任何前沿技术报告，都填写下面的卡片：

1. **问题**：旧方案在什么输入、长度、硬件或任务上失败？
2. **改动**：改变了数据、目标、参数、结构、训练流程还是服务系统？
3. **基线**：与什么规模、数据、预算和推理设置比较？
4. **证据**：是消融、独立评测、作者主张、工程估算还是课程推导？
5. **代价**：增加了什么显存、通信、训练难度、延迟或失败模式？
6. **边界**：在哪些条件下不能推广？下一步如何反驳？

## 重要前沿专题的学习出口

| 专题 | 读完必须能做什么 |
|---|---|
| MoE | 区分总参数、激活参数、路由、专家通信和负载均衡 |
| 长上下文 | 解释注意力矩阵、KV Cache、检索失败和外部记忆的差异 |
| SSM/线性注意力 | 说明固定状态如何降低成本，又为何可能丢失精确历史 |
| 推理训练 | 区分监督答案、偏好、可验证奖励和搜索过程 |
| 蒸馏与压缩 | 设计教师/学生/量化的独立对照，并检查教师新增能力、学生访问状态与轨迹长度 |
| 多模态 | 画出模态编码器、连接器、共享表示和输出头的接口形状 |
| Agent | 将基础模型能力与工具、权限、执行器、记忆和评测 harness 分开 |
| 推理控制与服务行为 | 把“更认真”“更快”“降智”等主观说法拆成模型、运行时、服务和输入等分层证据 |
| 可靠性 | 同时报告能力、校准、鲁棒性、安全和数据污染风险 |

## 证据等级

- **L0 稳定基础**：可由公式、代码或多个独立实现复核。
- **L1 工程实践**：在明确硬件、版本和负载下有效。
- **L2 作者实验**：只说明报告中的数据和设置，不自动推广。
- **L3 前沿假设**：有合理机制但证据或适用范围仍有限。

前沿内容默认从 L1-L3 出发，不能把“新”写成“更好”。课程的价值是训练判断方法，而不是追逐不断变化的模型名单。
