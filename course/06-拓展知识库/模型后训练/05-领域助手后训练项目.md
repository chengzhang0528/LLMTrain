# 领域助手后训练案例

> **学习导航**：汇总基座审计、SFT、偏好和回归；本课审阅一条预设的领域助手后训练方案；完成证据是能指出方案卡、数据卡、回归矩阵和模型卡是否相互支持。

## 本课核心判断

**后训练项目必须把需求、数据、训练、评测、部署和回滚串成证据链；只知道算法名无法证明模型变好。**

## 预设项目档案

档案中的目标是技术支持工单助手。输入是用户问题、产品版本和允许使用的资料；输出包含问题分类、需要追问的信息、建议回复和证据。信息不足、资料冲突或越权时必须拒答或升级人工。

## 对照版本

1. 基座 + 固定提示。
2. LoRA-SFT：SFT 规定监督目标，LoRA 规定只训练低秩增量。
3. LoRA-SFT + 偏好优化（只有偏好数据质量足够时）。
4. 可选：加入检索，但必须作为系统变量单独比较。

## 项目里程碑

| 阶段 | 预设材料 | 进入下一阶段的条件 |
|---|---|---|
| 任务冻结 | 问题合同、开发评测集、独立冻结测试集、资源上限 | 目标和失败代价可评测，两个评测集职责分开 |
| 基座审计 | 配置、基线、失败分类 | 确认训练能解决主要缺口 |
| 数据准备 | 数据卡、分桶、泄漏检查 | smoke 和单 batch 测试通过 |
| 训练对照 | 检查点、日志、版本表 | 目标任务有稳定改善 |
| 开发评测 | 能力矩阵、安全与可靠性结果 | 按预设门槛选定候选版本、阈值和规则 |
| 最终测试 | 未参与选择的冻结测试记录 | 只做最终估计，不再据此选择方案 |
| 复现审查 | 模型卡、部署与回滚说明 | 他人能够复核实验结论 |

## 当前证据链

课程已经提供[方案与任务边界](01-基座审计与任务边界.md)、[数据卡式记录](02-SFT数据与训练方案.md)和[开发评测回归矩阵](04-回归校准与安全.md)。回归矩阵中的候选都没有通过预设门槛，因此当前流程应停在开发评测：独立冻结测试集尚未开启，也不能把“有一个分数更高的版本”写成最终候选。

## 档案必须包含的成本

完整档案应同时记录训练显存和时间、适配器大小、推理显存、TTFT、TPOT，以及合并或加载适配器的方式。质量提高但目标硬件无法部署，不算完成需求。

当前课程材料只能核验[LoRA-SFT 方案中的 smoke test](02-SFT数据与训练方案.md)：峰值显存为 `18.6 GB`，低于 `22 GB` 预算。正式训练时间、适配器大小、推理显存、TTFT、TPOT 和加载方式均未提供，因此本案例只能说明训练链路能够接通，不能证明已经满足部署要求。正确的审查结论应是“性能证据不足”，而不是自行补出数字。

## 已填模型卡摘要

| 字段 | 当前记录 |
|---|---|
| 用途 | 根据允许使用的产品资料生成工单分类、追问信息、建议回复和证据；只作人工处理前的辅助草稿 |
| 基座与接口 | `Base-7B-v1`、固定 chat template、greedy 解码、最大输出 256 token |
| 候选改动 | 比较基座提示、LoRA-SFT、LoRA-SFT + 偏好优化；尚未选出通过全部门槛的候选 |
| 开发评测 | LoRA-SFT 与偏好优化版本提高目标任务分数，但通用回归分别下降 4 和 5 个百分点，超过 2 个百分点的容忍线 |
| 冻结测试 | **尚未开启**。候选未通过开发门槛，此时查看测试结果只会污染最终证据 |
| 部署证据 | 只有 smoke test 峰值显存；正式训练、适配器、推理延迟、显存和加载记录缺失 |
| 发布与回滚 | **不得发布**。保留基座和固定提示作为回退起点，修复回归后重新走开发评测 |

模型卡不是只在成功上线时填写。这里的正确产物是一张结论为“不发布”的模型卡：它把失败门槛、未开启的测试和缺失的部署证据固定下来，防止团队把开发阶段结果包装成已完成项目。

## 本课验收

1. 为什么检索版本不能与模型训练版本混成一个变量？
2. 哪个里程碑负责证明“确实需要后训练”？
3. 目标任务变好、通用能力下降时怎样决定是否接受？
4. 项目结束时为什么还要保留基座和提示基线？

## 方法边界

课程只展示经过脱敏的教学设定和部分汇总记录，不提供完整数据包、训练产物或业务系统，也不要求学习者生成私有数据、运行训练或做上线操作。真实项目还需许可证、隐私、合规和组织责任审查。
