# 训练一个可用的小模型

> **学习导航**：承接任务约束和三个基线；本课用预生成记录把数据、基础模型、训练参数与评测连成一次实验；完成后应能指出从零训练教学模型与适配现成小基座的不同资源账。

## 先算最低限度的资源账

若一个模型有 5 亿个参数，只计算 FP16 权重存储：


$$
500{,}000{,}000\times 2\text{ bytes}=1{,}000{,}000{,}000\text{ bytes}\approx 1\text{ GB}
$$

乘法两项不能少：参数量回答“有多少个数”，每参数字节数回答“每个数怎样存”。漏掉后者，就会把同一个 5 亿参数模型的 FP32、FP16 与 4-bit 权重误算成相同大小。上式的 `GB` 是十进制单位；`1,000,000,000 bytes` 换成操作系统常见的二进制单位约为 `0.93 GiB`，不能把 `GB` 与 `GiB` 当成两种不同测量结果。

这还只是**纯权重**。全参数训练还需要梯度、优化器状态、激活、中间缓冲区和数据 batch；量化权重还可能带尺度、零点等元数据，实际峰值会高出许多。LoRA 能减少可训练参数和优化器状态，却不自动消除基础模型权重与激活。

因此选模型时必须实际记录峰值显存，而不能用“参数量乘字节数”冒充完整训练预算。

## 路线 A：从零训练小模型

从零训练适合学习完整机制，或验证一种特殊 tokenizer、语言或架构。流程是：

```text
定义语料边界 -> 训练 tokenizer -> 固定词表与特殊 token
-> 选择层数、隐藏维度、头数和上下文长度
-> 小 batch 过拟合 -> 冒烟训练 -> 正式训练
-> 验证 loss、任务评测和失败分析
```

必须承认它的能力上限来自数据、模型容量和计算预算。小语料上的顺畅样例不等于获得通用知识。本课程的 tiny-llm 属于这条教学路线。

## 路线 B：适配现成小基座

实际任务通常先从一个许可合适、语言覆盖足够、上下文长度满足需求的小型预训练模型开始。不要只按排行榜选择，还要核对 tokenizer、模型架构、许可证、显存、推理框架支持和任务基线。

课程正文假设有 1,000 条经许可和脱敏的样本，并将其固定为 800 条训练、100 条验证、100 条冻结测试。冻结测试集对开发过程隐藏。这里只呈现数据卡式摘要，不附原始数据；数字是教学设定，不代表所有任务需要相同规模，学习者也不接触或上传原始数据。

每条样本都应记录原始输入、目标 JSON、数据来源、质量状态和是否由教师生成。训练集可以用于更新参数，验证集用于选择配置，冻结测试集只用于最终比较。

## 一次只改变一个变量

第一轮保持基础模型、数据划分、seed、最大长度和评测脚本不变，只比较：

| 实验 | 改变项 | 要回答的问题 |
|---|---|---|
| B0 | 不训练 | 学生原始能力是多少？ |
| B1 | 人工标注数据做 LoRA | 小模型能否学会任务格式和类别？ |
| B2 | 增加教师蒸馏数据 | 教师信号是否补足了泛化能力？ |
| B3 | 在 B2 基础上量化 | 部署收益是否超过质量损失？ |

若同时换模型、换数据、换提示和换量化格式，即使指标提高，也无法判断是哪项修改产生了作用。

## 小模型训练记录的完成证据

课程正文用汇总记录演示最终报告；真实报告至少应同时给出任务质量、JSON 合法率、关键类别召回率、长输入表现、延迟、吞吐、峰值显存、模型文件大小和典型失败。学习者要判断这些证据是否支持结论。下一课学习教师信号怎样进入学生模型。
