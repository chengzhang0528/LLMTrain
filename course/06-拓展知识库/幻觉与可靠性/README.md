# 幻觉与可靠性

学习导航：承接 D07 的生成过程、D12 的评测和 D13 的应用系统；本路线通过预设问题、证据和输出，把“回答不可靠”拆成可定位、可测量、可缓解的失败类型。

## 先回答本质问题

幻觉不是随机采样造成的单点故障，也不能靠关闭 temperature 根治。语言模型通常学习预测下一个 token，而非查询完整、实时、已验证的事实库。训练数据缺失、上下文无证据或互相冲突，以及“像答案”比“承认不知道”更常见，都可能产生流畅但错误的内容。

固定模型和输入会产生一组 logits。greedy 取最高分；temperature、top-k、top-p 可引入随机选择。随机性只改变生成路径，不会创造事实核验能力；确定性的 greedy 也可能稳定地产生错误。

vLLM 等引擎负责模型前向、KV Cache、批处理和解码执行，不替应用决定策略。实现正确性、精度和配置会影响输出与性能；模型能表达什么、看到了什么、倾向怎样回答，主要来自权重、上下文和后训练。部署平台不是质量的单一来源。

## 一组现象，不是一个原因

| 可观察现象 | 可能发生的层 | 先做什么实验 |
|---|---|---|
| 编造不存在的人名、论文或链接 | 参数知识、训练数据、解码 | 要求给出处，再独立核验；比较 greedy 与多次采样 |
| 给了资料仍然答错 | 长上下文利用、检索排序、指令冲突 | 检查证据是否进入上下文，并做逐条引用对齐 |
| 同一问题每次答案不同 | 解码随机性、提示敏感性 | 固定模型、提示和解码超参数，用多个已记录 seed 或独立重复采样统计答案分布；复现单条路径时再固定一个 seed |
| 总是很自信，不愿说不知道 | 后训练偏好、校准、产品提示 | 增加不可回答样本，测拒答精确率与覆盖率 |
| 工具结果正确，最终总结却错 | Agent 工作流、结果解析、生成忠实度 | 分开保存工具输出与最终回答，逐步评分 |
| 基准分很高，上线仍失败 | 评测污染、场景漂移、指标代理 | 建独立时间切分和真实失败回归集 |

## 三组预设材料：各自解决一个问题

三组数字不共用同一题集：第 3 课的 20 道题只用于手算覆盖率与正确率；第 4 课的 100 道政策题用于比较 RAG、拒答和引用核验；第 5 课另用 60 道题组成最终项目案例，对照直接回答、提示约束、RAG、RAG 加核验与拒答四个版本。三组材料都覆盖可回答与不可回答问题，但只有第 5 课承担路线的项目汇总。

这些数字是预生成教学材料，没有附带可下载的独立数据集或完整逐题运行记录。学习者要在每组材料内部检查题目类型、证据边界、系统配置、汇总结果与结论能否互相对上，不能跨题集拼接指标。真实项目还应保存逐题结果；单独展示几个“看起来不错”的回答不算验收。

## 方法边界

- RAG 能提供当前证据，不能保证检索结果正确，也不能保证模型忠实使用证据。
- 校准能改善“置信程度与正确率是否匹配”，不能把未知事实自动变成已知。
- 拒答会减少冒险回答，也可能降低覆盖率；必须按失败代价选择阈值。
- 多次采样、搜索或验证能提高部分任务质量，却增加延迟，并可能让错误获得更多包装。
- 高风险医疗、法律、金融或控制任务不能把“模型自检”当作独立外部验证。
