# 质量、成本与延迟的对照账本

> **学习导航**：承接降智归因；本课任务是把质量、成本、延迟、回退和安全放进同一张运行账本；完成证据是能为真实任务选择满足 SLO 的运行点。

## 本课核心判断

**模型服务优化的是质量门槛下的成本、延迟与稳定性；没有统一账本，深思、路由、量化和多次采样无法公平比较。**

## 厂商真正优化的不是“最聪明”一个指标

一个可用模型服务要同时满足任务质量、响应速度、成本、并发稳定性和安全边界。把其中一项拉到最高，常会牺牲另一项：深思预算提高质量却增加等待；多次采样提高通过率却增加 token；路由到强模型提高质量却提高成本；量化降低成本却可能出现能力回归。

因此“思考强度”最终要放进一个运行点选择问题：

```text
任务风险与难度
  ↓
选择模型/路由/预算/工具
  ↓
测质量、TTFT、TPOT、尾延迟、token 成本和安全
  ↓
满足 SLO 的最低成本方案
```

## 先统一账本口径

| 指标 | 要回答的问题 | 常见误读 |
|---|---|---|
| 任务质量 | 答案、工具参数、引用或代码是否通过任务标准 | 一个漂亮样例代表整体 |
| 应用端 TTFT | 从应用收到请求到用户看到第一个 token 要多久 | 代表完整回答速度，或能与引擎侧 TTFT 直接比较 |
| 应用端 TPOT | 同一应用边界下，首 token 后相邻 token 平均间隔多长 | 包含了首 token 前的排队和 prefill |
| P95/P99 | 长尾用户会等多久 | 平均值已经足够 |
| 总 token 成本 | 输入、思考、工具和输出一共用了多少 | 只看可见输出 |
| goodput | 在质量、延迟和错误率约束下真正完成多少有效工作 | 总 tokens/s 越大就一定越好 |
| 回退率 | 有多少请求没有按首选模型完成 | 回退不影响质量 |

## 预生成运行点对照

材料固定 100 个请求、同一质量评测集和同一硬件；所有数字为教学示例：

| 运行点 | 模型/预算 | 质量通过率 | 平均成本 | P95 TTFT | P95 完整回答 | 回退率 |
|---|---|---:|---:|---:|---:|---:|
| A | 强模型 + 深思 | 92% | 1.00 | 1.8 s | 12.0 s | 0% |
| B | 路由 + 边界题深思 | 90% | 0.57 | 0.9 s | 7.1 s | 4% |
| C | 快模型 + 短预算 | 82% | 0.31 | 0.4 s | 3.0 s | 0% |
| D | 快模型 + 5 次候选核验 | 89% | 0.76 | 1.2 s | 9.4 s | 2% |

没有“永远最佳”的行。医疗问答可能优先 A 或 B 的质量，实时聊天可能接受 C，代码修复可能选择 D；真正上线前还要加入安全、工具成功率和人工复核代价。

## 从账本反推控制项

| 症状 | 优先调整 | 必须同时守住 |
|---|---|---|
| 质量够但太慢 | 降低简单题 effort、路由、前缀缓存、推测解码 | 难题回归集、P95 和工具成功率 |
| 速度够但错误多 | 只对高风险题提高预算，加入检索/验证器 | 成本上限和拒答覆盖率 |
| 成本超标 | 强弱模型路由、候选数量、上下文整理 | 长尾质量与回退率 |
| 量化后便宜但错得多 | 更换校准、QAT 或精度/kernel | 独立任务集和端到端延迟 |
| 平均值很好，用户仍抱怨 | 分任务和分并发报告 P95/P99 | 尾部用户、超时和错误率 |

## 为什么“降智”讨论常和价格、速度一起出现

用户体感是一个复合结果：可见思考变少、首 token 变快、回答变短，可能来自低 effort，也可能来自路由到快模型或输出上限变小；若同时发生质量下降，才需要继续查版本、上下文、部署精度和后训练。没有同题、同配置和同版本的对照，不能把体验变化归因给单个旋钮。

## 这张表怎样用于学习

课程只提供冻结的请求、配置和结果。学习者的任务是：

1. 找到每个运行点改变的**一个或多个控制层**；
2. 检查质量和性能的分母、统计窗口与题集是否一致；
3. 找出“质量提高但不值得”“速度提高但不可用”“成本降低却发生回退”的行；
4. 为下一轮选择一个有明确回滚条件的运行点。

## 方法边界

- 教学账本的相对指数不是厂商报价，也不能代替目标负载上的实测。
- 平均值不能代表长尾体验；质量和安全约束必须与性能指标同时满足。
- 不同题集、版本、上下文和 token 口径不能直接横向比较。

## 本课验收

能用一张账本解释为什么“更强模型”“更多思考”“更快服务”不能互相替代，并写出一个面向真实问题的选择理由。
