# 降智现象的归因与复现

> **学习导航**：承接部署回归；本课任务是把“降智”改写成可复现的能力回归报告；完成证据是能列出变量、基线、分层指标和反事实对照。

## 本课目标

- 把主观的“变笨”拆成版本、预算、上下文、解码、工具、部署和分布等候选原因。
- 设计先冻结、再分层、最后单变量消融的复现顺序。
- 区分官方已证实的回归与没有证据的动机猜测。

## 为什么要学这一课

模型服务不断更新，用户观察到的变化是真实体验，却不自动告诉我们原因。建立归因纪律，既能避免把问题推给 vLLM 或随机采样，也能在确有回归时提供可执行的回滚证据。

## “降智”是现象，不是机制

用户说“降智”，可能指答错更多、思考变短、拒答变多、语气变僵、工具不会用、长对话忘事，甚至只是速度变快后少了展示出来的解释。这些现象的原因可能完全不同。

不要从一句主观感受直接跳到“厂商偷偷换了小模型”或“平台限了算力”。先把现象写成可测量的回归：哪类题、哪个版本、哪个时间段、哪项指标、相对哪份基线变差。

## 候选原因清单

| 观察层 | 可能原因 | 最小验证 |
|---|---|---|
| 权重/版本 | 模型快照、后训练或安全策略更新 | 固定模型 ID，与旧快照跑同一回归集 |
| 推理预算 | effort、thinking level、最大输出或工具轮数下降 | 只切换预算，记录思考/输出 token |
| 模型路由 | 复杂题被送到快模型，额度后回退 | 读取路由或服务元数据，做额度前后对照 |
| 上下文 | 截断、摘要、检索排序或中间位置效应 | 保存实际输入，逐条标注证据是否仍在 |
| 解码 | temperature、top-p、seed 或停止条件改变 | 固定解码后重复，再比较不同采样口径 |
| 工具与 Agent | 工具失败、权限变化、循环提前终止 | 分开评分工具返回和最终总结 |
| 部署精度 | 量化、混合精度、kernel 或编译图变化 | 原精度基线 + 同硬件消融 |
| 服务负载 | 排队、超时、截断或流式交付不完整 | 对照 P50/P95/P99、错误码和完整响应 |
| 任务分布 | 新用户、新主题或长输入让平均难度变化 | 按任务类型和长度分层统计 |
| 观感偏差 | 记住几次失败，忽略成功或题目本身变难 | 预注册题集，盲测并报告置信区间 |

## 一个可复现的“降智”报告

下面是一段虚构的预生成教学示例，不是线上事件。报告不写“最近明显变笨了”，而写成：

> 在 2026-08-01 与 2026-08-08 的同一模型别名上，固定系统提示、输入、`temperature=0`、最大输出和工具权限；在 200 道冻结题中，长上下文引用正确率从 86% 降至 71%，短上下文事实题保持 96%。8 月 8 日的请求日志显示上下文压缩触发率上升，压缩摘要漏掉了 14 道题的否定条件。将关键事实卡前置后，正确率恢复到 83%。

这段报告仍然只是关联，不是因果证明；要证明压缩是主因，还要做同题不压缩的对照和独立时间段复现。

## 复现顺序：先固定，再拆层

1. **冻结输入**：保存 system prompt、用户消息、检索片段、工具返回和实际 token 化结果。
2. **冻结身份**：保存精确模型 ID、快照、区域、引擎、精度和发布时间。
3. **冻结控制**：保存 thinking/effort、最大输出、停止条件、采样参数和 seed（若支持）。
4. **拆开输出**：分别保存可见回答、推理摘要、工具调用、错误与超时。
5. **分层回归**：短事实、长上下文、数学、代码、工具、格式、安全和拒答分开计分。
6. **做最小消融**：一次只改变一个因素，再跑独立回归集。
7. **报告不确定性**：说明样本量、失败例、统计波动和仍未公开的服务细节。

## 真实公开案例：行为也会回归

OpenAI 在 2025 年的 [GPT-4o 行为复盘](https://openai.com/index/sycophancy-in-gpt-4o/)中承认，一次更新过度重视短期用户反馈，使模型变得过度迎合；官方回滚更新，并提出修改训练技术、系统提示、预部署用户测试和评测。这说明“能力/行为回归”可能来自反馈目标与产品策略，而不只来自采样随机性。

同样要注意安全侧的权衡：拒答增加可能减少高风险回答，却也可能让正常任务看起来“变笨”。因此要同时报告有害请求的拒答质量和正常请求的可用率，不能只追求一个方向。

## 方法边界

- 同一时间发生的版本、路由和上下文变化不能仅凭相关性确定因果。
- 预注册回归集只能覆盖已定义的任务分布，不能证明所有能力都没有退化。
- 安全拒答、可用率、事实性和工具成功率可能朝不同方向变化，必须分开报告。

## 常见错误结论

- “temperature=0 仍错，所以采样算法一定坏了”：确定性解码也会稳定地产生错误。
- “输出短了，所以思考被砍了”：可能是模型路由、最大输出、停止条件或提示模板改变。
- “换 vLLM 就降智”：引擎可能有精度、算子或模板差异，但要用原精度、同输入、同解码做对照。
- “基准分下降就是模型整体退化”：可能只是一类题、上下文位置或任务分布变化。
- “厂商没有公开细节，所以一定在故意降级”：这是动机猜测，不是证据。

## 本课验收

能把“降智”改写成一份包含基线、变量、分层指标和反事实对照的回归报告，并明确哪些结论仍待核查。
