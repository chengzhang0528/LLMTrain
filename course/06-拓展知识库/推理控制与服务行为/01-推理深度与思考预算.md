# 推理深度与思考预算

> **学习导航**：承接模型运行、解码和 Token 速度；本课任务是把“思考强度”拆成可观察的运行时控制；完成证据是能区分推理预算、采样参数和静态权重。

## 本课目标

- 解释 `reasoning effort`、`thinking level` 和 `thinking budget` 的区别。
- 根据厂商文档判断哪些值是模型相关的，哪些结论不能横向推广。
- 用一张预生成账单说明额外思考 token 如何影响质量、成本和延迟。

## 为什么要学这一课

用户常把“回答更长”“显示了思维链”“temperature 更低”都叫作更深思考。若不先分清控制层，就会把平台速度、模型能力和随机性混成一个原因，也无法解释同一模型为什么在不同产品里表现不同。

## 先回答：能控制“思考多久”吗？

可以控制一部分预算，但它不是人脑式的计时器，也不是把权重临时改大。对支持 reasoning 或 thinking 的模型，服务可能允许模型在最终回答前生成内部推理 token，也可能只提供计算量或档位上限；模型会在这段预算内规划、分解、检查，再生成回答。不同接口未必暴露同一种内部状态。

因此要分开四件事：

| 名称 | 实际含义 | 不应误解为 |
|---|---|---|
| reasoning | 为得到结论而组合条件、执行中间步骤或验证结果的能力/过程 | 只要输出一长段文字就一定正确 |
| inference | 用已训练参数做前向计算并解码的运行阶段 | 推理能力本身 |
| reasoning effort / thinking level | 厂商给模型的思考强度提示或档位 | 行业统一的“智商旋钮” |
| thinking budget | 允许内部思考使用的 token 或计算量上限 | 训练参数数量或事实知识量 |

## 厂商公开了哪些控制项

下面只记录官方页面明确写出的内容。允许值、默认值和参数名随模型与接口变化，不能横向硬套。

| 厂商页面 | 公开控制 | 页面明确的边界 |
|---|---|---|
| OpenAI | `reasoning.effort` 可包含 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` 的一部分 | 支持值和默认值由模型决定；较低值偏向速度与少用 token，较高值允许更完整思考；原始 reasoning token 不直接公开 |
| Anthropic | `effort` 控制响应使用的 token 数；支持 adaptive thinking 时推荐用它控制深度 | 它会影响回答、工具参数和 thinking 的 token 花费，不只是隐藏思考；`high` 可能就是默认行为 |
| Gemini | 默认按请求复杂度动态调整思考量，可用 `thinking_level` 控制 | 不同 Gemini 模型支持的等级不同；思考摘要不等于完整内部状态 |
| DeepSeek | thinking mode 开关与 `reasoning_effort`/兼容格式的 effort 控制 | 官方明确提示思考模式下某些 `temperature`、`top_p` 等采样参数可能无效；不能把思考模式简化为调高 temperature |
| Qwen3 | `enable_thinking`，以及消息中的 `/think`、`/no_think` 按轮切换 | 思考版与非思考版、不同模型卡的模板和限制不同；路由或框架若丢失 reasoning 内容，工具循环质量可能受影响 |

官方入口：[OpenAI reasoning guide](https://platform.openai.com/docs/guides/reasoning)、[Anthropic effort](https://docs.anthropic.com/en/docs/build-with-claude/effort)、[Anthropic thinking](https://docs.anthropic.com/en/docs/build-with-claude/thinking)、[Gemini thinking](https://ai.google.dev/gemini-api/docs/thinking)、[DeepSeek thinking mode](https://api-docs.deepseek.com/guides/thinking_mode)、[Qwen3 官方仓库](https://github.com/QwenLM/Qwen3)。

## 这个旋钮实际改变什么

把一次回答画成一张账单更容易理解：

```text
请求进入
  ├─ 输入 token：提示、历史、工具结果
  ├─ 思考 token：规划、尝试、检查（有的接口只给摘要）
  ├─ 工具/搜索循环：调用、观察、再规划
  └─ 可见输出 token：最终回答
```

调高 effort 可能让模型在第二项花更多 token，也可能让它多做一次工具调用、输出更完整的参数，或者延长等待。调低 effort 则可能更早停止思考、少走工具循环或直接给出短答案。**实际改变的是运行时的预算和路径，不是静态权重中的知识。**

`temperature`、`top-k`、`top-p` 属于解码选择；它们改变每一步候选的概率分布。思考预算属于“要不要多算几步”，两者都可能影响输出，却不是同一个控制层。

## 为什么思考更久不保证正确

预算只给了更多尝试机会，不能自动提供真值。模型可能：

- 在错误前提上推理得更久；
- 重复同一种错误路径；
- 被有漏洞的 verifier 评分；
- 让更长的上下文挤掉真正重要的证据；
- 在工具结果错误时生成更自信的总结。

所以应同时报告质量、事实性、工具成功率、推理 token、TTFT、TPOT 和成本。不能把“思考摘要更长”当作“模型内部更正确”的证据；Google 文档还明确说明，思考步骤可能只有签名而没有文本摘要。

## 预生成对照：同一任务的三档预算

这是教学记录，不是某家模型的 benchmark。模型版本、提示和输入固定，只改变服务暴露的预算档位：

| 档位 | 内部思考 token | 最终答案 | 质量观察 | 代价观察 |
|---|---:|---|---|---|
| 快速 | 约 80 | 先给结论，再补一句理由 | 简单事实题不变；多约束题漏掉一个条件 | 首 token 较快，成本较低 |
| 平衡 | 约 260 | 分解条件后给结论 | 多约束题漏项减少 | 等待和 token 增加 |
| 深入 | 约 720 | 增加检查或工具步骤 | 只有在任务确实需要搜索/验证时才稳定提高 | 可能出现更长等待，收益不是线性的 |

读表时不要问“深档是不是更聪明”，而要问：收益出现在哪类题？额外 token 用在了哪一步？是否用独立题集复现？

## 方法边界

- 思考预算不是模型参数量，也不会补齐训练数据中不存在的事实。
- 同名 effort/level 只在对应模型和接口的文档范围内有效，不能直接跨厂商比较。
- 思考摘要不是内部状态的逐字记录，摘要变长也不是正确性的证明。

## 本课验收

- 一个厂商的 `high` 不等于另一个厂商的 `high`。
- “思考模式开关”可能是同一权重的运行时路径，也可能对应不同模型版本；必须看模型卡和请求记录。
- 推理摘要是可读说明，不是可当作模型真实内部过程的逐字录像。
- 思考预算必须和最大输出、工具轮数、上下文窗口一起看；只提高其中一个可能只是把等待推迟到别处。

本课验收：看到“请深度思考”时，能指出它可能改变的预算、不会改变的权重，以及还需要哪些记录才能证明质量真的提升。
