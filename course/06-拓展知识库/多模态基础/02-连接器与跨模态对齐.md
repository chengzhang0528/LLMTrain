# 连接器与跨模态对齐

> **学习导航**：承接模态张量；本课追踪视觉或音频特征怎样进入语言主干；完成后应能区分形状兼容和语义对齐。

## 本课目标

用具体形状解释线性投影、重采样器或 cross-attention 连接器的输入输出，并说明训练信号怎样建立跨模态对应。

## 为什么要学这一课

很多介绍只画一根“视觉编码器 -> LLM”箭头，容易让人误以为矩阵宽度一致就已经理解图片。连接器解决的是接口和信息汇聚，语义对应还需要配对数据、训练目标和任务反馈。

## 形状小例子

视觉编码器输出 `(B, 196, 768)`，语言主干隐藏宽度为 1024。一个线性投影可以把每个视觉位置从 768 维映射到 1024 维，得到 `(B, 196, 1024)`。

这里改变的是特征宽度，没有自动减少 196 个视觉位置。若使用重采样器把 196 个位置汇聚成 32 个视觉 token，输出才可能变成 `(B, 32, 1024)`。宽度投影与 token 数压缩是两件事。

## 三类常见连接

| 连接方式 | 做什么 | 主要取舍 |
|---|---|---|
| 线性或 MLP 投影 | 对齐隐藏宽度 | 简单，但保留全部视觉位置 |
| 重采样器 | 用固定查询汇聚视觉特征 | 控制 token 数，可能丢细节 |
| cross-attention | 语言位置按需读取视觉特征 | 交互灵活，结构和计算更复杂 |

## 语义怎样对齐

图文配对、描述生成、问答、对比学习、定位和指令数据分别提供不同信号。只训练图片标题，模型可能学会总体描述，却仍不擅长 OCR、计数或坐标定位。

## 预设案例观察

下面是一条冻结的教学结构记录：

| 阶段 | 输出形状 | 本轮是否训练 | 证据 |
|---|---|---:|---|
| 视觉编码器 | `(B, 196, 768)` | 否 | 参数状态为 frozen |
| MLP 连接器 | `(B, 196, 1024)` | 是 | 768 维被投影到 1024 维 |
| 语言主干 | `(B, T + 196, 1024)` | 否 | 文本与视觉位置进入同一隐藏宽度 |
| 输出头 | `(B, T + 196, V)` | 否 | 为每个位置产生词表 logits |

前一阶段的通用图文连接训练使用 20 万组“图片 + 整体描述”，没有区域框、OCR 转写或计数标注。这批数据只能直接监督总体描述；是否改善必须用独立开发集评测，也不能据此宣称模型已经学会精确定位、读小字或稳定计数。形状接通是接口证据，任务能力要看对应数据与评测。

## 本课验收

1. `(196, 768) -> (196, 1024)` 改变了哪条轴？
2. 重采样到 32 个 token 得到了什么收益和风险？
3. 为什么图文标题数据不能证明模型会精确定位？
4. 连接器参数少为什么仍可能决定多模态接口质量？

## 方法边界

低维可视化或相似度只能提供局部证据，不能完整证明高维语义对齐。最终结论必须回到分层任务评测。
