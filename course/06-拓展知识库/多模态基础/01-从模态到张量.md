# 从模态到张量

> **学习导航**：承接 D02 的文本表示；本课比较文本、图像、语音和视频怎样变成模型可计算的张量；完成后应能给每条轴命名。

## 本课目标

画出四种模态从原始输入到 token 或连续特征的转换，并区分采样、切块、编码和位置/时间信息。

## 本课核心判断

**图片、音频和视频必须先变成带采样结构的张量或 token；分辨率、采样率与帧数会共同改变信息损失和成本。**

## 四种输入

| 模态 | 原始对象 | 常见表示 | 关键轴 |
|---|---|---|---|
| 文本 | 字符串 | token ID、Embedding | batch、token、hidden |
| 图像 | 高宽与颜色通道 | patch、视觉特征或离散视觉码 | batch、patch、vision hidden |
| 语音 | 随时间变化的波形 | 声学帧、编码器特征或音频 token | batch、time、audio hidden |
| 视频 | 连续图像与声音 | 帧 patch、时序特征、音频特征 | batch、frame、patch、hidden |

## 图像 patch 小例子

一张 `224 x 224` 图像使用 `16 x 16` patch，不考虑额外 token 时，每边有 `224 / 16 = 14` 个 patch，共 `14 x 14 = 196` 个视觉位置。若视觉编码器输出宽度为 768，单张图可表示为 `(1, 196, 768)`。

在 patch 尺寸和裁剪策略不变时，提高输入分辨率会增加 patch 数，进而增加后续注意力和缓存成本；它不只是“图片更清楚”这么简单。若模型会缩放、动态切块或限制视觉 token，实际数量要按预处理器配置计算。

## 离散与连续表示

文本常用离散 ID 查 Embedding；图像和语音常先经编码器得到连续向量，也可以用离散码本。是否使用统一 token 取决于具体架构，不能把文本词表当成所有模态共享的万能词表。

## 预设案例观察

下面是两份教学用参数卡。先遮住“可推出的结果”自行计算，再核对答案：

| 输入 | 已知配置 | 可推出的结果 | 还不能确定什么 |
|---|---|---|---|
| 图像 | `224 x 224`，patch 为 `16 x 16`，视觉宽度 768 | 每边 14 个 patch，共 196 个位置；张量为 `(1, 196, 768)` | 是否另加 CLS token，要查视觉编码器配置 |
| 5 秒音频 | 采样率 16 kHz，编码器总步幅 320 个采样点，音频宽度 512 | 原始波形有 80,000 个采样点；编码后约 250 个位置，张量约为 `(1, 250, 512)` | 边缘填充和精确长度公式，要查特征提取器配置 |

图像的 196 和音频的 250 都是“位置数”，768 和 512 才是“每个位置的特征宽度”。音频结果使用本卡给定的步幅，不代表所有音频模型都采用相同设置。

## 本课验收

1. `224 x 224` 图像按 `16 x 16` 切块为什么得到 196 个 patch？
2. 图像维度能与语言模型相接，为什么仍不代表语义已经对齐？
3. 语音的时间轴与文本 token 轴有什么共同点和差异？
4. 提高视频帧率会增加哪些计算负担？
