# 从公开榜单到本地验收

<!-- benchmark-snapshot: 2026-08-12 -->

> **学习导航**：把上一页的候选写进验收卡，只用冻结测试集作发布决定。

## 本课目标

能为一个模型记录版本、配置、质量区间、成本、安全红线和回滚条件。

## 为什么要学这一课

公开榜单没有你的数据、工具和失败代价，发布前必须完成一次本地复核。

## 本课验收

1. 写出一张最小验收卡并区分开发集与冻结集。
2. 解释零事件为什么仍需要报告风险上界。

## 方法边界

- 区间只描述抽样不确定性，不修复数据偏差。
- 成对检验需要同一批适用样本和预先固定的规则。
- 性能和安全红线必须按业务批准，不能由榜单替定。

榜单做候选发现，本地验收做发布决定。不要把公开榜单分数抄成“本项目准确率”。

## 一页验收卡

| 字段 | 必填内容 |
|---|---|
| 模型身份 | 权重/API 名、完整版本或 commit、提示模板、推理预算、工具、精度/量化 |
| 数据 | 开发评测集、冻结测试集、语言/长度/风险切片、样本数、去污染说明 |
| 质量 | 任务主指标、失败切片、回答级引用支持；检索记录 Recall@k / Hit@k |
| 成本 | 输入/输出价格、token、并发、首 token 延迟、总延迟、吞吐和显存 |
| 安全 | 安全概率抽样集、人工红队集、拒答/升级规则和回归门槛 |
| 决策 | 通过/淘汰、原因、回滚版本、下一次复核日期 |

## 数字怎么写才不误导

- 二项通过率可报告 **95% Wilson 区间**；它是有限样本估计的不确定性，不是“真值有 95% 概率在区间内”。
- 选型阶段的 **选择阶段的描述性区间** 用于展示波动，不应冒充预注册的确认性结论。
- 成对样本比较 A/B 时记录“仅 A 对、仅 B 对”，需要时使用 **精确 McNemar 检验**；不同题集的两个平均数不能直接宣布胜负。
- 对安全事件这种“希望没有发生”的比例，可报告 **单侧 95% Clopper-Pearson 上界**；例如零事件不等于零风险。
- 多指标同时过线才算通过时，把它写成 **联合 SLO**；不要用一个平均分掩盖某项硬约束失败。

## 教学材料与真实项目

**教学数据声明**：本页只给记录格式和预生成示例，不声称课程已经替你运行了模型；现实结论必须替换成你的版本、数据和日志。

推荐的可复核记录：固定一个冻结教学配置账本，写明每轮顺序种子；性能测量按“每轮先预热 200 个请求，再记录 2,000 个正式请求”执行，避免把冷启动混进正式结果。通用能力可用 **300 条通用测试** 做回归，但不能因此省略业务冻结集。

## 最小发布门槛

1. 版本、模板、工具、预算和精度全部可复现。
2. 质量主指标、失败切片和回答级引用支持同时达标。
3. 联合 SLO 中的成本/延迟/显存和安全红线全部达标；安全事件上界不高于 1.0% 只是一个示例门槛，必须由业务风险负责人批准。
4. 冻结测试集只用于最终确认，不反复调参；失败时保留日志并回滚到已知版本。

## 不能从榜单推出的结论

| 看到什么 | 不能直接写成 |
|---|---|
| Arena 偏好第一 | 医疗、法律或事实任务最可靠 |
| LiveBench 总分高 | 你的长文档 RAG 一定召回好 |
| SWE-bench 高 | 所有代码库、所有工具链都能修 |
| 开放权重标签 | 开源、无限制、可商用、普通显卡可跑 |
| 95% 区间重叠/不重叠 | 自动证明业务上有/没有实际差异 |
