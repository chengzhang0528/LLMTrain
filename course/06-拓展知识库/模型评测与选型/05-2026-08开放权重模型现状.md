# 2026-08 开放权重模型现状

> **学习导航**：承接按场景建候选池；本课读取截至 2026-08-12 的官方模型卡，形成现实候选地图；完成后应能区分官方发布事实、作者实验和仍需本地验证的课程建议。

## 本课目标

- 认识当前仍值得进入候选池的开放权重模型版本。
- 区分 Apache-2.0、MIT 与模型专用许可证。
- 用总参数、激活参数、上下文、模态和部署条件做初筛而不越界下结论。

## 为什么要学这一课

只讲评测方法而不面对真实模型，学习者仍会在发布页前失去判断力；只抄一张“最新排行榜”，教材又会迅速过期。本页因此只保存可追溯的版本事实和候选理由，不复制厂商整张分数表，也不宣布综合冠军。

## 快照说明

- **核查日期**：2026-08-12。
- **模型范围**：可取得权重且仍具有现实生态或能力价值的代表版本，不是完整目录。
- **证据来源**：对应 Hugging Face 官方组织模型卡与许可证元数据。
- **证据 revision**：正文模型卡链接固定到核查时的 40 位 commit SHA；SHA 标识证据页面版本，不是权重文件哈希。
- **“值得考虑”含义**：可以进入相关场景候选池；最终必须按同一配置做本地验收。
- **未采用依据**：下载量只反映生态活跃线索，未用于质量排序。

## 怎样读这些官方事实

### 总参数、激活参数与内存不是同一个数

总参数影响完整权重存储和分布；激活参数描述稀疏模型每 token 路径的某种规模口径；权重内存还取决于位宽、量化元数据和是否分片；运行时还要加入激活、KV Cache、工作区和框架开销。不要把 `35B-A3B`、`119B/6.5B active` 或 `E4B` 写成可直接比较的“真实大小”。

### 上下文上限不是可靠长度

模型卡的 128K、256K 或 1M 表示接口/配置支持范围。真实项目仍要按长度、证据位置、干扰项、输出预算和并发分桶；长输入还会增加 prefill、KV Cache 和成本。

### 托管版与权重版可能不是同一系统

托管服务可能加入路由、系统提示、工具、上下文压缩和安全策略。开放权重本地运行则由你的模板、引擎和量化决定。两者名称相近也要分别建实验 ID。

### 作者分数为什么没有抄进本页

作者表格中的“领先”是发布方主张。不同模型可能使用不同 prompt、采样、输出长度、工具和 harness；复制分数而省略这些条件，会制造虚假可比性。需要使用时，应回到模型卡的具体脚注，把该条结果作为 C 级作者实验记录，再找独立复测或本地数据。

## 按现实约束建立短名单

| 约束起点 | 可优先核验的候选，不代表最终推荐 |
|---|---|
| 独立 GPU 显存 12–24 GB、文本/图文 | Ministral 3 8B 的官方 FP8 路线可先核验；Qwen3.5 4B/9B、Gemma 4 小型必须进一步固定低精度格式、引擎、上下文与 KV Cache |
| 官方只写约 16 GB `memory`，内存类型尚未落到目标机器 | gpt-oss-20b 的 MXFP4 路线可进入兼容性核验；先确认实际使用系统内存、独立显存还是统一内存，再谈能否部署 |
| 中文与代码、可用多卡 | Qwen3.5 27B/35B-A3B、DeepSeek V4 Flash、GLM-4.7-Flash |
| 大型图文与 Agent 服务 | Mistral Small 4、Qwen3.5 大型变体、GLM-5.2、DeepSeek V4 Flash |
| 超长/超大研究或集群 | Kimi K3、GLM-5.2、Qwen3.5 122B-A10B |
| Llama 生态兼容 | Llama 4 Scout 作为兼容基线，同时审查专用许可证与版本差距 |

这张表只安排核验顺序。若任务是 ASR、Embedding、Reranker、OCR 或安全分类，下一课的专用组件通常比继续换通用生成模型更相关。

系统内存、独立显存和统一内存不能只写成一个“多少 GB”。同样是 16 GB，数据搬运、可用带宽、运行引擎和能否同时容纳权重、KV Cache 与工作区都可能不同；模型卡只写 `memory` 时，课程只能保留原口径，不能擅自改写成 `VRAM`。

## 按维度看证据置信度

这里的“置信度”指课程对公开证据能支持多强结论的判断，不是模型自己输出的置信分数。

| 维度 | 当前较有把握的事实或候选 | 证据置信度与原因 |
|---|---|---|
| 权重与许可证入口 | 上表具体仓库；Apache/MIT/专用许可证分别记录 | 高：官方仓库和许可证可直接核对；目标用途是否合规仍需责任人审查 |
| 特定低精度能否装入较小内存 | gpt-oss-20b 的官方 MXFP4 16 GB 口径；Ministral 3 8B 的官方 FP8 12 GB VRAM 口径 | 中高：配置明确的官方工程事实；换量化、上下文、并发或引擎后结论失效 |
| 是否提供图像/音频/视频输入接口 | Qwen3.5、Gemma 4、Mistral 系列、Kimi K3 的对应官方模型卡 | 高到中高：能确认接口与变体；不能由此推出 OCR、音频或视频质量 |
| 中文通用、代码或数学谁更强 | Qwen、GLM、DeepSeek、Kimi、Mistral 等作者实验与第三方榜单 | 中到低：题集相关，prompt、预算和污染会改变结果；必须本地成对复测 |
| Agent 与仓库修复谁领先 | DeepSeek V4 Flash、GLM-5.2、Kimi K3 等作者表格 | 低到中：harness、工具、仓库、输出和时间预算差异很大，模型与系统难以剥离 |
| 128K/256K/1M 是否“真正可用” | 各模型卡能确认配置上限 | 接口上限为高置信事实；任意位置可靠检索、推理和成本是低置信外推，必须分桶验收 |
| 托管服务是否等同开放权重本地版 | 没有通用等同关系 | 低：服务可能有路由、工具和系统策略；只有同版本、同配置实测才能建立对应 |

因此可以高置信地说“某许可证文件存在”“某具体格式在官方条件下声称可装入某内存”，却不能高置信地说“某家族在所有中文 Agent 场景最好”。证据越接近接口事实越稳定，越接近跨场景质量冠军越需要独立、本地和配对证据。

## 本课验收

1. 为什么 Qwen3.5-35B-A3B 的 A3B 不能直接等同于显存或准确 FLOPs？
2. gpt-oss-20b 的“16 GB 内存运行”为什么不是你的并发服务已经达标？
3. Kimi K3 为什么属于开放权重候选，却不能直接归入 Apache/MIT 一类？
4. 官方模型卡中的 Agent 分数为什么必须连同 harness 和输出预算一起读？

## 方法边界

- 本页只在 2026-08-12 对列出的官方页面负责；后来修改的模型卡需重新审计。
- 未列出的模型不等于不可用；本页也不保证列出的模型一定适合任何项目。
- 官方规格是版本事实或作者主张，不是独立性能复现。
- 许可证名称不能替代完整条款、依赖许可和目标用途审查。
