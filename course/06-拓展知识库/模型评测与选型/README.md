# 模型评测与选型

这条路线解决一个现实问题：模型发布后总会伴随排行榜、厂商表格、社区投票和“最强”结论，学习者怎样把这些材料变成不会误导项目的选择证据？本专题不再介绍“评测很重要”这种常识，而是要求你拆开指标口径、证据强弱、运行配置、许可证、系统组件和场景失败代价。

> **现实模型快照日期：2026-08-12。** 方法课长期有效；现实模型页是有日期的候选池，不是永久榜单。模型、权重、模型卡或许可证变化后，应重新核对官方页面。

## 先记住结论

模型选择的比较单位不是一个家族名，而是：

```text
具体权重版本 + 提示模板 + 推理/采样配置 + 工具与 harness + 精度/量化 + 预算 + 硬件/服务版本
```

公开分数只能帮助缩小候选池。最终选择必须回到本项目的开发评测集、冻结测试集、成本与安全红线。课程说“值得考虑”，只表示证据足够进入候选池，不表示它在所有任务上胜出。

## 本路线的证据标签

| 标签 | 表示什么 | 不能被写成什么 |
|---|---|---|
| 官方事实 | 官方模型卡、仓库或许可证明确记录的版本、接口和发布信息 | 独立证明过的质量结论 |
| 作者实验 | 发布方在指定数据、提示、预算和 harness 下报告的结果 | 所有真实场景的稳定排名 |
| 第三方结果 | 与发布方分离的复测或盲测 | 自动适配你的业务分布 |
| 教学示例 | 为练习选择和审计而预生成的记录 | 现实模型的公开 benchmark 分数 |
| 课程建议 | 根据约束把模型放入或移出候选池 | 不附条件的“最好模型” |

## 路线产物

完成本路线后，应能交出一页模型选择记录：任务合同、候选版本、许可证、公开证据、证据置信等级、本地开发集结果、冻结测试结果、质量/成本/安全门槛、回滚条件和下一次复核日期。学习者只审阅课程提供的预生成材料，不要求安装模型、购买算力或运行训练。

## 更新规则

- 快照只收录能指向官方模型卡或许可证的具体版本，不根据宣传海报补全未知训练细节。
- 下载量、点赞、参数量和上下文上限可以说明生态或接口线索，不能单独当作质量分数。
- 开放权重不自动等于开放源代码、开放训练数据、无使用限制或适合商业部署。
- 量化衍生版、托管服务版和原始权重版分别验收；它们不能自动继承同一组分数。
- 新版本进入候选池时保留旧版本的比较条件和复核日期，不覆盖历史决策记录。
