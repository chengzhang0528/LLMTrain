# 先定义模型选择合同

> **学习导航**：承接 D12 的模型评测和实际模型案例的问题合同；本课先冻结“选来做什么、不能失败什么、资源上限是什么”；完成后应能拒绝一个只有模型名和总分、没有比较条件的选型请求。

## 本课目标

- 把模型选择写成任务、风险、系统和许可共同组成的合同。
- 区分模型家族、具体权重、托管服务和量化衍生版。
- 为公开榜单规定它只能承担的筛选职责。

## 为什么要学这一课

“中文最强”“代码第一”“能跑 1M 上下文”都不是完整需求。同一权重在不同聊天模板、思考预算、工具循环、精度和硬件下，会得到不同质量、延迟与成本；同一家族的 API 服务也可能加入路由、检索或未公开的系统策略。若比较对象没有冻结，后面的数字再精确也无法支持决策。

## 选择合同的七个字段

| 字段 | 必须写清 | 不合格写法 |
|---|---|---|
| 用户任务 | 谁在什么输入上完成什么输出 | “做一个智能助手” |
| 失败代价 | 哪类错最危险，能否拒答或转人工 | “准确率越高越好” |
| 输入分布 | 语言、长度、模态、噪声和敏感数据 | “支持长文本” |
| 系统边界 | 是否有检索、工具、代码执行和人工复核 | “测 Agent 能力” |
| 资源预算 | 显存/内存、并发、p95 延迟、成本上限 | “尽量便宜” |
| 合规边界 | 权重许可、数据流向、商用和再分发要求 | “是开源模型就行” |
| 验收规则 | 开发集、冻结测试集、门槛和回滚条件 | “在排行榜靠前” |

先写硬约束，再比较软偏好。模型违反数据不得出域、许可证或安全红线时，即使公开平均分最高，也应直接退出候选池。

## 比较对象必须冻结到版本

把一次候选记录写成下面的元组：

```text
候选 = 权重仓库与 revision
     + tokenizer / chat template
     + 推理模式与采样参数
     + 上下文和最大输出预算
     + 工具 schema / Agent harness
     + 精度、量化格式与推理引擎版本
     + 硬件、并发与测量边界
```

只要其中一项改变，就应视为新的运行配置。模型家族名适合查找候选，不适合充当实验 ID。

## 开放权重不是一个万能许可标签

开放权重模型表示公众能够在许可条件下取得模型权重。它不自动说明以下事项：

- 训练代码、训练数据和完整配方是否公开；
- 许可证是否允许商业使用、再分发或特定用途；
- 衍生量化是否获得原作者认可；
- 本地部署是否现实，或托管版是否使用完全相同的系统；
- 模型输出、输入数据和依赖组件是否满足项目合规要求。

因此选型表应分别记录“权重可取得”“许可证名称”“目标用途已由责任人审查”，而不是用一个“开源：是/否”列替代法律和工程判断。

## 公开评测在合同中的位置

```mermaid
flowchart LR
    A[任务与硬约束] --> B[公开材料筛候选]
    B --> C[统一配置做开发评测]
    C --> D[检查失败切片和系统成本]
    D --> E[冻结方案]
    E --> F[一次冻结测试]
    F --> G[发布或回滚]
```

公开材料适合排除明显不支持目标语言、模态、许可或资源边界的模型，也可以提醒你要测哪些能力。它不能替代本地任务样本，因为 benchmark 的用户、提示、答案标准和失败代价通常不同。

## 示例：企业中文文档助手

合格合同可以这样写：只回答内部政策文档问题；答案必须给出句级引用，证据不足时拒答；输入不得离开本地网络；单请求输入 p95 为 24K token，输出不超过 800 token；单机可用显存 24 GB；20 并发时端到端 p95 小于 5 秒；关键政策题引用忠实度至少 98%，越权访问为零容忍；许可证需允许组织内部商用；方案冻结后再启封 300 条测试题。

此时“超大托管模型综合分更高”没有决策意义，因为数据不得出域是硬约束。“窗口支持 128K”也不是通过，因为真实长度桶、引用和并发仍未验收。

## 本课验收

1. 为什么不能只用“Qwen”“Llama”或“DeepSeek”作为实验 ID？
2. 一个模型权重可以下载，为什么仍需单独审查许可证和部署边界？
3. 公开榜单在完整选型流程中最适合做哪一步，最不适合替代哪一步？
4. 写出你关心场景的一项质量门槛、一项资源门槛和一项安全红线。

## 方法边界

- 选择合同能防止比较对象漂移，不能保证任务样本和标签本身正确。
- 许可证摘要不是法律意见；高风险商用仍需由有责任和权限的人审查原文。
- 冻结配置不等于永远不更新；模型、依赖或流量变化后要建立新版本记录。
- 硬件可容纳权重不等于服务满足并发、上下文和尾延迟要求。
