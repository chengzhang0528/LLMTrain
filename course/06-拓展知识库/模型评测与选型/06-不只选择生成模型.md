# 不只选择生成模型

> **学习导航**：承接现实生成模型快照；本课把真实 AI 系统拆成召回、重排、识别、生成、安全与执行组件；完成后应能为每个组件指定独立候选、指标和失败责任。

## 本课目标

- 识别 Embedding、Reranker、OCR、ASR、Guard 和生成模型的不同职责。
- 为每类组件匹配正确指标，不用聊天总分替代组件验收。
- 判断何时应加入专用模型，何时复杂系统并不划算。

## 为什么要学这一课

用户看到的是一个回答，系统内部却可能先做语音识别、查询改写、向量召回、重排、OCR、生成、内容安全和权限检查。若所有失败都归因给“主模型不够强”，团队会反复换大模型，却没有修复真正丢失信息的环节。

> **快照证据**：本页模型卡链接固定到 2026-08-12 核查时的 40 位 commit SHA；SHA 标识证据页面 revision，不是权重文件哈希。日期快照更新时必须重新核对许可证与正文事实，不能只把日期向后移动。

## 一条现实系统链

```mermaid
flowchart LR
    A[文本/图片/语音] --> B[OCR / ASR / 解析]
    B --> C[Embedding 召回]
    C --> D[Reranker 重排]
    D --> E[生成模型]
    E --> F[Guard / 规则 / 引用核验]
    F --> G[回答或工具动作]
```

并非所有项目都需要这条完整链。流程图用于定位职责，不表示应默认增加组件。

## Embedding：先把相关内容召回来

Embedding 模型把查询和候选内容表示成向量，用于相似检索、聚类或匹配。它的核心不是“回答得多好”，而是目标证据能否进入前 `k` 个候选。

| 需要测什么 | 为什么 |
|---|---|
| Recall@k | 前 `k` 项召回的相关项数占全部相关项的比例 |
| Hit@k | 前 `k` 项是否至少命中一个相关项 |
| 全部必要证据齐全率 | 回答该题所需的所有证据单元是否都进入前 `k` 项 |
| MRR / nDCG@k | 相关结果是否排在前面，相关等级是否合理 |
| 语言与领域切片 | 中文、英文、代码、术语和短查询可能表现不同 |
| 长度与切分 | 文档被截断或切得过碎会丢语义 |
| 索引速度、内存与更新成本 | 线上可维护性不只取决于质量 |

截至快照日，[Qwen3-Embedding-0.6B](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B/blob/97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3/README.md) 的官方元数据为 Apache-2.0，[BGE-M3](https://huggingface.co/BAAI/bge-m3/blob/5617a9f61b028005a4858fdac845db406aefb181/README.md) 为 MIT，[multilingual-e5-large](https://huggingface.co/intfloat/multilingual-e5-large/blob/3d7cfbdacd47fdda877c5cd8a79fbcc4f2a574f3/README.md) 为 MIT。它们可作为多语言或不同资源档的现实候选，不能因公开名称含“multilingual”就跳过本地中文领域召回测试。

## Reranker：把少量候选重新排序

Reranker 通常同时读取查询与候选文本，估计更精细的相关性。它可能提高前排证据质量，但增加每个候选的计算与延迟。验收必须固定召回器和候选数，否则无法知道收益来自哪里。

现实候选包括 Apache-2.0 的 [Qwen3-Reranker-0.6B](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B/blob/e61197ed45024b0ed8a2d74b80b4d909f1255473/README.md) 和 [bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3/blob/953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e/README.md)。比较时同时报告 `k`、文本截断、批处理、nDCG/MRR、端到端答案和额外 p95；Reranker 自身分数高不保证生成答案使用了排在前面的证据。

## OCR 与文档解析：先确认读到了什么

OCR 不是“图片交给大模型”这一句话。文档系统可能需要字符识别、版面检测、表格结构、公式、阅读顺序、跨页关联和字段规范化。常见指标包括 CER、字段 Exact Match、表格结构相似度、阅读顺序与端到端问答成功率。

[PaddleOCR-VL-1.5](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.5/blob/2a4195faa5e7914c12f2fc601d72c81caf8d2da5/README.md) 在 2026-08-12 官方元数据中为 Apache-2.0、图文到文本候选。它发布很新，生态活跃或发布更晚不等于已经在你的扫描件、票据和语言上验证。通用视觉语言模型也应作为对照，但不能只凭视觉问答总分替代小字、表格和跨页切片。

## ASR：语音先变成可用文本

ASR 要同时测语言/口音、噪声、专业词、时间戳、长音频、流式首字延迟和实时因子。WER 与 CER 只能描述转写误差，不能代表说话人识别、语义问答或语音自然度。

MIT 许可的 [Whisper large-v3-turbo](https://huggingface.co/openai/whisper-large-v3-turbo/blob/41f01f3fe87f28c78e2fbf8b568835947dd65ed9/README.md) 仍可作为多语言 ASR 基线候选。若项目要求中文方言、实时会议或端侧运行，应加入对应专用候选和真实录音切片；公开英语或干净语音分数不能外推。

## Guard 与规则：限制输入、输出和动作

Guard 模型可以分类安全政策、越权请求或输出风险；确定性规则还负责权限、参数范围、数据脱敏和工具白名单。安全评测至少报告 Precision、Recall、误杀、漏放、语言切片、绕过攻击和延迟。

[Llama Guard 4 12B](https://huggingface.co/meta-llama/Llama-Guard-4-12B/blob/87acb4b94e930c3d679e6e7ee9d57e2feab9ea71/README.md) 是图文 Guard 候选，但采用 Meta 专用许可证，需独立审查。任何 Guard 都不能替代应用权限：模型说“允许”不应自动授予数据库、付款或代码执行权限。

## Router、验证器和小模型

- Router：按任务、预算或风险选择模型/配置，要测路由准确、回退、成本和最坏情况。
- 可执行验证器：对 JSON schema、代码测试、计算和数据库约束给确定结果，但覆盖不足会产生假通过。
- 小分类器：意图、语言、垃圾内容和固定标签任务常比大生成模型更稳定便宜。
- 引用核验器：检查主张与证据对应，仍需面对证据本身错误或过时。

## 用端到端消融决定是否保留组件

固定同一开发集，依次比较：

1. 只有最简单检索/规则基线；
2. 加 Embedding 或替换召回；
3. 加 Reranker；
4. 替换生成模型；
5. 加 Guard 或验证器。

每次只改一个主要因素，记录质量增量、p95、成本和新增失败。若 Reranker 只提高公开 nDCG，却没有提高端到端任务成功，或收益小于延迟与维护代价，就没有足够证据保留它。

## 组件选择矩阵

| 观察到的失败 | 先查组件 | 不应默认做什么 |
|---|---|---|
| 正确文档完全没进入候选 | 切分、Embedding、索引 | 先换更大生成模型 |
| 相关文档很多但关键证据排太后 | Reranker、查询改写 | 盲目扩大上下文 |
| 扫描表格字段丢失 | OCR、版面、表格解析 | 把错误 OCR 文本归因给推理 |
| 专业词转写错误 | ASR、词表与音频切片 | 只调聊天 prompt |
| 工具越权或危险参数 | 权限、规则、Guard、执行沙箱 | 让生成模型自行保证安全 |
| 证据齐全但回答不遵循格式 | 生成模型、提示或后训练 | 重建向量索引 |

## 本课验收

1. RAG 没召回关键文档时，为什么换更大生成模型通常不能修复？
2. Reranker 的 nDCG 提高后，为什么仍要测端到端回答？
3. OCR 的 CER 很低，文档问答仍可能在哪些层失败？
4. Guard 模型为什么不能替代应用层权限与执行沙箱？

## 方法边界

- 增加组件会增加延迟、依赖、监控和故障面，不应为了“架构完整”而添加。
- 模型卡的许可证元数据仍需对照原文和依赖；本页不是法律意见。
- 组件局部指标与端到端价值可能方向不同，最终决策回到任务合同。
- 本页列出的专用模型是快照候选，不是各领域永久最佳模型。
