# 把评分指标翻成大白话

> **学习导航**：承接选择合同中的验收规则；本课把常见质量、偏好、检索、代码和系统指标还原成“数了什么”；完成后应能指出一个分数的对象、分母、方向和未覆盖风险。

## 本课目标

- 用日常语言解释常见评分指标及其适用对象。
- 区分自动真值、模型裁判、人类偏好和系统性能证据。
- 识别同名指标因数据、预算或聚合方式不同而不可直接比较。

## 为什么要学这一课

一个分数只有在“样本、正确标准、运行配置、聚合方法”固定时才有意义。`90%` 可能是 100 道选择题的准确率，也可能是允许生成十次后的 `pass@10`，还可能是裁判模型的偏好率。三者都写百分数，却回答完全不同的问题。

## 有参考答案的任务

| 指标 | 大白话 | 必须追问 |
|---|---|---|
| Accuracy | 所有样本里，完整判对了多少 | 类别是否失衡；“判对”规则是什么 |
| Exact Match | 输出规范化后与参考答案完全一致多少 | 合理同义答案会不会被判错 |
| Precision | 模型说“是”的结果里，有多少真是 | 误报代价是否高 |
| Recall | 所有真正的“是”里，模型找出了多少 | 漏报代价是否高 |
| F1 | Precision 与 Recall 的调和平均 | 是否把不同类别和切片平均掉了 |
| MAE / RMSE | 数值预测与真值相差多远；RMSE 更惩罚大错 | 单位、异常值和误差分布 |

类别极不平衡时，Accuracy 可能很好看。例如 1000 份文档只有 10 份违规，全部预测“合规”也有 99% Accuracy，却把 10 份违规全部漏掉。此时 Recall、误报率和具体失败切片比总 Accuracy 更重要。

## 文本生成与翻译指标

| 指标 | 大白话 | 不能证明 |
|---|---|---|
| BLEU | 机器译文与参考译文的短语重合程度，含长度惩罚 | 译文事实、语气和所有合理表达都正确 |
| ROUGE | 候选摘要覆盖参考摘要词片段的程度 | 摘要没有编造，或覆盖了用户最重要的信息 |
| Perplexity | 模型对一段 token 序列有多“意外”；越低通常表示越会预测该分布 | 聊天更安全、推理更强，或不同 tokenizer 下可直接横比 |
| LLM-as-a-Judge 分数 | 裁判模型按量表认为回答多好 | 裁判没有位置偏差、风格偏好或自我偏好 |

生成任务通常允许多个正确答案，词面重合指标因此只应承担有限职责。事实问答还应核验主张；RAG 还要测证据忠实度；摘要还要检查遗漏和新增事实。

## 代码指标

`pass@1` 问的是：每道题只接受一个候选时，候选通过测试的比例或估计概率。`pass@k` 问的是：允许 `k` 个候选时，至少一个通过测试的概率估计。它必须同时报告每题实际采样数 `n`、`k`、采样配置、测试覆盖、超时和执行环境。

高 `pass@10` 不表示用户第一次生成就有同样成功率，也不表示补丁安全、可维护或真正修复了仓库问题。测试不完整时，错误实现也可能“通过”。HumanEval 论文给出了常见 `pass@k` 估计口径，但具体排行榜仍须核对实现。[来源：Evaluating Large Language Models Trained on Code](https://arxiv.org/abs/2107.03374)

## 偏好、胜率和 Elo

| 指标 | 大白话 | 关键边界 |
|---|---|---|
| Win rate | 在指定成对比较中，A 被判优于 B 的比例 | 依赖对手、题目、平局规则和裁判 |
| Elo rating | 根据一系列对局结果，把相对强弱压成一个可更新标尺 | 是特定对手池中的相对值，不是绝对正确率 |
| Arena 排名 | 用户在匿名成对回答中表达的总体偏好 | 更讨喜不等于更真实、更安全或更适合专业任务 |

若 A 对 B 胜率 60%，不能推出 A 在事实题上 60% 正确，也不能推出 A 对 C 仍胜 60%。比较提示顺序未交换时，裁判还可能偏向第一或第二个答案。

## RAG 与搜索指标

| 指标 | 大白话 | 容易漏掉的层 |
|---|---|---|
| Recall@k | 对每个查询计算“前 `k` 项中的相关项数 / 该查询全部相关项数”，再说明怎样跨查询平均 | 证据排得多靠前、生成是否真正使用 |
| Hit@k | 前 `k` 项中是否至少出现一个相关项，再统计命中的查询比例 | 多个必要证据是否全部召回 |
| 全部必要证据齐全率 | 前 `k` 项是否包含回答该题所需的全部证据单元 | 证据顺序、冗余和生成是否正确使用 |
| MRR | 第一个相关结果出现得有多靠前 | 后续多个相关结果的整体质量 |
| nDCG@k | 兼顾相关等级与排名位置的折损收益 | 标注等级是否可靠、答案是否忠实 |
| Answer correctness | 最终回答是否满足参考标准 | 证据来源与引用是否正确 |
| Faithfulness | 回答主张是否被给定证据支持 | 给定证据本身是否真实、完整、最新 |

RAG 的生成分数低，原因可能在检索、重排、上下文拼接或生成；只换大模型不能定位问题。

若每个查询恰好只有一个相关项，Recall@k 才会退化成 `0/1`，并与该查询的 Hit@k 相同。只要一题可能需要多个文档、段落或表格单元，三者就不能混写：召回 2 个必要证据中的 1 个，Recall@k 是 `1/2`，Hit@k 是 `1`，全部必要证据齐全率则是 `0`。

## OCR、ASR 与多模态

- CER：字符级编辑距离除以参考字符数，常用于中文 OCR 或识别；插入、删除、替换口径要一致。
- WER：词级编辑距离除以参考词数，常用于语音识别；中文如何分词会改变结果。
- 文档理解：还应分开测版面、表格、字段值、阅读顺序和跨页关系。
- 图像问答：总分应拆到 OCR、物体、空间、图表、推理与幻觉切片；“能看图”不是一个单一能力。
- 长上下文：应按长度、证据位置、干扰项和任务类型分桶，窗口上限不是准确率指标。

## 系统指标也属于模型选择

| 指标 | 大白话 | 报告条件 |
|---|---|---|
| TTFT | 从声明起点到收到首 token 多久 | 是否含排队、检索、网络和 prefill |
| TPOT | 首 token 后相邻输出 token 的平均间隔 | 输出长度、batch、并发和统计方式 |
| p95 / p99 latency | 95% / 99% 请求不超过的延迟阈值 | 负载分布、测量窗口和超时处理 |
| Throughput | 单位时间完成多少请求或 token | 输入/输出 token 口径与质量约束 |
| Goodput | 只统计同时满足质量与 SLO 的有效工作量 | 质量门槛和错误请求如何处理 |

平均延迟不能替代尾延迟；离线单请求速度不能替代线上并发；tokens/s 也不能跨 tokenizer、输入输出比例和硬件直接横比。

## 每个分数的六问

1. 在什么数据版本上测？
2. 分母是什么，样本有多少，怎样分桶？
3. 输出如何判对，是规则、人工还是模型裁判？
4. 模型、提示、推理预算、工具和精度是什么？
5. 数字怎样聚合，有没有置信区间和多次运行？
6. 它没有覆盖哪类真实失败？

## 本课验收

1. 为什么 `pass@10 = 90%` 不能写成“第一次生成有 90% 正确”？
2. 一个摘要的 ROUGE 很高，仍可能出现哪两类严重错误？
3. Accuracy 为 99% 的违规检测器为什么可能完全不可用？
4. TTFT 与 TPOT 分别影响哪段用户等待？为什么必须声明测量起点？

## 方法边界

- 指标定义清楚不等于参考答案、测试用例或裁判本身没有偏差。
- 一个指标适合某任务，不表示它能覆盖该任务的全部质量与风险。
- 不同论文可能使用同名指标的不同实现、宏/微平均或规范化规则，必须查评测代码。
- 小样本分数会随机波动；下一课才讨论样本量、配对比较和不确定性。
