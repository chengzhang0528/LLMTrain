# 读榜与选型：指标与场景

<!-- benchmark-snapshot: 2026-08-12 -->

**快速扫描只抓四项：任务、指标方向、版本日期、复核入口。** 榜单排名只对它公开的题目与条件成立。

## 一眼读懂一根柱子

| 位置 | 大白话 | 常见误读 |
|---|---|---|
| 标题 / 副标题 | 任务、数据集、指标和 release | 只看模型名，忘了它测的是哪类任务 |
| 横轴单位 | 百分比、Elo、均值、价格、速度或延迟 | 把不同单位放在一起比 |
| 柱子右侧 | 精确值、并列关系、推理档位 | 只看柱长，不看 `±`、预算和工具 |
| 日期 / 版本 | 这条结果什么时候、用哪个版本测的 | 把旧 release 和新 release 混排 |
| 官方链接 | 回到机构原页、脚本、数据集和模型卡 | 用截图或二手转述代替来源 |

## 指标翻译

| 榜单上写的 | 实际在说什么 | 适合回答 | 不能推出 |
|---|---|---|---|
| Elo / 偏好分 | 这一批用户投票时更常选谁 | 哪个回答更讨喜 | 事实正确、安全、业务成功 |
| Mean / 平均分 | 多个任务分数被合成一个均值 | 固定题集里的总体趋势 | 每个子任务都更强 |
| `% Resolved` | issue 是否被 agent 修复并通过测试 | 指定仓库和 harness 能否完成修复 | 换仓库后仍有同样成功率 |
| `% correct` | 代码编辑题通过的比例 | 受限编辑格式下能否改对代码 | 仓库级工程能力、成本最优 |
| WER | 词级错误比例：$(替换\ S+删除\ D+插入\ I)/参考词数\ N$，越低越好；插入错误多时可超过 100% | 指定语言、分词与规范化口径下的转写错误程度 | 语音识别准确率，或所有语言、噪声和实时场景都一样 |
| RTFx / tokens/s | 相对实时倍数或输出速度，越高通常越好 | 系统吞吐和速度 | 质量、尾延迟和用户体验 |
| Price / latency | 每任务成本、首 token 延迟或响应速度 | 质量与成本/速度的权衡 | 低价或低延迟必然更好 |
| Hit@k | 前 k 项是否至少命中一个相关项；单个查询取 0 或 1 | 是否找到了至少一条相关证据 | 找齐全部必要证据，或生成模型会正确引用 |
| Recall@k | 前 k 项找回的相关项数 / 全部相关项数，再按约定跨查询聚合 | 相关证据被找回了多少 | 至少命中一项就等于召回完整，或生成模型会正确引用 |
| Risk vector / 拒答率 | 不同风险场景下的行为切片 | 哪些风险需要治理 | 存在一个“安全总冠军” |

## 按场景选榜单

| 你的问题 | 先看 | 再补什么 |
|---|---|---|
| 对话体验、写作、综合偏好 | [Arena Text](https://arena.ai/leaderboard/text) | LiveBench 客观任务；不要把偏好分当事实分 |
| 固定题集的通用能力 | [LiveBench](https://livebench.ai/) · [HELM](https://crfm.stanford.edu/helm/capabilities/latest/) | 分类分数、提示、预算和本地样本 |
| 代码补全或仓库修复 | [Aider](https://aider.chat/docs/leaderboards/) · [SWE-bench](https://www.swebench.com/verified.html) | 仓库、工具、重试、成本、测试通过率 |
| 视觉语言、多模态 | [OpenCompass](https://rank.opencompass.org.cn/old-home) · [HELM VHELM](https://crfm.stanford.edu/helm/vhelm/latest/) | 分辨率、图像类型、工具和场景切片 |
| RAG、检索、重排 | [MTEB / MMTEB](https://mteb-leaderboard.hf.space/benchmark/MTEB(Multilingual%2C%20v2)) | 自己的查询分布、Recall@k、引用支持、延迟 |
| OCR、表格、公式、版面 | [OmniDocBench](https://github.com/opendatalab/OmniDocBench) | 文档类型、语言、版面和真实 PDF |
| ASR、会议转写 | [Open ASR](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard) | 语言、口音、噪声、WER、RTFx 和实时约束 |
| 安全和合规 | [HELM Safety](https://crfm.stanford.edu/helm/safety/latest/) · [AIR-Bench](https://crfm.stanford.edu/helm/air-bench/latest/) | 业务红线、人工红队、拒答和升级规则 |
| 只允许本地部署 | LiveBench / MTEB 的开放权重筛选 | 权重、代码、数据、许可证、显存、量化和引擎 |

## 四步决定能不能用

1. **先排硬约束**：许可证、部署地域、上下文、显存、价格或延迟不合格，直接淘汰；“开放权重”不等于代码、训练数据一并开放，也不自动允许商用。
2. **再查复核条件**：数据集、指标公式、模型版本、提示、推理预算、工具、量化和重试是否公开且一致。
3. **再读差距**：只比较同榜同指标；Arena、LiveBench、SWE-bench 与 MTEB 单位不同，**不能跨榜相加**。先看并列、误差区间和样本量；例如 `1506 ±5` 与 `1505 ±4` 不能写成确定领先。
4. **最后本地复测**：用同一批业务样本成对比较，记录失败样本、成本、P50/P95 延迟与红线；榜首仍可能在这一步被淘汰。
