# D15：先固定起点：未训练基线

> **学习导航**：承接 D14 的生命周期闭环，进入 D15-D21 预生成案例；本课审阅环境快照与未训练输出，不要求安装或运行。完成后应能从环境、配置、seed、参数量和测试状态解释“坏输出”为何是必要对照，以及结果还缺什么复查条件。

## 本课核心判断

**没有未训练基线，就无法判断改善来自训练、初始化、提示词还是人工挑选。**

## 这组案例负责什么

**D15-D21 只训练你的证据判断，不让你实际训练模型。** 你会依次审查起点、数据、张量、单 batch 排错、正式曲线、对照实验和模型卡。字符级微型模型删掉了分词器训练的复杂度，适合暴露训练链，但不能外推为真实业务质量。

看环境记录时只核对五类条件：模型与 tokenizer、模板与精度、软件与硬件版本、输入输出长度、batch 与并发。CPU/GPU 决定怎样执行和花费多少，不直接决定权重学会了什么。

## 预设案例：运行前快照

下面是课程冻结的教学快照，不是要求学习者复现的环境：

| 项目 | 记录值 | 观察重点 |
|---|---|---|
| Python | 3.12 | 软件版本会影响可复现性 |
| PyTorch | 2.x，CPU | 只足以说明大致运行环境；要严格复现还需精确版本、构建和相关库 |
| 配置 | `smoke.yaml` | `seed=42`、1 层、2 头、隐藏宽度 32 |
| 数据 | 文本模式读取后 1,288 个字符 | 只能验证管线和局部记忆 |
| 单元测试 | 全部通过 | 说明已检查形状、遮罩和基础接口，不说明模型质量好 |
| 权重状态 | 随机初始化 | 还没有通过训练数据形成稳定语言模式 |

这里的 `smoke.yaml` 是快速检查管线的调试配置，不是后面 800 step 正式记录使用的候选配置。D17 继续用这组较小宽度追踪张量形状；D19 会明确切换到 `cpu.yaml`，再把正式配置、曲线和最终模型卡绑定在一起。

冻结的未训练输出示意：

> 小束页岸疑巡，空既灯的石……

这段文字看似偶尔出现中文字符，但没有稳定语义。字符来自词表，顺序主要由随机权重和解码过程决定；不能因为出现了“灯”或“石”就说模型理解了物体。

## 怎样读这个基线

- 测试通过：代码满足被测试的局部性质。
- 输出很差：符合未训练模型的预期。
- 固定 seed：减少一次比较中的随机变化，不代表所有硬件都逐位一致。
- 小配置：让案例容易观察，不代表真实模型的规模和能力。
- `PyTorch 2.x`：是教学快照的已知范围，不是可精确重建数值结果的依赖记录。

## 先固定一份实验合同

基线不只是“先跑一次”。在看到训练后结果之前，应先写下本案例准备比较什么：

| 合同项 | 本案例的冻结约定 | 为什么要先写 |
|---|---|---|
| 核心问题 | 参数更新后，模型是否更能预测这份小语料的局部模式 | 防止看到结果后改成更容易回答的问题 |
| 起点 | 随机初始化、`seed=42`、固定字符词表 | 给后续检查点一个明确参照 |
| 开发证据 | 同一切分下的 train/val loss 与固定提示样例 | 用于观察和选择候选点 |
| 结论边界 | 只讨论教学管线和局部拟合 | 不把小语料结果外推成通用中文能力 |
| 不允许改变 | 比较时的提示、tokenizer 和数据版本 | 避免多个变量一起变化后无法归因 |

正式项目还会加入质量、安全、成本门槛和冻结测试集。本案例故意把目标缩小，是为了让每条结论都能从预设证据推出，而不是让一个微型模型承担真实任务。

## 同一段坏输出可能来自不同原因

未训练模型输出混乱是预期现象，但“输出混乱”本身不能证明权重一定未训练：

| 可能原因 | 怎样区分 |
|---|---|
| 随机初始化 | 检查加载日志和 step=0 权重状态 |
| tokenizer 不匹配 | 同一 ID 无法按训练时词表还原，常出现大量异常字符 |
| 提示超出词表或分布 | 已知提示正常、陌生提示失败，需比较输入覆盖 |
| 解码参数极端 | 固定权重后改变 temperature 或 top-k 做对照 |
| 检查点加载失败 | 比较加载前后参数摘要和已知验证 loss |

因此本课关注的是“运行前快照能否支持起点判断”。只展示一段文字，不展示配置、权重状态和 tokenizer，证据是不完整的。
