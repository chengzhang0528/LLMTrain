# 模型卡审查框架

这不是需要学习者填写或提交的模板。下面是一份已填写的 tiny-llm 教学模型摘要；已知缺口会直接写成“未提供”，不会用占位话术伪装成完整证据。学习重点是检查“模型、数据、评测、限制和复现证据”是否互相支持。

## 冻结案例摘要

| 字段 | 冻结案例记录 | 审查意见 |
|---|---|---|
| 架构 | 2 层字符级 Decoder-only Transformer | 可解释训练流程，但与现代通用大模型差距巨大 |
| 参数量 | 130,432（约 0.130M，LM Head 与 token Embedding 共享权重） | 可由 418 字符词表、64 维隐藏层、64 token 上下文和 2 个 Transformer Block 复算 |
| tokenizer | 字符级，约 418 个字符 | 适合教学，不代表 BPE 或 Unigram |
| 上下文长度 | 64 token | 超出长度的输入不在能力范围内 |
| 训练配置 | 固定 seed，800 steps，课程预生成记录 | 固定种子减少比较噪声，不等于跨硬件逐位复现 |
| 代码版本 | Git 提交 `7220daf58dc4` 中的 `tiny-llm` 实现与 `configs/cpu.yaml` | 后续实现变化时必须另记提交，不能继续沿用本页数字 |
| 数据 | 1331 字符课程原创文本，90/10 顺序切分 | 许可清楚，但覆盖窄且可能存在相邻内容相似 |
| 评测 | train/val loss、固定提示样例 | 缺少外部领域、事实性和安全评测 |
| 记录中的候选点 | step 500 在已展示评测点中的 val loss 最低 | 缺少部分评测点，不能确认它是全程最佳；还应核对选择规则是否事先冻结 |
| 已知失败 | 记忆、重复、乱码、换主题失败 | 失败样例必须保留，不能只展示最好输出 |
| 预期用途 | 解释最小训练和生成链路 | 不能用于真实业务 |
| 不适用用途 | 客服、医疗、法律、内容自动发布 | 限制与证据范围一致 |

## 一条结果还缺哪些上下文

任何 loss 或生成样例都要绑定配置、数据版本、检查点、提示词、seed、temperature、top-k、设备和评测脚本版本。少掉这些条件，数字仍然存在，但结论无法复查。
