# D21：用模型卡守住结论边界

> **学习导航**：承接 D15-D20 的全部预设案例；本课审阅一份预生成模型卡摘要，不要求打包或提交文件；完成后应能发现模型来源、评测、限制和复现证据中的缺口。

## 本课目标

能根据模型卡判断一个教学模型从哪里来、测过什么、不能做什么，以及别人是否有足够信息复查结论。

## 为什么要学这一课

权重文件本身不会说明训练数据、配置、最佳检查点、失败模式和适用边界。模型卡把这些证据放在一起，防止把“能加载”误写成“可使用”，也防止把教学演示误投到真实业务。

## 预设案例：模型卡摘要

| 字段 | 冻结记录 | 审阅意见 |
|---|---|---|
| 模型 | 2 层字符级 Decoder-only Transformer | 结构清楚，但与现代商用 LLM 差距巨大 |
| 参数量 | 130,432（约 0.130M，输入输出权重共享） | 与 D19 的 `cpu.yaml` 正式配置和源码张量形状一致 |
| 上下文长度 | 64 token | 超出长度不属于本模型能力范围 |
| 数据 | 文本模式读取后 1,288 字符课程原创文本 | 许可清楚，覆盖极窄 |
| tokenizer | 字符级，约 418 个字符 | 适合教学，不代表 BPE/Unigram 方案 |
| 训练 | 固定 seed，800 steps | 需要同时提供最佳验证点而非只给最后一步 |
| 代码版本 | Git 提交 `95d627307a99` 中的 `tiny-llm` 与 `configs/cpu.yaml` | 结果只绑定这个实现快照 |
| 运行环境 | Python 3.12、PyTorch 2.x、CPU | 已知范围足以阅读案例；缺少精确 PyTorch 构建、底层库和 CPU 信息，不能宣称逐位复现 |
| 评测 | train/val loss、固定提示样例 | 没有外部领域、事实性或安全评测 |
| 记录中的候选点 | step 500 在已展示评测点中的 val loss 最低 | 缺少 200、400、600 等评测结果，不能确认它是全程最佳；选择规则也应在实验前固定 |
| 限制 | 可能记忆、重复、输出乱码、不能用于业务 | 边界与证据一致 |
| 不允许用途 | 客服、医疗、法律、内容自动发布 | 教学模型不承担真实决策 |

## 参数量怎样复算

`cpu.yaml` 使用 `V=418、D=64、T=64、N=2`，MLP 中间宽度为 `4D=256`。源码让 QKV 和注意力输出投影不带 bias，MLP 两个线性层带 bias；每个 Block 有两个带缩放和偏置的 LayerNorm，最后还有一个 LayerNorm。LM Head 与 token Embedding 共享权重，不重复计数。

| 部分 | 算式 | 参数量 |
|---|---:|---:|
| token 与位置 Embedding | `418×64 + 64×64` | 30,848 |
| 单个 Block 的注意力 | `3×64×64 + 64×64` | 16,384 |
| 单个 Block 的 MLP | `64×256+256 + 256×64+64` | 33,088 |
| 单个 Block 的两个 LayerNorm | `2×(64+64)` | 256 |
| 两个 Block | `2×(16,384+33,088+256)` | 99,456 |
| 最终 LayerNorm | `64+64` | 128 |
| 总计 | `30,848+99,456+128` | 130,432 |

只给词表、隐藏宽度、上下文和层数还不足以得到精确参数量；还必须知道 MLP 宽度、各层 bias、Norm 参数和权重共享约定。

## 复现证据审查

一份记录至少应能对应到：代码版本、数据版本、配置、tokenizer、随机种子、训练日志、最佳检查点选择规则、评测脚本版本和已知失败。课程只训练你审查这些证据，不要求在空白环境中重新执行流程。

## 从主张反查证据

模型卡不是字段越多越好，而是每条主张都能找到支持与边界：

| 主张 | 当前证据 | 审阅结论 |
|---|---|---|
| “代码和形状链可工作” | 单元测试与 D17 前向追踪 | 支持被测试的局部性质 |
| “模型拟合了教学语料” | train loss 下降、单 batch 过拟合 | 支持局部拟合，不支持通用能力 |
| “step 500 是最佳点” | 已展示点中 val loss 最低 | 证据不足，缺 200/400/600 |
| “结果可精确复现” | Python 3.12、PyTorch 2.x、CPU | 证据不足，环境记录太粗 |
| “可用于真实客服” | 无外部任务、安全或事实评测 | 不支持，并且模型卡明确禁止 |

审阅时把每个形容词改成可查问题：“好”对应哪个指标和样本？“稳定”重复了多少次？“安全”覆盖哪些高风险类别？“可复现”允许多大数值差异？无法回答时，删掉主张或把它降为待验证事项。

## 模型卡最终要支持一个使用决策

模型卡的读者需要知道“可以做什么、不能做什么、出错怎么办”。对于这个 tiny-llm，合格决策是：可以用于阅读字符级 Decoder 的数据、形状、训练与评测证据；不能用于生成真实业务内容，也不能把预生成结果当作当前机器 benchmark。

若要发布真实模型，还应补充责任人、许可证、风险接受者、监控指标、回滚版本和到期复审时间。模型、数据、提示、检索或工具任一关键版本变化后，都要重新核对受影响的模型卡字段；文档不能永远描述第一个版本。

## 三种完成状态不要混在一起

| 状态 | 判定依据 |
|---|---|
| 学完案例 | 能解释 D15-D21 的预设证据与结论边界 |
| 复查过实验 | 已核对真实代码、配置、日志、检查点和评测记录 |
| 模型可发布 | 目标质量、成本、安全、治理和回滚门槛全部通过 |

本课程只要求第一项。能正确指出证据缺口，比假装完成后两项更符合成果验收。

## 最终口试

1. 数据怎样变成错开一位的输入与目标？
2. 因果遮罩保护了什么性质？
3. loss、梯度和参数更新的顺序是什么？
4. train loss 与 val loss 分别能说明什么？
5. prefill、decode 与 KV Cache 在推理时怎样连接？
6. 为什么单 batch 过拟合不能证明泛化？
7. 为什么这个案例不是通用大语言模型？

能不用运行代码而根据预设证据准确回答这些问题，就完成了训练过程案例的学习目标。
