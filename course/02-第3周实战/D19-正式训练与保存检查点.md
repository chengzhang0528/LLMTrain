# D19：从曲线中选择可恢复检查点

> **学习导航**：承接 D18 的最小管线检查；本课审阅一份预生成训练记录摘要和检查点清单，不要求等待计算；完成后应能从已展示的 train/val loss、配置与恢复信息判断实验发生了什么，并识别还缺哪些证据。

## 本课目标

能从已展示记录中找出候选验证点和过拟合迹象，说明确认最佳检查点还缺什么，并列出恢复训练所需信息，不再用终端最后一行代表整次训练。

## 为什么要学这一课

训练不是“等一个低 loss”。一份可信记录必须同时回答配置是什么、数据怎样切、指标怎样变化、哪些点值得作为候选、证据是否足以确认最佳点，以及失败后能否恢复。否则即使留下一个权重文件，也不知道它来自哪次实验。

## 预设案例：800 step 教学记录

D15-D17 使用 `smoke.yaml` 和缩短输入检查管线与张量形状；本课切换到正式候选配置 `cpu.yaml`。这是从调试阶段进入正式记录，不是一次只改变层数的对照实验。后续 loss、检查点和模型卡都绑定下面这组配置：

| 项目 | 正式记录 |
|---|---|
| 数据与切分 | 1331 字符课程语料，按顺序 90% 训练、10% 验证 |
| 随机与设备 | `seed=42`，CPU；页面未提供精确 PyTorch 构建和底层库版本 |
| 模型 | 2 层、4 头、隐藏宽度 64、上下文 64 token、dropout 0.1 |
| 训练 | `batch_size=16`、800 step、每 100 step 评测、每次评测 20 个 batch |
| 优化 | 学习率 0.001、weight decay 0.01、梯度裁剪 1.0 |
| 生成检查 | 固定提示“小”、temperature 0.75、top-k 20；生成设置不参与训练 loss 计算 |

以下表格只摘录部分评测点；配置要求的 step 200、400、600 结果未在本页提供，因此只能比较表中已展示的记录，不能据此确认全程最佳检查点。

| step | train loss | val loss | 教学解读 |
|---:|---:|---:|---|
| 0 | 6.08 | 6.04 | 随机初始化 |
| 100 | 4.21 | 4.36 | 训练与验证都改善 |
| 300 | 3.02 | 3.41 | 仍有泛化改善 |
| 500 | 2.31 | 3.18 | 当前展示点中的最低验证值 |
| 700 | 1.82 | 3.27 | train 继续降，val 在展示记录中回升 |
| 800 | 1.63 | 3.39 | 过拟合迹象更明显 |

这组数值是冻结的判读材料，不是对某块 CPU 或 GPU 的性能声明。若只根据本页展示的验证点选择候选检查点，step 500 暂时最值得检查；正式选择仍需查看所有评测点，并使用事先固定的选择规则，而不是因为 step 800 的 train loss 最低就自动选最后一步。

## 先写选择规则，再看曲线

一个可复查规则可以写成：在所有已完成的周期评测点中，选择验证 loss 最低且数值有限的检查点；若差异小于预先设定的容差，再优先选择更早或成本更低的点。规则写在训练前，能避免看完曲线后为喜欢的结果临时改口径。

本页缺少 step 200、400、600，因此 step 500 只能叫“已展示记录中的候选点”。若缺失点的 val loss 是 3.05，最终候选就会改变。这里故意保留证据缺口，是为了练习区分“表内最优”和“全程最优”。

选择候选检查点之后，还要在固定任务样本上检查生成、已知失败和资源指标；最低 val loss 不保证每个产品门槛都达标。最终方案冻结后，才交给未参与选择的冻结测试集。

## 检查点至少要能回答什么

| 信息 | 缺失后的问题 |
|---|---|
| 模型权重与架构配置 | 无法正确加载张量 |
| tokenizer 与词表 | ID 无法还原为同一套符号 |
| optimizer 与当前 step | 无法从同一优化状态继续训练 |
| 随机种子与数据版本 | 难以解释重跑差异 |
| 当前和最佳指标 | 不知道保存点为什么被选中 |
| 软件、硬件与依赖记录 | 无法判断数值或性能差异来源；仅写“PyTorch 2.x”不足以精确重建运行环境 |

## 可恢复、可复查和可复现不是同一级要求

| 要求 | 最少意味着什么 | 本案例当前状态 |
|---|---|---|
| 可加载 | 权重、架构和 tokenizer 能组合起来做前向 | 模型卡描述了所需对象 |
| 可恢复 | 还能还原优化器、调度器、step、随机与数据位置继续训练 | 页面列出要求，但未提供真实检查点 |
| 可复查 | 他人能沿配置、日志和选择规则判断结论是否成立 | 可以审阅展示材料，也能发现缺失点 |
| 精确复现 | 在明确环境中重跑并达到约定容差或逐位结果 | 缺少精确依赖与完整日志，不能宣称 |

恢复关注“能否接着跑”，复现关注“别人能否重新得到相同证据”。一份含优化器状态的检查点可能可恢复，却因为数据版本不明而不可复现；一份完整实验报告也可能可复查，但没有发布权重，无法直接恢复训练。
