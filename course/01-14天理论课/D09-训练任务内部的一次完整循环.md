# D09：一个训练 Step 如何推动整次任务

> **学习导航**：[模型全生命周期总纲](模型训练总纲.md) -> D08 数据准备 -> **D09 一次训练任务** -> D10 规模化；本课把 batch、一次参数更新、周期验证和保存连成任务。完成后应能逐行解释伪代码，按正确分母读 loss 与吞吐，并说明它为何仍不是完整模型项目。

## 先记四个训练判断

1. **一个 step 只在 `optimizer.step()` 后完成一次参数更新。**
2. **batch 中有多少 token，不等于更新了多少次参数。**
3. **验证只做前向，不更新参数；它用于选配置和 checkpoint，不是最终测试。**
4. **日志要把 loss、学习率、梯度、吞吐和检查点对齐到同一 step。**

## 先分清三个尺度

| 尺度 | 包含什么 | 本课是否完整覆盖 |
|---|---|:---:|
| 完整模型项目 | 问题、基线、数据、架构、多次训练、后训练、评测、部署 | 否，见训练总纲 |
| 一次训练任务 | 固定一套数据版本、模型配置和超参数，运行许多 step，保存日志与检查点 | 是，本课主角 |
| 一个训练 step | 取 batch、前向、loss、反向、更新 | 是，训练任务反复执行的内核 |

例如 L0 的完整项目先固定 `V=8、D=4、N=2` 和训练外测试集；其中一次训练任务采用 batch 16、最多 600 step；每个 step 只处理当前 batch 并产生一次参数更新。三层都能被称为“训练”，但可得出的结论不同。

## 一个 step 怎样循环成训练任务（第一次必看）

```python
evaluate_without_updating_parameters()
save_checkpoint(step=0)

for completed_steps in range(1, max_steps + 1):
    x, y = next_train_batch()
    optimizer.zero_grad()
    logits, loss = model(x, y)
    loss.backward()
    clip_grad_norm_if_needed()
    optimizer.step()
    scheduler.step()

    if completed_steps % eval_interval == 0:
        evaluate_without_updating_parameters()
        save_checkpoint(step=completed_steps)
```

**step 表示“已经完成多少次参数更新”：**`step=0` 是更新前起点，第一次 `optimizer.step()` 完成后才是 `step=1`。

1. 循环外固定数据、结构、起点、优化器、学习率计划和随机种子。
2. 循环内执行前向、loss、反向和更新。
3. 周期性验证与保存负责比较和恢复，不参与当前 batch 的参数更新。

| 代码动作 | 接上了哪一课 | 它产生什么 |
|---|---|---|
| `next_train_batch()` | D08 的切分与打包 | 输入 `x` 和错开一位的目标 `y` |
| `model(x, y)` | D02-D06 的模型前向 | logits 与平均 loss |
| `loss.backward()` | D04 的梯度 | 当前计算图中参与 loss 的可训练参数梯度 |
| `optimizer.step()` | D04 的参数更新 | 一组新参数 |
| `evaluate...()` | D08 的验证集（开发集） | 不更新参数的验证指标 |

## 用数字读懂一个 step（第一次必看）

沿用教学模型 L0，假设一个 batch 有 `B=2` 条序列，每条有 `T=4` 个计分位置，词表大小 `V=8`：

1. 输入 ID 的形状是 `(2,4)`。
2. 模型输出 logits 的形状是 `(2,4,8)`，共给出 `2 x 4 = 8` 份下一 token 分布。
3. 目标形状是 `(2,4)`，每个位置提供一个正确 token ID。
4. 交叉熵先得到 8 个位置的损失，再按实现约定求平均或求和。
5. 一次 `backward()` 把这批位置共同产生的信号累积到参数梯度；一次 `optimizer.step()` 才完成这一个 step 的参数更新。

所以“8 个预测位置”不等于“更新 8 次参数”。batch、token 位置和参数更新属于不同计数轴。若使用梯度累积，甚至会处理多个小 batch 后才完成一次参数更新；日志里的 step 定义必须跟随真正的 `optimizer.step()`，否则学习率、保存点和恢复位置都会错位。

### 五种训练计数不能混用

假设 4 张卡，每张卡一次放 2 条长度为 4 的序列，梯度累积 3 次后更新；每条序列平均只有 3 个位置计入 loss：

| 计数 | 一次参数更新内的数值 | 回答什么 |
|---|---:|---|
| 原始序列位置 | `4卡×2序列×4位置×3次=96` | 设备实际处理了多少位置，含 mask 或 padding |
| 有效计分 token | `4×2×3×3=72` | 有多少目标位置真正进入 loss |
| 梯度累计轮次 / 本地 micro-batch | 3 轮；每轮每卡 1 个本地 micro-batch | 更新前累计了几轮梯度；单卡每轮装入什么 |
| optimizer step | 1 | 参数被优化器写回多少次 |
| epoch | 不能仅由上述数字确定 | 对某个有限数据集大约遍历了多少轮 |

**有效 batch 是按什么单位定义的，必须就地写清。**这里若按序列计，一次更新的全局有效 batch 是 `4×2×3=24` 条序列；若按有效 token 计，则是 72。多来源加权采样、流式数据或反复重采样时，“一个 epoch”可能没有稳定且有用的含义，应优先报告累计有效 token、optimizer step 和各来源抽样次数。

## Loss 的分母会改变每个 token 的权重

**有变长样本或梯度累积时必看。**

padding、角色 mask 和文档边界会让不同小 batch 的有效计分 token 数不同。假设准备累计两个小 batch 后再更新：

| 小 batch | 有效 token 数 | token loss 总和 | 本批平均 loss |
|---|---:|---:|---:|
| A | 8 | 12 | 1.5 |
| B | 4 | 4 | 1.0 |

若目标是让 12 个有效 token 等权，累计窗口的正确平均是：

$$
\frac{12+4}{8+4}=\frac{16}{12}\approx1.33.
$$

**不能再平均两个“批平均 loss”**：这样会让 4 个 token 的 B 与 8 个 token 的 A 拥有相同批权重。

实现可以让 micro-batch、样本或 token 等权，但配置与日志必须写清分母；`micro-batch` 一词还要注明是单卡批次还是全局合计。分布式训练也要写清跨设备规约的是 loss 总和、有效 token 数，还是已经平均过的值。

这也是为什么“梯度累积 8 次约等于更大 batch”需要条件。若每次都对本批平均 loss 直接反向，再把梯度相加，最后一个短批、不同长度样本或不同 mask 比例可能改变实际权重。稳妥做法是先定义希望等权的基本单位，再让 loss 缩放、梯度累计和日志统计共同实现这个定义。

## 梯度裁剪（出现不稳定时再读）

全局梯度范数裁剪会先把所有可训练参数的梯度合在一起计算范数。若当前全局范数为 10，阈值为 1，就把各梯度统一乘以约 `1/10`，使总范数回到 1；这种整体缩放保留方向，缩短本步长度。它通常发生在反向传播之后、优化器更新之前。

裁剪不是把异常根因删除。若某个损坏样本、错误 mask 或过大学习率持续制造巨大梯度，裁剪只是在每一步限制损害。日志应同时记录裁剪前范数、是否触发裁剪和异常 batch 身份；若几乎每步都触发，优先检查数据、loss 尺度、精度和学习率，而不是继续降低阈值掩盖问题。

## AdamW 怎样把当前梯度变成一次更新

**进阶。**

D04 使用 `新参数 = 旧参数 - 学习率 × 梯度` 建立方向直觉。真实大模型常用 AdamW，它为每个参数维护两份历史统计，并把权重衰减作为独立项。忽略偏置修正细节前，核心账本可写成：

$$
m_t=\beta_1m_{t-1}+(1-\beta_1)g_t,
\qquad
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2.
$$

- $g_t$ 是当前梯度。
- $m_t$ 汇总近期方向，减少只跟随单批噪声。
- $v_t$ 汇总梯度平方，用来调整不同参数方向的步幅尺度。
- 学习率决定全局步幅；权重衰减项则独立把选定权重向 0 拉近。

第一次更新若 `g=2、m₀=v₀=0、β₁=0.9、β₂=0.99`，会先得到 `m=0.2、v=0.04`。进行第一次偏置修正后，方向估计回到约 2，平方尺度回到约 4；两者组合后的适配方向约为 `2/√4=1`。若参数为 3、学习率 0.1、衰减系数 0.01，忽略很小的 epsilon，本步大致减去：

```text
梯度适配项：0.1 × 1 = 0.1
独立衰减项：0.1 × 0.01 × 3 = 0.003
新参数约为：3 - 0.1 - 0.003 = 2.897
```

这个例子只解释状态怎样进入更新，不代表默认超参数或所有参数都应衰减。实际训练通常按参数组决定哪些权重使用衰减。AdamW 也不会替模型计算梯度、自动找到学习率或保证泛化；它只是从已有梯度和历史状态计算本次更新。

## 一次训练任务的外壳

```text
任务开始：记录配置与数据版本 -> 初始化或加载检查点
任务中间：反复执行 step -> 定期验证 -> 定期保存 -> 记录异常
任务结束：按开发验证指标选候选检查点 -> 冻结方案 -> 交给冻结测试集做最终评估
```

“最后一个检查点”不必是“最好的检查点”，验证指标可能在训练后期变差。一次任务结束也不等于项目成功：候选检查点先由验证集参与选择；方案冻结后，再用未参与选择的冻结测试集检查质量、成本与安全边界。

## 停下、保存和恢复是三件事

**长任务必看。**

训练可以因为达到最大 step、验证指标不再改善、资源预算耗尽或发生异常而停下。停下只描述“这次运行不再继续”，不自动说明已经保存，也不说明能从同一点恢复。

一个用于继续训练的检查点通常需要模型权重、优化器状态、学习率调度器状态、已完成 step、随机状态和数据读取位置。只保存权重通常足以做推理，却可能无法复原下一步的学习率、动量和样本顺序。恢复后先核对 step、学习率和下一批数据，再继续写入同一实验记录；否则日志看似连续，实际已经换了一条轨迹。

严格的恢复测试不是“文件能打开”，而是从同一检查点再走一步：

1. 读取相同 batch，核对前向 loss、学习率、梯度范数和参数摘要。
2. 硬件或分布式拓扑改变时可以不逐 bit 一致，但数据位置和优化器状态必须语义连续。
3. 恢复后若 loss 突跳，先停下并比较配置、样本与状态，不能直接归因于随机波动。

## 日志怎么读

```text
step=0   train_loss=4.20 val_loss=4.25  # 更新前起点
step=200 train_loss=2.10 val_loss=2.20
step=500 train_loss=1.20 val_loss=2.35
```

`step=0` 记录尚未更新参数的起点。到 step 200 时，训练和验证都改善；到 step 500 时，训练继续改善而验证变差，这是过拟合信号之一，但单次波动不足以下结论，应看重复评测和整体趋势。

一条训练曲线不能回答所有问题。最少把下面几类记录对齐到同一 step：

| 记录 | 主要回答 | 异常时先怀疑 |
|---|---|---|
| train loss | 当前训练批次是否更容易被拟合 | 数据、目标、学习率、实现 |
| val loss / 任务指标 | 改善是否迁移到开发数据 | 过拟合、切分、分布差异 |
| 学习率 | 优化器此刻迈多大一步 | 调度器、恢复位置 |
| 梯度范数 | 反向信号是否消失、爆炸或异常 | 数值范围、裁剪、异常样本 |
| tokens/s 与显存 | 系统是否稳定、高效 | 数据加载、通信、序列长度 |

它们只提供定位线索。例如梯度范数突然变大与 loss=NaN 同时出现，值得检查首个异常 batch；但单凭梯度范数不能宣布根因。

配套分镜：[训练、验证与测试：三套题](../04-图解与数字漫画/训练与验证-两套题.md)

| 现象 | 可能原因 | 下一步 |
|---|---|---|
| train/val 都不降 | 学习率、数据、实现或容量问题 | 先尝试过拟合一个 batch |
| train 降、val 升 | 过拟合或分布差异 | 检查切分、正则化、训练时长 |
| loss 为 NaN | 数值不稳定、异常数据或过大学习率 | 定位首个异常 step |
| OOM | 激活、参数或 batch 超出内存 | 先减 batch 或序列长度 |

## 先过拟合一个 batch

这是最有效的训练单元测试之一。让模型反复看同一小批样本，若 loss 无法明显下降，应先怀疑数据对齐、遮罩、模型、梯度或优化器，而不是购买更多数据。

成功过拟合一个 batch 只证明管线具备记忆这批数据的能力，不证明泛化。

## 控制训练但不由模型直接学出的量

| 名称 | 作用 | 常见误解 |
|---|---|---|
| 随机种子 | 固定初始化、采样或数据顺序等随机过程的起点 | 同一 seed 能跨硬件保证逐 bit 相同 |
| 学习率调度器 | 按 step 改变学习率，例如预热后衰减 | 调度器会替模型判断何时已经学会 |
| 正则化 | 通过约束、噪声、数据增强等减少只记训练数据的倾向 | 加正则就保证泛化 |
| 早停 | 验证指标不再改善时停止训练 | 看过测试集后决定停止仍算独立测试 |
| 混合精度训练 | 让不同张量或算子使用不同数值精度并管理缩放 | 所有计算都降成同一种低精度 |

这些都属于训练配置或超参数。比较训练方案时要记录版本和取值；否则模型差异可能只是随机性或配置差异。
