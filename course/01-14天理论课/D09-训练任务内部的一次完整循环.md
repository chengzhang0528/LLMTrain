# D09：训练任务内部的一次完整循环

> **学习导航**：这是“数据准备与模型训练”主线的局部放大；本课承接 D04 的参数更新和 D08 的训练 batch，把一个 step、周期性验证与保存连成一次训练任务；完成后应能逐行解释训练伪代码，并明确它处于完整模型项目的哪个位置。

> **主线位置**：[模型全生命周期总纲](模型训练总纲.md) -> 主线三的 D08 数据准备 -> **D09 一次训练任务** -> D10 规模化 -> D11-D12 评估与优化。标题中的“完整”只指训练任务内部动作完整，不指从问题定义到持续迭代的整个生命周期。

## 本课目标

能区分完整模型项目、一次训练任务和一个训练 step；读懂训练日志，知道何时看训练 loss、验证 loss、梯度范数、吞吐和检查点。

## 为什么要学这一课

前向、loss、反向和优化器如果只作为分散名词，就无法运行或排查训练。训练循环把它们变成有顺序、可记录、可恢复的工程过程；缺少这层理解时，loss 不降、显存溢出或验证变差都只能靠猜。

## 先分清三个尺度

| 尺度 | 包含什么 | 本课是否完整覆盖 |
|---|---|:---:|
| 完整模型项目 | 问题、基线、数据、架构、多次训练、后训练、评测、部署 | 否，见训练总纲 |
| 一次训练任务 | 固定一套数据版本、模型配置和超参数，运行许多 step，保存日志与检查点 | 是，本课主角 |
| 一个训练 step | 取 batch、前向、loss、反向、更新 | 是，训练任务反复执行的内核 |

例如 L0 的完整项目先固定 `V=8、D=4、N=2` 和训练外测试集；其中一次训练任务采用 batch 16、最多 600 step；每个 step 只处理当前 batch 并产生一次参数更新。三层都能被称为“训练”，但可得出的结论不同。

## 一个 step 怎样循环成训练任务

```python
evaluate_without_updating_parameters()
save_checkpoint(step=0)

for completed_steps in range(1, max_steps + 1):
    x, y = next_train_batch()
    optimizer.zero_grad()
    logits, loss = model(x, y)
    loss.backward()
    clip_grad_norm_if_needed()
    optimizer.step()
    scheduler.step()

    if completed_steps % eval_interval == 0:
        evaluate_without_updating_parameters()
        save_checkpoint(step=completed_steps)
```

这里的 step 表示“已经完成多少次参数更新”：`step=0` 是更新前的随机初始化或已加载起点，第一次 `optimizer.step()` 完成后才是 `step=1`。真实代码还要在循环外固定数据版本、模型结构、初始检查点、优化器、学习率计划和随机种子，并处理设备、混合精度、分布式同步与异常恢复。循环内部的主线是前向、损失、反向和更新；周期性验证与保存让这次训练任务可以比较和恢复。

| 代码动作 | 接上了哪一课 | 它产生什么 |
|---|---|---|
| `next_train_batch()` | D08 的切分与打包 | 输入 `x` 和错开一位的目标 `y` |
| `model(x, y)` | D02-D06 的模型前向 | logits 与平均 loss |
| `loss.backward()` | D04 的梯度 | 当前计算图中参与 loss 的可训练参数梯度 |
| `optimizer.step()` | D04 的参数更新 | 一组新参数 |
| `evaluate...()` | D08 的验证集（开发集） | 不更新参数的验证指标 |

## 一次训练任务的外壳

```text
任务开始：记录配置与数据版本 -> 初始化或加载检查点
任务中间：反复执行 step -> 定期验证 -> 定期保存 -> 记录异常
任务结束：按开发验证指标选候选检查点 -> 冻结方案 -> 交给冻结测试集做最终评估
```

“最后一个检查点”不必是“最好的检查点”，验证指标可能在训练后期变差。一次任务结束也不等于项目成功：候选检查点先由验证集参与选择；方案冻结后，再用未参与选择的冻结测试集检查质量、成本与安全边界。

## 日志怎么读

```text
step=0   train_loss=4.20 val_loss=4.25  # 更新前起点
step=200 train_loss=2.10 val_loss=2.20
step=500 train_loss=1.20 val_loss=2.35
```

`step=0` 记录尚未更新参数的起点。到 step 200 时，训练和验证都改善；到 step 500 时，训练继续改善而验证变差，这是过拟合信号之一，但单次波动不足以下结论，应看重复评测和整体趋势。

配套分镜：[训练、验证与测试：三套题](../04-图解与数字漫画/训练与验证-两套题.md)

| 现象 | 可能原因 | 下一步 |
|---|---|---|
| train/val 都不降 | 学习率、数据、实现或容量问题 | 先尝试过拟合一个 batch |
| train 降、val 升 | 过拟合或分布差异 | 检查切分、正则化、训练时长 |
| loss 为 NaN | 数值不稳定、异常数据或过大学习率 | 定位首个异常 step |
| OOM | 激活、参数或 batch 超出内存 | 先减 batch 或序列长度 |

## 先过拟合一个 batch

这是最有效的训练单元测试之一。让模型反复看同一小批样本，若 loss 无法明显下降，应先怀疑数据对齐、遮罩、模型、梯度或优化器，而不是购买更多数据。

成功过拟合一个 batch 只证明管线具备记忆这批数据的能力，不证明泛化。

## 梯度累积

显存只能放 batch=2，但希望每 8 个小 batch 更新一次，可以累计 8 次梯度，得到有效 batch 约 16。严格等价还取决于 loss 缩放、随机层、归一化、分布式和优化器细节，所以应称“近似获得更大有效 batch”，而非无条件完全等价。

## 控制训练但不由模型直接学出的量

| 名称 | 作用 | 常见误解 |
|---|---|---|
| 随机种子 | 固定初始化、采样或数据顺序等随机过程的起点 | 同一 seed 能跨硬件保证逐 bit 相同 |
| 学习率调度器 | 按 step 改变学习率，例如预热后衰减 | 调度器会替模型判断何时已经学会 |
| 正则化 | 通过约束、噪声、数据增强等减少只记训练数据的倾向 | 加正则就保证泛化 |
| 早停 | 验证指标不再改善时停止训练 | 看过测试集后决定停止仍算独立测试 |
| 混合精度训练 | 让不同张量或算子使用不同数值精度并管理缩放 | 所有计算都降成同一种低精度 |

这些都属于训练配置或超参数。比较训练方案时要记录版本和取值；否则模型差异可能只是随机性或配置差异。
