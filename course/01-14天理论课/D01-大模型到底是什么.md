# D01：大模型到底是什么

> **学习导航**：[模型原理总纲](模型原理总纲.md) -> **D01 参数化条件预测** -> D02 输入表示；本课建立“上下文 -> 参数化前向 -> logits -> 解码 -> 逐 token 输出”的总框架。完成后应能画出推理流程，并指出训练在哪一步写参数、推理在哪一步只读参数。

## 先记四个判断

1. **输入是本次上下文里的 token，不是直接喂给模型的“原文”。**
2. **参数来自训练；普通推理读取参数，不会因聊天而永久更新。**
3. **前向先产生 logits，再由解码策略接受一个 token。**
4. **长回答是“追加 token 后再算一轮”的循环，不是一次查出整段答案。**

## 一句话定义（第一次必看）

大语言模型可以写成：

$$
P(\text{下一个 token}\mid\text{已有 token};\theta)
$$

这行不是要求背诵的神秘公式，它压缩了四个对象：

| 公式里的部分 | 白话 | 来源或作用 |
|---|---|---|
| 已有 token | 这一次已经给模型看的上下文 | 用户消息、系统提示、历史消息和工具结果 |
| $\theta$ | 训练得到的模型参数 | 训练过程更新，普通推理默认只读取 |
| $P$ | 下一个 token 的条件概率分布 | 模型前向先产生 logits，再经归一化得到这个分布 |
| 下一个 token | 本轮将追加的一个候选 | 解码策略从分布中选择 |

教学模型 L0 使用 `V=8、D=4、N=2` 和 308 个参数。输入 `<bos> / 我 / 爱` 后，它不会从参数中查找整句，而会为 8 个词表候选计算分数。真实模型规模更大，但普通推理仍由上下文和已加载参数共同产生本轮 logits。

这里的“条件”指结果依赖已有 token；“参数化”指具体计算由一组可训练数字 $\theta$ 决定。结构规定数字怎样流动，参数决定每一步具体怎样映射。两者合起来才是可运行的模型。

### 一个 token 不是一次小计算（关心性能时再读）

$P(\text{下一个 token}\mid\cdots)$ 描述的是**这一轮交付什么结果**，不是硬件只算一个数字。对密集 Transformer，一次基础 decode 通常仍要让新位置穿过全部 Transformer Block：每层读取主要权重矩阵，Attention 还读取历史 KV Cache，MLP 继续执行大规模矩阵乘法；到 LM Head 才为整个词表产生 logits，解码代码最后只接受一个 token。

因此，**输出粒度很小，不代表计算规模很小**。GPU 的价值主要在于并行执行矩阵运算和提供更高的显存带宽；CPU 也能运行量化后的小模型，只是模型越大、速度要求越高，等待越明显。D07 的[单 token 计算高楼](D07-模型一次运行到底发生什么.md#一个-token-背后是一整栋计算高楼)会把这一轮逐层展开，并给出 7B 与 70B 的数量级估算。

## 先分清模型、架构、权重和基座

**第一次必看。**

这些词经常一起出现，但指向不同对象：

| 词 | 它是什么 | 换掉它意味着什么 |
|---|---|---|
| 语言模型（language model） | 为文本或其他符号序列建立概率、预测下一个或缺失部分的模型 | 任务仍可能是语言建模，但具体能力和接口会变化 |
| 大语言模型（LLM） | 规模较大、从大量数据训练的神经语言模型；“大”没有跨论文统一参数门槛 | 不能只凭参数量推出事实性、推理或多模态能力 |
| 神经网络 | 由多层可学习变换组成的计算系统 | Transformer 是神经网络架构的一类，不是“神经网络”的同义词 |
| 模型架构 | 规定层、连接、张量形状和信息流的计算蓝图 | 改架构会改变允许怎样计算，即使参数数量相近也不是同一个模型 |
| 模型权重 | 架构中训练得到的参数数值 | 架构不变、权重不同，模型行为仍可完全不同 |
| 基座模型 | 供后续提示、检索、微调或对齐继续使用的起始模型与检查点 | “基座”描述项目角色，不保证它一定通用、最大或未经后训练 |

一句话记忆：**架构规定有哪些旋钮和连线，权重记录旋钮当前数值，基座模型是后续工作的起点。**

### 三个角色

- **Tokenizer**：把文本切成 token，再映射为整数 ID。
- **模型参数**：训练中调整的大量数字。它们共同决定输入经过模型后得到什么 logits。
- **生成策略**：规定如何根据 logits 选择 token；贪心可以直接选最高 logit，temperature、top-k、top-p 等配置通常会先调整 logits 或形成候选分布，再决定是否随机采样。

“大”通常指参数量、训练数据和训练计算的规模大，不代表模型必然正确，也不代表所有参数都保存了一条可直接查询的事实。

大语言模型至少包含两部分：**网络结构**规定数字怎样流动，**训练参数**决定具体变换。上下文经计算得到 logits，再转成下一个 token 的候选概率。模型做的是基于所学规律的条件预测，不是从内部数据库逐句检索原文。

## 训练与推理不是一回事

**训练**时必须有可计算的训练目标，但不一定有人逐条写“参考答案”。语言模型预训练常把原始文本中的下一个 token 当作监督信号；SFT 使用整理过的示范回答；偏好优化和强化学习还可能使用比较、奖励或验证器信号。根据这些目标和信号，训练过程计算 loss 或相应优化目标，并据此更新参数。

**推理**时通常不更新参数。模型根据当前上下文反复预测和追加 token。把一段资料放入上下文能临时影响回答，但不等于模型已经把资料训练进参数。

| 阶段 | 使用什么信号 | 更新参数 | 常见输出 |
|---|---|:---:|---|
| 训练 | token 目标、示范、偏好、奖励或验证器等 | 是 | loss、训练指标、检查点 |
| 验证 | 留出的标签、目标或任务指标 | 否 | 验证 loss、指标 |
| 推理 | 当前输入与已加载参数；可另接检索或工具结果 | 否 | 生成文本或结构化输出 |

## 它不是什么

- 不是实时更新的百科数据库，知识可能过时或混杂。
- 不是每次都按固定规则查到唯一答案的普通程序。
- 不能仅凭流畅语气证明事实正确。
- 是否具有意识属于哲学和科学争议，不能从“会对话”直接推出结论。

## 站内观察

观察页面给出的候选 token 分布，再在纸上或浏览器答题区预测哪一个会被选中，并检查概率之和是否为 1。这里练习的是读懂分布，不需要调用任何模型或外部服务。
