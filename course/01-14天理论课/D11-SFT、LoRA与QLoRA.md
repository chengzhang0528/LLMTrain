# D11：让基座适应任务：SFT、LoRA 与 QLoRA

> **学习导航**：[模型全生命周期总纲](模型训练总纲.md) -> D10 预训练检查点 -> **D11 SFT / LoRA / QLoRA** -> D12 对齐与评测；本课比较起点、训练信号、更新范围和显存账本。完成后应能选方法、手算多层 LoRA 参数量，并沿前向、梯度与部署路径定位适配器错误。

## 先记四个选择判断

1. **知识过期先考虑检索或数据源，不要默认微调。**
2. **SFT 改目标行为；全参数、LoRA、QLoRA 的主要差异是更新范围与资源账本。**
3. **LoRA 冻结基座参数，但前向和反向仍要经过基座计算。**
4. **训练成功还不等于交付成功；适配器、基座、tokenizer 和合并方式必须版本匹配。**

## 微调先看起点、目标和更新范围

**第一次必看。**

**微调（fine-tuning）** 是从已有模型权重出发，用较小或更聚焦的数据继续训练。它描述“从已有模型继续训练”，不自动说明数据类型、训练目标或更新多少参数。

| 词 | 起点 | 更新范围 | 与其他词的关系 |
|---|---|---|---|
| 全参数微调 | 已有基座模型 | 通常更新全部模型权重 | 成本高，表达自由度也更大 |
| 参数高效微调（PEFT） | 已有基座模型 | 只更新少量新增或选定参数 | LoRA 是 PEFT 的一种，不是全部 PEFT |
| 适配器 | 插入或附加在基座上的小型可训练模块 | 通常只训练适配器 | LoRA 适配器用低秩矩阵表达权重增量 |
| 监督微调（SFT） | 已有模型 | 可全量更新，也可用 PEFT | “监督”说明数据和目标，“全量/PEFT”说明更新范围 |

**后训练**是更大的阶段集合，可包含 SFT、偏好优化、强化学习、校准和安全训练；微调是继续更新模型的一类动作。二者有重叠，但不能把所有后训练都等同于 SFT，也不能把继续预训练等同于监督微调。

## 五种训练动作（选方法时必看）

| 方法 | 主要数据 | 更新什么 | 适合目标 |
|---|---|---|---|
| 从零预训练 | 大规模预训练语料，目标通常由数据自身构造 | 全部参数 | 建立基础语言模型 |
| 继续预训练 | 领域预训练语料，目标通常由数据自身构造 | 通常全部参数 | 适应领域语言分布 |
| 全参数 SFT | 指令-回答示例 | 全部参数 | 调整行为、格式、任务能力 |
| LoRA SFT | 指令-回答示例 | 通常主要更新小型低秩适配器 | 低成本行为适配 |
| QLoRA SFT | 同上 | 通常主要更新适配器；基础权重以低比特冻结存储 | 更节省基础权重内存 |

SFT 的 loss 通常仍是 token 级交叉熵，只是数据被组织成指令和理想回答。实现会选择哪些 token 计入 loss，例如只训练 assistant 部分。

“主要更新适配器”描述的是常见配置，不是硬性限制。具体实现还可以训练 bias、输出头或选定模块，因此比较实验时应记录实际可训练参数，而不能只看方法名称。

## 需求到方法（第一次必看）

“模型答得不好”还不是训练目标。先把差距落到稳定对象上：

| 需求 | 更像缺什么 | 先做的低成本基线 | 何时再考虑训练 |
|---|---|---|---|
| 每周更新的政策且必须引用 | 当前外部知识 | RAG、版本过滤、引用核验 | 检索正确但模型仍稳定违背证据 |
| 输出固定 JSON 字段 | 格式与约束 | Schema、受约束解码、提示 | 基线在代表性样本上仍频繁失败 |
| 学会领域术语和表达分布 | 领域表示与语言模式 | 提示、术语表、检索 | 有足量合规语料和独立评测时继续预训练 |
| 按统一客服风格完成任务 | 稳定行为 | 少样本提示和规则 | 有高质量示范且行为差距可复现时做 SFT |
| 在两个可接受回答中稳定偏向更好者 | 偏好边界 | 明确量表与人工对照 | 偏好数据一致、奖励和最终评测可分离时 |

**没有可靠开发评测集、合规数据或可复现失败时，先停止训练方案。**这张表不是唯一答案，而是防止把知识、格式、工具流程和模型能力全部塞进“微调”一个词里；方法选择之后仍要与不训练的基线公平比较。

## SFT 样本与 loss（准备数据时必看）

一条聊天样本可以被组织为：

```text
<system> 你是客服助手
<user>   怎样申请退款？
<assistant> 请先提供订单号……
```

模型前向时通常仍看到完整上下文；训练实现可以只让 assistant 回答部分计入 loss，把 system、user 和 padding 位置设为忽略。这样做的含义是“利用前文预测回答”，不是让模型学习去复述用户问题。

若数据管线误把所有 token 都计分，模型会同时被要求模仿系统提示和用户文本；若把回答开头或结束 token 错误 mask，目标又会缺失。SFT 数据检查因此至少要抽样显示原文、token、角色边界和 loss mask，而不能只统计样本条数。

## LoRA 核心（使用 LoRA 时必看）

先看一个缩小后的形状例子。假设原权重矩阵 `W` 是 `4 × 4`，共有 16 个位置。若 LoRA 的中间秩 `r=1`：

| 矩阵 | 形状 | 包含的数 | 作用 |
|---|---:|---:|---|
| `A` | `1 × 4` | 4 | 先把 4 个输入坐标压到 1 个中间坐标 |
| `B` | `4 × 1` | 4 | 再把 1 个中间坐标展开回 4 个输出坐标 |
| `BA` | `4 × 4` | 由 `A`、`B` 共同决定 | 形成与 `W` 同形状的更新量 |

这个简化例子只需训练 `4+4=8` 个数，而不是直接训练一份新的 16 个数更新矩阵。真实模型的 $d$ 很大，$r$ 通常远小于 $d$，节省会更明显。

| 符号 | 对象类型 | 本节含义 |
|---|---|---|
| $W$ | 大矩阵 | 冻结的原始权重，`W` 常取自 weight |
| $A,B$ | 两个小矩阵 | 共同生成低秩更新；不同资料可能交换 A、B 的命名 |
| $BA$ | 大矩阵 | 与 $W$ 形状相同的更新量 |
| $s$ | 标量 | 控制更新量的缩放；常见实现取 $s=\alpha/r$ |
| $d,r$ | 整数 | 原空间宽度与较小的中间秩 |

这些字母可以改名，不能改变的是矩阵乘法的形状兼容关系，以及 $BA$ 必须与 $W$ 同形状才能相加。

原权重矩阵 `W` 冻结，把两个小矩阵相乘后加到它上面：

$$
W' = W + sBA
$$

这里要分开三个事实：

1. **缩放口径**：常见实现取 $s=\alpha/r$；资料也可能把缩放吸收到 $A$、$B$ 或学习率约定中，$\alpha BA$ 不是唯一写法。
2. **矩阵形状**：若原矩阵为 $d\times d$，可令 $A$ 为 $r\times d$、$B$ 为 $d\times r$。
3. **秩上限**：输入先到 $r$ 维中间空间再回到 $d$ 维，所以 $BA$ 的秩最多为 $r$。

因此，“LoRA 的核心”不是记住字母 A 和 B，而是：冻结大矩阵 $W$，只训练两个带有小中间维度 $r$ 的矩阵，再把它们生成的更新加回 $W$。

| 删项或固定值 | 直接后果 |
|---|---|
| 令 $A=0$ 或 $B=0$ | $BA=0$，适配器此刻不改变前向；若两者都以零初始化，第一步两边也都收不到有效梯度，因此常见做法只让其中一边为零 |
| 去掉 $A$ 或 $B$ | 失去“先到 $r$ 维、再回输出维”的低秩分解；若改成直接训练一份与 $W$ 同形的更新，就变成另一种参数化方案 |
| 令 $s=0$ | 无论 $A、B$ 学到什么，更新都被乘成零 |
| 令 $s=1$ | 数学上仍成立，但采用了不同缩放口径；不能再把使用 $\alpha/r$ 得到的学习率与幅度经验原样套用 |
| 同时训练 $W$ | 变成“全参数更新加 LoRA 分支”，不再拥有冻结基座带来的训练状态节省和清晰的适配器隔离 |

几何上，可以把它理解成：全参数微调可直接学习一般形状的更新矩阵；LoRA 学习 $A$、$B$，并令 $\Delta W=BA$，所以这次更新的秩最多为 $r$。$A$、$B$ 的方向也会随训练改变，并非预先指定一个固定子空间；受限的是最终更新矩阵的秩和可训练自由度。原权重矩阵本身不会因此变成低秩，低秩限制也不保证能表达任务所需的所有更新。

低秩与数值幅度是两回事。一个低秩更新仍可能有很大的范数；一个满秩更新也可能数值很小。秩回答“有多少独立方向”，范数回答“总体幅度多大”。

$$
N_{LoRA}=r d_{in}+d_{out}r=r(d_{in}+d_{out})
$$

第一项 $r d_{in}$ 数的是 $A\in\mathbb{R}^{r\times d_{in}}$，第二项 $d_{out}r$ 数的是 $B\in\mathbb{R}^{d_{out}\times r}$。少一项就等于漏记一个可训练矩阵；只算一个目标层也不能代表整模型，还要按实际 `target_modules` 和层数逐项求和。

假设一个教学模型有 32 层，每层的 `q_proj`、`k_proj`、`v_proj`、`o_proj` 都是 `4096×4096`，统一使用 `r=8`：

| 统计范围 | 算式 | 可训练参数 |
|---|---:|---:|
| 一个投影矩阵 | `8×4096 + 4096×8` | 65,536 |
| 一层四个注意力投影 | `65,536×4` | 262,144 |
| 32 层注意力投影 | `262,144×32` | 8,388,608 |

若只适配每层的 `q_proj` 和 `v_proj`，账本会减半为 4,194,304；若再适配 MLP，必须按 MLP 各矩阵自己的输入、输出维度逐项相加，不能继续套 `4096×4096`。因此配置里的 `target_modules`、层数和每个矩阵形状，与 `r` 一样会直接改变参数量。

这 838 万个数只是适配器参数。它不能推出训练总显存，也不能证明效果足够；它回答的是“优化器允许改变多少个坐标”。

```formula-story
  "counterfactual": { "label": "拿掉 Wx", "text": "这不再是对基座模型的小更新，而是只剩一条秩受限映射，能力边界完全不同。" },

```

$$
y=Wx+sB(Ax)
$$

训练时，两条分支都参与前向。冻结的 $W$ 仍要计算 `Wx`，其数值也会影响上一层收到的梯度；“冻结”只表示不为 $W$ 累积要更新的梯度，也不为它创建本轮优化器更新。适配器分支则要保留反向所需状态，并计算 $A$、$B$ 的梯度。

| 对象 | 参与前向 | 需要把梯度继续传向更早层 | 本轮被优化器更新 |
|---|---|---|---|
| 冻结基座权重 `W` | 是 | 是，通过线性运算传递 | 否 |
| LoRA 矩阵 `A`、`B` | 是 | 是 | 是 |
| 输入与中间激活 | 是 | 训练时通常要保留或重算 | 不是模型参数 |

这解释了一个常见误判：LoRA 的可训练参数很少，训练却仍可能因长序列激活而显存不足。参数冻结减少了梯度和优化器状态，却没有删除基座前向、层间激活和反向传播。

## QLoRA 量化范围（使用 QLoRA 时必看）

QLoRA 将冻结的基础模型权重以 4-bit 等形式存储，同时训练 LoRA 适配器。矩阵运算时，量化权重通常会按块反量化到所选计算精度，再参与乘法；“4-bit 存储”不等于所有算术都直接以 4-bit 完成。总显存还包含激活、适配器梯度、优化器状态和工作区，不能用“4/16”直接推出总显存恰好减少 75%。

量化可能带来质量、速度、硬件和算子支持方面的权衡；“几乎无损”必须绑定模型、数据、指标和配置。

### 用 10 亿参数做一次 QLoRA 显存账本

下面只用于区分存储对象，不是任何框架的显存承诺。假设冻结基座有 10 亿参数，适配器有 1000 万参数，适配器和梯度用 BF16，Adam 的两份矩状态用 FP32：

| 对象 | 教学估算 | 约占空间 |
|---|---:|---:|
| 4-bit 基座原始数值 | `10亿×0.5 byte` | 0.50 GB |
| BF16 适配器 | `1000万×2 bytes` | 0.02 GB |
| BF16 适配器梯度 | `1000万×2 bytes` | 0.02 GB |
| Adam 两份 FP32 矩状态 | `1000万×2×4 bytes` | 0.08 GB |

表中小计约 0.62 GB，但真实值一定更高：4-bit 分块还需要量化尺度等元数据；算子会创建反量化或矩阵乘工作区；训练还要保存或重算激活；不同优化器也可能保留主权重或使用分页、低比特状态。正确结论不是“QLoRA 总显存等于 0.62 GB”，而是先把冻结权重、可训练状态、激活和临时工作区分账，再用目标框架实测峰值。

若序列长度翻倍后显存大涨，而适配器参数量没有变化，优先检查激活和注意力工作区；若更换 `target_modules` 后常驻显存上升，才更像可训练参数、梯度和优化器状态增加。

## LoRA 从训练到部署还要做三次选择

1. **适配哪些模块**：只适配注意力投影，还是也覆盖 MLP；目标不同会改变可训练参数和表达能力。
2. **用多大的秩与缩放**：更大的 `r` 提供更多更新自由度，也增加参数、显存和过拟合空间；必须通过开发评测比较。
3. **怎样交付适配器**：可以保留“基座 + 适配器”便于切换，也可以在兼容条件下合并权重便于部署。无论哪种方式，都要绑定正确的基座版本和 tokenizer。

多个适配器共用同一基座能节省存储，但不会自动解决并发、路由和相互兼容问题。加载错基座、重复合并或遗漏缩放，都可能让“文件存在”却得不到训练时行为。

### 合并前后怎样证明交付一致

不要只检查文件能否加载。冻结一组短输入，在相同 tokenizer、相同基座提交、相同计算精度和关闭随机采样的条件下，分别运行“基座 + 未合并适配器”和“已合并权重”：

1. 记录基座与适配器标识、`target_modules`、`r`、`alpha` 和是否已合并。
2. 比较同一位置的 logits 或固定解码输出；浮点合并可能有微小舍入差异，因此要预先给出数值容差。
3. 再用代表性回归集比较任务指标，确认导出、量化或推理引擎没有引入额外退化。

若未合并路径正确而合并路径明显偏离，优先检查是否重复加了 $Delta W$、遗漏 $s=\alpha/r$、矩阵方向与框架约定是否相反，以及合并后是否又加载了一次适配器。若两条路径都错，先核对基座和 tokenizer 版本，而不是继续调整采样温度。
