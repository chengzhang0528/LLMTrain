# D12：让行为可控，让改进可测

> **学习导航**：承接 D11 的监督微调；本课学习偏好与奖励怎样变成参数更新信号，以及怎样用独立评测约束奖励投机；完成后应能手算一组 DPO/GRPO 信号，把模糊要求改写成可执行标准，并沿分层证据定位“训练分数提高、真实任务变差”。

> **主线位置**：[模型全生命周期总纲](模型训练总纲.md) -> 主线四的 D11 行为优化 -> **D12 独立评测** -> 主线五的 D13 推理、部署与应用。完成本课后先判断模型是否达到上线门槛，完整生命周期还要继续经过部署、监控和反馈迭代。

## 本课目标

能解释 SFT 之后为什么还会做偏好优化，手算偏好间隔和组内相对优势，并设计独立评测避免“只优化分数”。

## 先记四个判断

1. **训练信号不同，改变的行为也不同：示范教目标行为与格式，偏好教取舍，奖励或验证器教可检查结果。**
2. **DPO、GRPO 等是优化方法，不是“更聪明”的保证书。**
3. **奖励分数必须拆出硬门槛和失败类型，不能只看平均值。**
4. **评测要同时看任务、切片、回归、安全和独立测试证据。**

## 先把对齐和强化学习的角色排好

**第一次必看。**

**模型对齐**是让模型行为更符合明确的人类意图、任务规范和安全边界的过程，不是一次算法，也不等于让模型“拥有所有人的共同价值”。

| 角色 | 它提供什么 | 不要混淆 |
|---|---|---|
| 偏好数据 | 同一输入下候选输出的选择、排序或理由 | 不一定是真值，也可能带有标注偏差 |
| 奖励模型 | 根据输入和输出估计一个可优化分数 | 不是最终裁判，也可能被投机 |
| 策略模型 | 当前正在产生输出、并被训练改变的模型 | 不是部署策略或解码策略的同义词 |
| 生成轨迹（rollout） | 从初始状态出发，记录策略产生的 token 或动作，以及环境或验证器返回的观察、结果、奖励 | 最终答案相同不代表中间轨迹相同 |
| 验证器 | 用规则、程序、工具结果或模型检查输出 | 能验证的范围不自动覆盖真实任务全部要求 |
| 优势估计 | 衡量某个动作或输出相对参考水平好多少 | 不是原始奖励本身，也不是绝对正确率 |

**强化学习**利用带奖励的轨迹数据优化策略；轨迹可以在训练中在线采样，也可以来自预先收集的数据。GRPO、PPO 等是具体策略优化方法；RLHF 描述使用人类反馈的一类流程；RLVR 强调奖励可由程序或明确验证器产生。它们处在不同分类轴上，不能平铺成互斥选项。

## 同一个任务会产生不同训练信号

以“用户缺少订单号时，先追问，不得编造退款进度”为例，四类材料承担不同职责：

| 材料 | 示例 | 直接告诉模型什么 | 仍需防什么 |
|---|---|---|---|
| SFT 示范 | 问题 + 一条理想追问 | 怎样生成一份合格回答 | 只会模仿模板，未覆盖变体 |
| 偏好对 | 回答 A 追问订单号，回答 B 编造进度；A 更好 | 同一输入下更偏向哪种行为 | 标注者偏好不一致、长度偏好 |
| 可验证奖励 | 是否出现合法订单号、是否调用了查询工具 | 哪些结果能被程序检查 | 学会钻格式或工具环境漏洞 |
| 独立测试 | 新用户表达、越权订单、工具超时 | 改进能否迁移到未参与训练的场景 | 测试样本过少或继续被用于调参 |

这些材料不能互相替代。示范告诉模型“照什么做”，偏好告诉它“两个候选更喜欢哪个”，奖励把部分目标变成可优化分数，独立测试才负责检查有没有真的解决任务。若四者使用同一批样本和同一条规则，模型很容易只学会迎合验收口径。

## 对齐在解决什么

预训练模型擅长续写，不自动等于有帮助、遵循指令或符合安全要求。后训练用示范、偏好比较、可验证奖励和安全数据塑造行为。

### RLHF 的典型高层流程

1. SFT 得到能按指令回答的模型。
2. 收集人类对多个回答的偏好。
3. 训练奖励模型近似偏好。
4. 用强化学习优化策略，同时常用参考模型约束偏离程度。

这是典型流程，不是唯一实现，也不保证“对齐了所有人类价值”。

### DPO 与 GRPO

第一次学习不需要背完整论文推导，但必须能追踪最小数字账本：准备多个候选输出，依据人类偏好或可验证结果产生训练信号，再检查模型是否把分数漏洞当成捷径。DPO、GRPO 是实现这条结构的不同方法名。

- **DPO** 直接利用偏好对优化策略目标，避免显式训练并在线使用单独奖励模型的完整 RLHF 流程。
- **GRPO** 是一类基于同组多个输出相对奖励来估计优势的策略优化方法。它常见于可验证任务和推理训练讨论，但不是对所有任务普遍优于其他方法的定律。

## DPO：偏好对怎样产生一个更新方向

**学习优化算法时再读。**

对同一个输入 $x$，偏好数据给出获选回答 $y_w$ 和落选回答 $y_l$。先分别计算当前策略与参考策略对整段回答的对数概率，再比较“当前策略比参考策略多偏爱获选回答多少”：

$$
z=\beta\left[(\log \pi_\theta(y_w|x)-\log \pi_\theta(y_l|x))-(\log \pi_{ref}(y_w|x)-\log \pi_{ref}(y_l|x))\right]
$$

DPO 的单对损失可写为 $-\log \sigma(z)$。这里不要求记住字母，先算一个例子：

| 项 | 获选回答 | 落选回答 | 获选减落选 |
|---|---:|---:|---:|
| 当前策略对数概率 | -2.0 | -3.0 | 1.0 |
| 参考策略对数概率 | -2.2 | -2.8 | 0.6 |

若 $\beta=0.5$，则 $z=0.5\times(1.0-0.6)=0.2$，$\sigma(0.2)\approx0.55$，损失约为 $-\log 0.55\approx0.60$。优化会推动 $z$ 增大，也就是让当前策略相对参考策略更偏向获选回答。

注意这里使用整段回答的对数概率，通常由回答中计分 token 的 log probability 相加得到。回答长度、mask、参考模型版本和 $\beta$ 都会改变数值；只看到“获选回答概率更大”还不够，因为 DPO 比较的是当前策略相对参考策略的偏好变化。若获选与落选标签受长度偏好或标注噪声影响，公式会忠实放大错误信号。

## GRPO：原始奖励怎样变成组内相对优势

**学习优化算法时再读。**

假设同一问题采样四个回答，验证器给出奖励 `[1, 1, 0, -1]`。最简单的组内中心化先算均值：

$$
\bar r=(1+1+0-1)/4=0.25
$$

各回答减去均值得到相对信号 `[0.75, 0.75, -0.25, -1.25]`。若再除以这组奖励的总体标准差，标准差约为 $0.83$，归一化后约为 `[0.90, 0.90, -0.30, -1.51]`。

| 回答 | 原始奖励 | 减去组均值 | 此时的含义 |
|---:|---:|---:|---|
| A | 1 | 0.75 | 比同组平均好，增加其动作概率的信号 |
| B | 1 | 0.75 | 与 A 同档，不表示两条推理过程同样可靠 |
| C | 0 | -0.25 | 虽非最低分，仍低于本组基线 |
| D | -1 | -1.25 | 明显低于本组基线 |

真实 GRPO 实现还会涉及 token 级概率比、裁剪、KL 约束、数值稳定项和具体优势口径；不同实现不一定恰好使用上面的总体标准差。这个小账本只说明关键机制：训练用的不只是绝对奖励，还取决于同组其他回答。若一组回答全都同分，组内相对信号可能接近零；若验证器把格式捷径打成高分，相对优势同样会奖励捷径。

## 奖励分项必须保留硬门槛

假设客服奖励写成“事实 70% + 格式 20% + 简洁 10%”。一个编造退款到账、但格式完美且很简短的回答，可能得到 `事实0 + 格式0.2 + 简洁0.1 = 0.3`；另一个事实正确但格式略有问题的回答可能得到 `0.7 + 0 + 0.1 = 0.8`。加权分数能排序普通质量，却仍可能让低频严重错误被其他分项抵消。

更稳妥的设计把目标拆成两类：权限越界、隐私泄露和伪造支付状态是硬门槛，命中就拒绝样本或施加独立惩罚；在通过硬门槛的回答中，再比较事实支持、任务推进、格式和表达。每一分项还要有独立测试，防止模型只学会让总分变高。

奖励曲线上升时，至少同步看四层证据：原始分项奖励、独立验证器、未参与训练的人工抽样、以及按任务与风险切开的回归集。若只有训练奖励上涨，结论只能是“模型更会优化当前奖励”，不能写成“真实能力提高”。

### 在策略蒸馏：密集教师信号也有可学习性条件

另一条后训练路线是让学生先生成自己的轨迹，再由教师对学生实际访问的每个前缀给出下一 token 分布。这是在策略蒸馏的一种常见形式：它能提供比最终对错更密的信号，也减少只在固定教师答案上训练造成的状态错位。

“教师更强”不保证学生学得更多。研究显示，双方高概率 token 是否兼容、教师是否提供新增能力，都会影响训练；长轨迹尾部的逐 token 信号还可能失真。完整证据见[在策略蒸馏深读](../06-拓展知识库/在策略蒸馏深读/)。

算法名称不能替代奖励和数据设计。奖励有漏洞时，模型可能学会投机，即 reward hacking。

可验证任务也不等于奖励天然可靠。代码执行器、数学判题器和搜索环境可以成为 agent harness 中的工具或环境；完整 harness 还包括系统提示、执行循环、上下文管理和错误恢复。环境若过窄、超时策略不一致或答案可被格式漏洞绕过，模型可能优化“过判题器”而不是解决真实任务。训练奖励与最终评测应保持独立。

## 评测不是只跑一个排行榜

**第一次必看。**

**模型评测**是在固定样本、规则、预算和版本下收集质量、成本与风险证据。相关材料各自回答不同问题：

| 名称 | 负责什么 | 不能证明什么 |
|---|---|---|
| Ground truth（真值） | 当前任务认可的参考答案、标签或可验证事实 | 开放问题一定存在唯一无争议答案 |
| Benchmark（评测基准） | 固定任务、数据和计算口径，便于比较 | 排名能代表所有真实场景 |
| 消融实验 | 一次移除或替换一个关键机制，缩小贡献归因 | 组合系统中的单次消融能证明完整因果 |
| LLM-as-a-Judge | 用模型按量表扩展评审 | 裁判模型天然无偏且等同人工真值 |
| 回归测试集 | 检查新版本是否破坏旧能力和高风险边界 | 只测新任务就足以发现灾难性遗忘 |
| 数据卡 / 模型卡 | 记录数据或模型的来源、版本、用途、指标和限制 | 填了文档就自动完成审计和复现 |

## 评测金字塔

1. **训练和验证 loss**：检查学习与泛化趋势。
2. **任务指标**：准确率、F1、pass@k、人工规则等。
3. **固定行为集**：关键提示、边界情况、拒答与格式。
4. **人工评测**：依据明确量表比较可用性。
5. **线上监测**：真实分布、延迟、成本和事故。

LLM-as-a-Judge 可扩展评测，但可能受位置、措辞、长度、模型家族和自我偏好影响，应随机交换顺序、隐藏模型身份、校准人工样本并报告不确定性。

### 裁判校准要落到一张对照表

假设专家先判定 100 条样本，其中 40 条合格、60 条不合格。模型裁判把 50 条判为合格：35 条确实合格，15 条其实不合格；它还漏掉 5 条专家认可的合格回答。

| | 专家：合格 | 专家：不合格 |
|---|---:|---:|
| 裁判：合格 | 35 | 15 |
| 裁判：不合格 | 5 | 45 |

这时总体一致 80 条，一致率为 80%；但裁判判“合格”的 50 条里只有 35 条确实合格，合格判定的精确率是 70%。如果这 15 条误放行集中在越权场景，即使总体一致率看起来不错，也不能让裁判独立承担发布门禁。

校准不是只做一次。更换裁判模型、提示、输出顺序、任务语言或回答长度分布后，都要重新抽样对照；同时保留分歧样本和专家裁决理由，才能判断偏差来自量表含糊、裁判位置偏好，还是某个风险切片能力不足。

## 把“回答要好”拆成可判定量表

继续使用退款助手。一个可执行量表可以把要求拆开：

| 维度 | 可检查的通过条件 | 失败严重性 |
|---|---|---|
| 事实与状态 | 没有工具结果时不得声称退款已到账 | 严重，单独设红线 |
| 权限 | 只能查询当前用户有权访问的订单 | 严重，不能被平均分抵消 |
| 任务推进 | 缺订单号时明确追问所需字段 | 普通质量门槛 |
| 表达 | 不添加无关承诺，语句清楚 | 可与其他质量项分别统计 |
| 成本与延迟 | 在固定模型、预算和超时口径下达标 | 系统门槛 |

先定义样本、允许使用的信息和工具，再定义每个维度怎样判定。安全红线用“必须全部通过”或独立上限，普通质量可以报告分项比例；不能把一次越权和几个措辞偏好平均成一个看似不错的总分。

开放回答可能没有唯一文本真值，但仍可检查关键事实、证据支持、禁止行为和任务结果。此时人工量表或模型裁判要用一小批专家样本校准，并记录评审之间的分歧，而不是把裁判输出当成客观真理。

## 先看失败分层，再看总分

假设新模型总通过率从 82% 升到 86%，还不能直接宣布上线。至少把样本按任务、难度、语言、风险和是否需要工具分层，再比较失败迁移：

- 若普通问答提高，但唯一的越权测试从通过变成失败，应阻止发布。
- 若只在很长回答上得分更高，先检查裁判是否偏爱长度。
- 若同一问题多次采样波动很大，报告分布或置信区间，不只报最好一次。
- 若改动同时包含数据、提示和奖励，不能把收益单独归因给某个算法名。

总分用于概括，失败切片用于决策。上线门槛应在查看测试结果前写明；看完冻结测试集再修改阈值，会把测试集重新变成开发集。

## 评测纪律

- 训练集、开发集、测试集职责分离。
- 比较模型时统一提示、解码参数和预算。
- 报告样本数、均值之外的波动或置信区间。
- 防止测试数据污染训练数据；旧 Benchmark 高分不自动代表真实新任务。

读技术报告时，再逐项追问：评测版本、提示模板、采样参数、最大输出长度、工具权限、推理预算、样本是否污染、裁判如何校准、失败样本是否公开。缺少这些条件的单个榜单数字，只能作为有限证据。

阅读论文和前沿页面时，会看到一组证据标签：`[一手事实]`、`[作者实验]`、`[作者主张]`、`[教学推导]`、`[工程估算]`、`[待核查]`。它们帮助你区分信息来自哪里、能核验到什么程度；不要把它们当成简单的“强弱排名”，也不要把教学解释误认成论文结论。

## 安全不是一项总分

分别测试隐私泄露、提示注入、有害指导、偏见、越权工具调用和不可逆操作。一个平均分会掩盖低频高损害问题。
