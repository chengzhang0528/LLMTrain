# 术语速查

课程正文中的核心术语与本页保持同一份定义。每个词条都包含一句话解释、真实沟通示例和最常见的误解；沟通示例演示如何在讨论、评审或排错中准确使用术语，不是推荐配置或固定标准。容易混淆为函数、数值、向量、形状或计数的术语，还会在解释中补一个具体对象示例。英文术语会同时显示美式音标，点击旁边的播放按钮即可朗读；浏览器不支持语音合成时，会自动播放课程自带的离线发音。

| 术语 | 一句话解释 | 不要误解为 |
|---|---|---|
| <span id="term-token"></span>**token（词元）** | 模型序列中的一个处理单元；文本、图像和音频 token 的形成方式可以不同 | 必然等于一个字或单词，或所有模态共用文本 tokenizer |
| <span id="term-token-id"></span>**token ID** | token 在固定词表中的离散整数索引。例：“猫”的 token ID 在某词表中可以是 `238` | 是连续语义数值，编号大小代表语义远近 |
| <span id="term-tokenizer"></span>**tokenizer（分词器）** | 把文本切成 token，并在 token 与整数 ID 之间转换的规则和词表 | 模型自己临时决定的切词方式 |
| <span id="term-bpe"></span>**BPE（Byte Pair Encoding，字节对编码）** | 从基本单元出发，反复合并语料中常见的相邻单元，并保存规则供编码使用 | 每次聊天都会根据当前句子重新学习合并规则 |
| <span id="term-vocab"></span>**vocab（词表）** | tokenizer 可以表示的 token 集合 | 模型掌握的全部知识 |
| <span id="term-discrete-representation"></span>**discrete representation（离散表示）** | 取值来自有限或可数候选集合的表示；token ID 或码本索引的编号大小通常没有距离意义 | 整数编号天然是连续语义坐标，或离散表示一定不能参与神经网络计算 |
| <span id="term-continuous-representation"></span>**continuous representation（连续表示）** | 用实数坐标描述对象的表示；计算机中实际是有限精度浮点数，因此“连续”是数学近似 | 每个坐标都有固定人类语义，或连续表示一定比离散码保留更多信息 |
| <span id="term-parameter"></span>**parameter（参数）** | 模型计算中保存的数值；训练只更新其中被允许学习的部分。例：某个权重可以是 `-0.017` | 所有参数每次都会更新，或一个参数对应一条事实 |
| <span id="term-trainable-parameters"></span>**trainable parameters（可训练参数）** | 当前训练中允许接收梯度并被优化器更新的参数子集；某一步也可能因条件路由或未被使用而没有梯度 | 等于总参数量，或冻结参数不参与前向 |
| <span id="term-language-model"></span>**language model（语言模型）** | 为文本或其他符号序列建立概率，预测下一个、缺失或指定位置内容 | 必然是聊天机器人，或只能处理自然语言文字 |
| <span id="term-large-language-model"></span>**large language model（LLM，大语言模型）** | 规模较大、从大量数据训练的神经语言模型；“大”没有统一参数门槛 | 参数更多就自动更真实、更会推理，或所有 AI 都是 LLM |
| <span id="term-neural-network"></span>**neural network（神经网络）** | 由多层可学习变换组成、通过训练调整参数的计算系统 | 会像人脑一样逐条存取记忆，或 Transformer 是唯一网络 |
| <span id="term-model-architecture"></span>**model architecture（模型架构）** | 规定层、连接、张量形状和信息流的计算蓝图 | 就是权重文件，或参数量相同就表示架构相同 |
| <span id="term-model-weights"></span>**model weights（模型权重）** | 架构中由训练得到、推理时读取的参数数值 | 一项权重对应一条事实，或权重包含完整服务配置 |
| <span id="term-base-model"></span>**base model（基座模型）** | 在项目中作为提示、检索、微调或对齐起点的模型与检查点 | 必然未经后训练、规模最大或适合所有任务 |
| <span id="term-foundation-model"></span>**foundation model（基础模型）** | 在广泛数据上训练、可适配多种下游任务的模型类别 | 一定通用、开放，或“基础”只表示参数更大 |
| <span id="term-training-sample"></span>**training sample（训练样本）** | 一次训练可处理的输入与目标或监督信息单元 | 一行文本必然是独立样本，或必须由人工回答 |
| <span id="term-dataset"></span>**dataset（数据集）** | 按任务、来源和用途组织的一组样本 | 只是一个文件，或样本越多就一定越好 |
| <span id="term-corpus"></span>**corpus（语料）** | 用于语言分析或训练的大规模文本或多模态材料集合 | 天然干净、有授权并已包含任务标签 |
| <span id="term-training-label"></span>**training label（训练标签）** | 作为预测目标或计分依据的类别、token、数值或结构 | 必须人工填写，或永远代表无争议真值 |
| <span id="term-data-annotation"></span>**data annotation（数据标注）** | 为原始样本补充类别、答案、边界、偏好等信息 | 标注者必然一致，或完成标注就没有偏差 |
| <span id="term-training-objective"></span>**training objective（训练目标）** | 规定哪些预测或行为获得更低损失或更高奖励的数学目标 | 等同真实世界全部目标，或 loss 低就证明产品成功 |
| <span id="term-supervision-signal"></span>**supervision signal（监督信号）** | 告诉训练过程什么输出更符合目标的信息，可来自标签、数据自身、偏好或奖励 | 必须人工逐条写答案，或信号一定正确 |
| <span id="term-self-supervised-learning"></span>**self-supervised learning（自监督学习）** | 从原始数据自身构造预测目标，如用后一个 token 监督当前位置 | 等于没有训练目标，或不需要数据治理 |
| <span id="term-forward-pass"></span>**forward pass（前向传播）** | 按当前参数从输入逐层计算到预测、logits 或任务输出 | 执行前向就会更新权重，或只发生在推理阶段 |
| <span id="term-activation"></span>**activation（激活值）** | 某层或算子对当前输入产生的中间数值，依赖输入和当前参数。例：一个位置的 activation 可以是形状为 `(1, 4096)` 的向量 | 等同激活函数、模型权重或固定不变的知识 |
| <span id="term-decode-phase"></span>**decode phase（解码阶段）** | prefill 之后反复生成 token 的阶段，通常包含 decode forward、token 选择、状态追加与停止判断；本课程用“decode 前向”专指读取历史 KV Cache、写入新 K/V 并产生 logits 的模型前向。例：基础路径每接受一个 token，通常再执行一轮 decode forward | 在所有资料里都只指模型前向，或 decode 前向就是采样 |
| <span id="term-gradient-descent"></span>**gradient descent（梯度下降）** | 梯度指向目标值局部上升最快的方向；梯度下降沿负梯度方向迭代更新 | 一步找到全局最优，或与 AdamW 完全相同 |
| <span id="term-hyperparameter"></span>**hyperparameter（超参数）** | 由训练配置设定而非模型直接学出的量，如学习率或 batch size | 不影响结果，或只能凭经验随意选择 |
| <span id="term-random-seed"></span>**random seed（随机种子）** | 初始化数据顺序、参数或采样等伪随机过程的整数起点。例：`seed = 42` | 相同 seed 能跨硬件保证逐 bit 一致 |
| <span id="term-gradient-accumulation"></span>**gradient accumulation（梯度累积）** | 汇总多个微批次的梯度后再执行一次优化器更新 | 与一次放入同样大 batch 在所有实现中严格等价 |
| <span id="term-mixed-precision-training"></span>**mixed precision training（混合精度训练）** | 为不同张量或算子选用不同精度，并管理缩放和累加 | 所有计算都用同一种低精度，或位宽比例等于显存比例 |
| <span id="term-regularization"></span>**regularization（正则化）** | 用约束、噪声或数据策略减少只记训练数据的倾向 | 加入就保证泛化，或只指权重衰减 |
| <span id="term-early-stopping"></span>**early stopping（早停）** | 根据预先规定的验证指标和耐心窗口停止训练 | 看过测试结果再停止仍算独立测试，或首次波动就该停 |
| <span id="term-fitting"></span>**fitting（拟合）** | 根据训练数据调整参数或规则，使模型逼近数据中的关系；训练指标改善只是可能表现 | 训练集分数变好就是拟合的完整定义，或拟合好就证明能泛化 |
| <span id="term-generalization"></span>**generalization（泛化）** | 把训练中学到的规律迁移到未参与拟合的新样本或情境 | 训练 loss 低就证明泛化好 |
| <span id="term-data-leakage"></span>**data leakage（数据泄漏）** | 本应隔离的信息进入训练、规则拟合或方案选择，使评测失真 | 只有测试文本直接进入参数才算泄漏 |
| <span id="term-data-contamination"></span>**data contamination（数据污染）** | 评测题、答案或近重复内容混入训练材料 | 没有完全相同字符串就一定没有污染 |
| <span id="term-vector"></span>**vector（向量）** | 按顺序排列的一组数；维数是坐标数量，长度需要计算。例：`[3, 4]` 是二维向量，欧氏长度为 `5` | 有 10 个坐标就表示长度等于 10 |
| <span id="term-matrix"></span>**matrix（矩阵）** | 按行列组织的一组数，也可充当线性变换规则。例：`[[1, 2], [3, 4]]` 是 `2 x 2` 矩阵 | 矩阵 W 就是输入空间或输出空间本身 |
| <span id="term-embedding"></span>**embedding（嵌入）** | 把对象表示为连续向量；token Embedding 通常由可训练查表得到 | 所有 embedding 都只能来自 token ID 查表 |
| <span id="term-hidden-state"></span>**hidden state（隐藏状态）** | 某一层、某一位置结合当前上下文形成的向量表示 | 与静态 token Embedding 永远相同 |
| <span id="term-hidden-dimension"></span>**hidden dimension（隐藏维度）** | 每个位置的隐藏表示包含的坐标数量，是正整数。例：`D = 4096` 表示每个位置有 4096 个坐标 | 每一维都有固定可命名的人类语义 |
| <span id="term-tensor"></span>**tensor（张量）** | 按若干轴组织的一组数，是向量和矩阵的推广。例：形状 `(2, 4, 8)` 的三轴张量共含 64 个数 | 轴的含义可以不说明，只看总元素数 |
| <span id="term-tensor-shape"></span>**tensor shape（张量形状）** | 各轴长度组成的整数记录，必须连同轴含义一起读。例：`(2, 4, 8)` 可表示 2 个样本、每个 4 个 token、每个 token 8 个坐标 | 相同数字排列代表相同轴含义 |
| <span id="term-representation-space"></span>**representation space（表示空间）** | 模型用一组坐标和方向组织隐藏表示的高维空间 | 每个坐标轴都是人工预先定义的概念 |
| <span id="term-high-dimensional-space"></span>**high-dimensional space（高维空间）** | 需要许多坐标描述一个点或向量的空间 | 能像二维平面一样完整画出和直观看懂 |
| <span id="term-vector-norm"></span>**vector norm（向量范数）** | 把向量总体幅度汇总成非负标量的规则。例：`[3, 4]` 的欧氏范数是 `5` | 能说明向量具体朝哪个方向 |
| <span id="term-cosine-similarity"></span>**cosine similarity（余弦相似度）** | 用标量比较两个非零向量的方向，常见范围为 `-1` 到 `1`。例：`0.92` 表示方向很接近 | 等同于欧氏距离或原始点积 |
| <span id="term-euclidean-distance"></span>**Euclidean distance（欧氏距离）** | 把两个点的直线距离汇总为非负标量。例：`(0, 0)` 到 `(3, 4)` 的距离是 `5` | 在所有高维表示任务中都天然最合适 |
| <span id="term-linear-projection"></span>**linear projection（线性投影）** | 用矩阵学习输入坐标的组合并映射到输出空间 | 只是 reshape，或输出维度越大知识越多 |
| <span id="term-subspace"></span>**subspace（子空间）** | 高维空间中由较少独立方向张成的受限空间 | 从原向量机械切出的一段固定语义坐标 |
| <span id="term-matrix-rank"></span>**matrix rank（矩阵秩）** | 矩阵独立方向的数量，是非负整数。例：`2 x 2` 单位矩阵的秩为 `2` | 矩阵元素大小或参数数量 |
| <span id="term-low-rank"></span>**low rank（低秩）** | 矩阵秩明显小于行列允许的上限 | 数值小、矩阵稀疏或必然同比加速 |
| <span id="term-dimensionality-reduction"></span>**dimensionality reduction（降维）** | 把高维数据摘要到较少维度以分析、压缩或可视化 | 能无损保留高维空间的全部关系 |
| <span id="term-pca"></span>**PCA（主成分分析）** | 寻找保留较大线性变化方向的降维方法 | 前两个主成分代表全部结构或真实语义轴 |
| <span id="term-tsne"></span>**t-SNE** | 尽量保留高维局部邻近关系的探索性可视化方法 | 二维簇间距离、簇大小和方向可还原全局结构 |
| <span id="term-umap"></span>**UMAP** | 基于邻域图和流形假设构造低维表示的方法 | 输出图就是原高维空间的唯一真实地图 |
| <span id="term-logits"></span>**logits** | softmax 前的一组实数分数，通常是与候选数等长的向量。例：`[1.2, -0.3, 2.0]` | 已经是概率或正确率 |
| <span id="term-softmax"></span>**softmax** | 把分数向量转换为总和为 1 的权重向量的函数。例：`softmax([0, 1]) ≈ [0.27, 0.73]` | 会让答案自动真实或概率自动校准 |
| <span id="term-loss"></span>**loss（损失函数）** | 既可指计算差异的函数，也常指该函数算出的标量。例：交叉熵函数算得 `loss = 2.31` | 任何“信息损失”都属于训练 loss，或一个数代表全部质量 |
| <span id="term-gradient"></span>**gradient（梯度）** | loss 相对当前计算图中参与运算且允许训练的参数的局部变化率；冻结、未参与或梯度已断开的参数可能没有梯度。例：某参数的梯度为 `0.08` | 每个参数一定都有梯度，或梯度直接给出全局最优答案 |
| <span id="term-gradient-norm"></span>**gradient norm（梯度范数）** | 把一组参数梯度的总体幅度汇总成非负标量。例：`gradient norm = 1.7` | 数值正常就表示每个参数的更新都合理 |
| <span id="term-learning-rate"></span>**learning rate（学习率）** | 控制每次参数更新幅度的非负标量超参数。例：`2e-5`，即 `0.00002` | 越大就一定训练得越快越好 |
| <span id="term-optimizer"></span>**optimizer（优化器）** | 根据梯度及内部状态计算参数更新的算法 | 负责计算前向预测或损失 |
| <span id="term-adamw"></span>**AdamW** | 用梯度的一阶与二阶移动统计适配更新尺度，并把权重衰减从梯度适配中解耦的优化器 | 自动找到学习率、保证泛化或负责计算梯度 |
| <span id="term-batch"></span>**batch（批次）** | 一次共同送入计算流程的一组样本、序列或请求 | 必然等于一次参数更新，或只用于训练 |
| <span id="term-batch-size"></span>**batch size（批次大小）** | 一个 batch 的样本或序列数，是正整数。例：`batch size = 16` | 越大就一定更快、更好，或等于更新所用全部样本数 |
| <span id="term-effective-batch-size"></span>**effective batch size（有效批次大小）** | 一次参数更新汇总的样本或序列总量。例：4 张卡 × 每卡 8 个样本 × 累积 2 次，结果为 `64` | 所有任务都只按样本数算，或扩大后严格等价 |
| <span id="term-step"></span>**step（训练步）** | 本课程默认指一次优化器更新，日志常用整数计数。例：`step = 300` 表示已完成 300 次更新 | 所有框架里的 step 都完全相同 |
| <span id="term-epoch"></span>**epoch（轮次）** | 训练过程大致遍历一遍训练集，常用整数或小数记录进度。例：`epoch = 2` 表示大致遍历了两遍 | 总有固定数量的 step |
| <span id="term-context"></span>**context（上下文）** | 本次计算可用的输入与生成历史；不同模态可编码成 token 或连续表示 | 已写入模型参数，或所有模态都必须先变成文本 token |
| <span id="term-transformer"></span>**Transformer** | 由注意力、MLP、残差连接和归一化等模块组成的一类架构 | 所有大模型都只能采用同一种结构 |
| <span id="term-transformer-block"></span>**Transformer Block / Decoder Block** | Transformer 主干中重复堆叠的计算单元；在 Decoder-only 模型中也常称 Decoder Block，通常包含注意力、MLP、残差连接与归一化 | 每个 Block 都是独立模型，或所有 Block 参数共享 |
| <span id="term-attention"></span>**attention（注意力）** | 根据 Query 与 Key 的匹配权重，对 Value 做加权汇总 | 权重就是完整可靠的人类可读解释 |
| <span id="term-self-attention"></span>**self-attention（自注意力）** | 让同一序列中的位置互相产生 Q、K、V，并按可见范围汇总信息 | 每个位置都能读未来，或权重就是完整因果解释 |
| <span id="term-positional-mechanism"></span>**positional mechanism（位置机制）** | 向序列表示提供顺序或相对位置线索，如位置 Embedding、旋转或注意力偏置 | 只能把固定的绝对位置向量加到 token Embedding 上 |
| <span id="term-normalization"></span>**normalization（归一化）** | 按规则调整隐藏表示的尺度或统计量；常见 LayerNorm 与 RMSNorm | 所有算法计算相同，而且一定放在子层之后 |
| <span id="term-residual-connection"></span>**residual connection（残差连接）** | 把子层输入直接加回子层输出，为信息和梯度保留较短通路 | 会跳过子层计算，或保证深层模型一定稳定 |
| <span id="term-mlp"></span>**MLP / FFN（前馈网络）** | 在 Transformer Block 中对每个位置分别做可学习的非线性特征变换 | 会像注意力一样直接跨 token 位置汇总信息 |
| <span id="term-cnn"></span>**CNN（卷积神经网络）** | 用共享卷积核在局部邻域提取特征的一类神经网络架构 | 只适用于图片，或卷积核会直接识别完整物体 |
| <span id="term-rnn"></span>**RNN（循环神经网络）** | 复用同一递归单元，让隐藏状态随序列步骤持续更新的一类网络 | 每个时间步使用不同参数，或固定状态能无损保存任意长历史 |
| <span id="term-lstm"></span>**LSTM（长短期记忆网络）** | 用细胞状态与遗忘、输入、输出等门控制序列信息保留和更新的门控循环网络 | 能永久记住所有历史，或门是人工设定的硬开关 |
| <span id="term-gru"></span>**GRU（门控循环单元）** | 用更新门和重置门维护单一隐藏状态的门控循环网络 | 只是删减版 LSTM 因而必然更差，或门更少就保证更快 |
| <span id="term-autoencoder"></span>**autoencoder（自编码器）** | 用编码器把输入变成瓶颈表示，再由解码器重建输入的架构与训练目标组合 | 重建越好就表示下游语义越好，或必须始终保留解码器 |
| <span id="term-gan"></span>**GAN（生成对抗网络）** | 让生成器与判别器在相互对抗的目标下共同训练的生成建模框架 | 部署生成时必须运行判别器，或判别器分不清就证明样本真实 |
| <span id="term-diffusion-model"></span>**diffusion model（扩散模型）** | 学习逐步去噪，并在生成时从噪声反复还原样本的一类生成模型 | 训练是在记住原图，或减少采样步数后质量必然不变 |
| <span id="term-gnn"></span>**GNN（图神经网络）** | 让节点沿图边收集邻居消息并更新表示的一类神经网络 | 图中的边一定正确，或层数越多就能无损利用更远关系 |
| <span id="term-output-head"></span>**output head（输出头）** | 把主干隐藏表示映射到任务输出；语言模型中通常得到词表 logits | 会直接选出下一个 token，或输出天然校准的概率 |
| <span id="term-causal-mask"></span>**causal mask（因果遮罩）** | 自回归计算中限制每个位置只能读取自己和之前位置 | 会阻止读取之前位置，或只在训练阶段存在 |
| <span id="term-backpropagation"></span>**backpropagation（反向传播）** | 用链式法则把误差逐层传回并计算梯度 | 本身就是优化器更新 |
| <span id="term-cross-entropy"></span>**cross-entropy（交叉熵）** | 把目标与预测的差异算成标量的损失函数；单一正确类别时为 `-log p`。例：`p = 0.8` 时 loss 约为 `0.223` | 对称距离、等同于准确率，或任何任务都只有一个正确类别 |
| <span id="term-checkpoint"></span>**checkpoint（检查点）** | 训练状态快照；至少可含权重，完整恢复通常还需优化器等状态 | 每个检查点都能完整恢复训练或直接上线 |
| <span id="term-fine-tuning"></span>**fine-tuning（微调）** | 从已有模型权重出发，用更聚焦的数据和目标继续训练 | 必然只更新少量参数，或适合写入频繁变化的事实 |
| <span id="term-full-fine-tuning"></span>**full fine-tuning（全参数微调）** | 在已有模型上继续训练，并通常允许全部参数更新。在“全参数 SFT”中，“全参数”描述更新范围，“SFT”描述监督目标 | 一定优于 PEFT，或训练显存只由权重决定 |
| <span id="term-peft"></span>**PEFT（参数高效微调）** | 只训练少量新增或选定参数来适配已有模型的一类方法 | 等同 LoRA，或参数少就保证无质量损失 |
| <span id="term-adapter"></span>**adapter（模型适配器）** | 附加到基座上的小型可训练模块或参数集合 | 是完整模型副本，或能与任意基座兼容 |
| <span id="term-pretraining"></span>**pretraining（预训练）** | 面向具体任务微调或对齐前，用预训练目标学习初始参数 | 一定得到通用模型，或数据越多越真实 |
| <span id="term-continued-pretraining"></span>**continued pretraining（继续预训练）** | 从已有 checkpoint 出发，沿用预训练目标学习新数据 | 只能用无标注领域数据，或等同 SFT |
| <span id="term-post-training"></span>**post-training（模型后训练）** | 在已有基座上继续塑造指令、偏好、推理、安全或拒答等行为的一组训练阶段 | 自动补齐事实知识并保证原有能力不退化 |
| <span id="term-knowledge-distillation"></span>**knowledge distillation（知识蒸馏）** | 让学生模型学习教师的回答、概率、特征或策略信号 | 复制教师参数或保证能力无损 |
| <span id="term-off-policy-distillation"></span>**off-policy distillation（离策略蒸馏）** | 在固定教师轨迹或预收集数据上学习 | 与学生推理时访问的状态完全一致 |
| <span id="term-on-policy-distillation"></span>**on-policy distillation（在策略蒸馏）** | 学生先访问自己的状态，教师再提供概率、回答或其他监督 | 一定等于逐 token logit 蒸馏 |
| <span id="term-exposure-bias"></span>**exposure bias（暴露偏差）** | 训练依赖理想历史，推理却接着自身输出生成所形成的状态差异 | 单步准确就不会沿轨迹累积误差 |
| <span id="term-teacher-model"></span>**teacher model（教师模型）** | 在蒸馏中提供监督信号的模型；教师身份由角色而非规模决定 | 必然更大、更强，且输出都是真值 |
| <span id="term-student-model"></span>**student model（学生模型）** | 在蒸馏中学习教师信号、通常更小或更便宜的模型 | 学生只能通过复制参数获得教师能力 |
| <span id="term-logit-distillation"></span>**logit distillation（logit 蒸馏）** | 让学生匹配教师在候选 token 上的 logits 或软概率 | 看到最终答案就获得完整概率信息 |
| <span id="term-sft"></span>**SFT（supervised fine-tuning，监督微调）** | 用输入与理想输出示例训练目标行为 | 会自动完成事实核验，或所有指令微调都使用相同 loss 范围 |
| <span id="term-lora"></span>**LoRA** | 冻结大部分基础权重，用低秩矩阵学习权重增量 | 自动压缩推理模型或保证无损 |
| <span id="term-qlora"></span>**QLoRA** | 低比特保存冻结的基础模型，运算时通常反量化到计算精度，同时训练 LoRA 适配器 | 所有训练状态和矩阵乘法都直接使用 4 bit |
| <span id="term-rlhf"></span>**RLHF（人类反馈强化学习）** | 利用人类偏好信号和强化学习优化行为的一类流程 | 所有对齐都只能通过它完成 |
| <span id="term-dpo"></span>**DPO（直接偏好优化）** | 比较获选与拒选回答相对参考策略的对数概率比，用分类损失直接优化策略 | 不需要偏好数据、参考约束或独立评测 |
| <span id="term-model-alignment"></span>**model alignment（模型对齐）** | 让模型行为更符合明确的人类意图、任务规范和安全边界的过程 | 是一种单独算法，或一次训练能代表所有人的价值 |
| <span id="term-preference-data"></span>**preference data（偏好数据）** | 记录同一输入下候选输出的选择、排序或理由 | 必然等于事实真值，或标注者天然一致 |
| <span id="term-preference-optimization"></span>**preference optimization（偏好优化）** | 用候选回答的比较或排序信号调整模型行为的一类后训练方法 | 偏好分数提高就证明事实性、推理和安全都提高 |
| <span id="term-reward-model"></span>**reward model（奖励模型）** | 根据输入和候选输出估计奖励分数的模型 | 是无偏真值裁判，或高奖励必然等于真实成功 |
| <span id="term-reinforcement-learning"></span>**reinforcement learning（强化学习）** | 利用带奖励的轨迹数据优化策略的一类方法；轨迹可在线采样，也可预先收集 | 只是随机试错，或有奖励就一定要用强化学习 |
| <span id="term-policy-model"></span>**policy model（策略模型）** | 根据当前状态产生动作或 token 分布、并被优化的模型 | 等同奖励模型，或这里只指部署策略 |
| <span id="term-advantage-estimate"></span>**advantage estimate（优势估计）** | 估计某个动作或输出相对参考水平好多少 | 就是原始奖励、绝对正确率或跨任务通用分数 |
| <span id="term-rollout"></span>**rollout（生成轨迹）** | 从初始状态出发，记录策略产生的 token 或动作，以及环境或验证器返回的观察、结果、奖励 | 最终答案相同就表示轨迹、成本和风险相同 |
| <span id="term-verifier"></span>**verifier（验证器）** | 用规则、程序、工具结果或模型检查输出是否满足条件 | 覆盖了真实目标全部边界，或通过就等于事实正确 |
| <span id="term-grpo"></span>**GRPO（组相对策略优化）** | 用同一输入的一组输出及相对奖励估计策略更新信号 | 不需要奖励设计，或在所有任务上普遍更好 |
| <span id="term-regression-test-set"></span>**regression test set（回归测试集）** | 检查新版本是否破坏旧能力、已修复问题或高风险边界 | 只测新任务就能发现全部退化，或可替代独立测试集 |
| <span id="term-rag"></span>**RAG（检索增强生成）** | 检索外部资料并放入上下文辅助生成 | 能保证资料和答案都真实 |
| <span id="term-agent"></span>**Agent（智能体）** | 围绕目标反复观察、行动并处理结果的系统；大模型 Agent 常借助工具 | 接入工具就算 Agent，或可脱离权限和人工确认自主执行 |
| <span id="term-agent-swarm"></span>**Agent Swarm（智能体群协作）** | 多 Agent 协作方案的宽泛称呼，没有统一固定架构 | 是定义统一的算法，或 Agent 越多越可靠 |
| <span id="term-inference"></span>**inference（模型推理）** | 用已训练参数执行前向计算，并按任务解码或读取预测 | 等同于推理能力，或通常会继续训练权重 |
| <span id="term-model-deployment"></span>**model deployment（模型部署）** | 把权重、Tokenizer、推理配置、服务和回滚方案交付到目标环境 | 上传权重文件就完成部署，或部署后自动持续学习 |
| <span id="term-inference-engine"></span>**inference engine（推理引擎）** | 在硬件上执行模型算子、缓存、批处理和解码循环的软件运行层 | 决定模型知识质量，或换引擎就等于重新训练 |
| <span id="term-model-serving"></span>**model serving（模型服务）** | 把推理包装为处理请求、并发、队列、超时和版本的服务系统 | 只是 HTTP 接口，或吞吐提高就代表每个请求更快 |
| <span id="term-compute-kernel"></span>**compute kernel（计算内核）** | 在目标处理器上执行具体张量算子或其一部分的底层程序单元。例：一次 attention kernel 读取 Q/K/V 并写出中间结果 | 等同整个模型或操作系统内核，或写出 kernel 就一定最快 |
| <span id="term-profiler"></span>**profiler（性能分析器）** | 记录各阶段耗时、显存、调用关系或硬件利用率，用来定位实际瓶颈。例：某 kernel 占总 GPU 时间的 `38%` | 只看模型质量，或一次 profile 就代表所有输入和并发 |
| <span id="term-schema"></span>**schema（结构约束）** | 描述数据字段、类型、必填项和嵌套关系。例：schema 规定 `answer` 必须是字符串、`score` 必须是数字 | 会验证事实正确性，或声明字段就等于执行了工具 |
| <span id="term-smoke-test"></span>**smoke test（冒烟测试）** | 用少量快速样例确认程序能启动并完成关键路径。例：加载模型、发送一条请求并检查输出结构 | 覆盖完整质量、性能和安全评测，或通过就证明可以上线 |
| <span id="term-performance-warm-up"></span>**performance warm-up（性能预热）** | 正式测量前先运行若干次，让编译、内存分配、缓存和频率等状态稳定。例：先预热 `10` 次，再统计后续 `100` 次 TPOT | 会训练模型、改变权重，或预热次数在所有硬件上都固定有效 |
| <span id="term-prompt"></span>**prompt（提示词）** | 本次交给模型的指令、上下文、示例或问题组合 | 会永久改变权重，或能补齐模型没有的知识与权限 |
| <span id="term-system-prompt"></span>**system prompt（系统提示）** | 应用放在系统消息位置、用于约束角色和行为的提示 | 是不可绕过的安全边界，或已经写入模型参数 |
| <span id="term-context-window"></span>**context window（上下文窗口）** | 一次模型计算允许接收和保留的 token 上限。例：`128 Ki tokens` = `128 x 1024` = `131072` 个 token；若文档写 `128K`，需先确认计量口径 | 越长就表示每个位置都能同样可靠利用 |
| <span id="term-context-compaction"></span>**context compaction（上下文压缩）** | 接近上下文上限时，用摘要或压缩块替换较早内容以继续长任务。例：旧消息被一段摘要替代后继续对话 | 是无损永久记忆，或摘要存在就能逐字恢复原始证据 |
| <span id="term-tool-calling"></span>**tool calling（工具调用）** | 模型生成工具名称和参数，再由外部系统校验执行 | 输出参数就表示工具已执行，或工具结果一定可信 |
| <span id="term-model-monitoring"></span>**model monitoring（模型监控）** | 持续观察服务健康、输出质量、任务效果和安全风险 | 只看服务器存活，或用户点赞可直接当真值 |
| <span id="term-reasoning"></span>**reasoning（推理能力/过程）** | 组合条件、执行中间步骤或验证结果以得到结论 | 思维链越长就证明内部推理越正确、越忠实 |
| <span id="term-reasoning-effort"></span>**reasoning effort（推理强度）** | 厂商引导一次请求投入多少内部推理 token 或计算预算的控制项。例：`reasoning.effort = high` | 是行业统一的智商旋钮，或调高后必然得到正确答案 |
| <span id="term-thinking-budget"></span>**thinking budget（思考预算）** | 特定模型或 API 为一次内部思考阶段设置的 token 或计算额度，具体计量由接口定义。例：教学记录给思考阶段 `256` 个 token | 等于模型参数量、知识量，或预算用完就代表答案正确 |
| <span id="term-thinking-level"></span>**thinking level（思考级别）** | 某些厂商对动态思考量提供的档位，具体等级由模型文档定义。例：Gemini 的 `thinking_level` | 不同厂商的同名档位可以直接比较，或只改变 temperature |
| <span id="term-adaptive-thinking"></span>**adaptive thinking（自适应思考）** | 根据请求复杂度或运行状态动态分配思考量，而不是每次使用固定预算 | 能准确判断所有问题难度，且不影响延迟和成本 |
| <span id="term-decoding-strategy"></span>**decoding strategy（解码策略）** | 从 logits 得到一个已接受 token 的规则组合：先应用已启用的约束与分数处理；greedy 对处理后的候选取最大项，sampling 可组合 temperature 缩放、top-k/top-p 过滤、重归一化与随机采样 | temperature、top-k、top-p 与 greedy 必须四选一，或随机性是幻觉唯一原因 |
| <span id="term-greedy-decoding"></span>**greedy decoding（贪心解码）** | 每一步在已启用的约束与分数处理之后，选择当前分数或概率最高 token 的确定性规则 | 局部每步最高就保证整段序列全局最好或事实正确 |
| <span id="term-top-k-sampling"></span>**top-k sampling（top-k 采样）** | 每一步只保留分数最高的固定 k 个候选，将保留项重新归一化后再采样 | 固定 k 能保证每步保留相同概率质量 |
| <span id="term-top-p-sampling"></span>**top-p sampling（top-p 采样）** | 按概率从高到低保留累计概率达到阈值 p 的最小前缀，将保留项重新归一化后再采样 | 候选数量固定，或降低 p 就保证事实正确 |
| <span id="term-overfitting"></span>**overfitting（过拟合）** | 训练数据表现改善，未见数据表现却没有同步改善 | 训练 loss 下降就一定没有发生 |
| <span id="term-catastrophic-forgetting"></span>**catastrophic forgetting（灾难性遗忘）** | 学习新任务或分布后，模型原有能力显著退化 | 新任务分数上升后不必检查旧能力 |
| <span id="term-training-set"></span>**training set（训练集）** | 用于拟合参数或训练数据相关规则的数据 | 训练集表现好就证明能泛化 |
| <span id="term-validation-set"></span>**validation set（验证集）** | 不直接更新参数，用于选配置、checkpoint、阈值或停止时机，也常称开发集或开发评测集 | 反复调参后仍是无偏最终测试证据 |
| <span id="term-test-set"></span>**test set（测试集）** | 方案冻结后用于最终估计；冻结测试集在开发期间保持不可见，据此反复改方案就参与了开发 | 不参与梯度就可以无限次查看 |
| <span id="term-baseline"></span>**baseline（模型基线）** | 采用复杂方法前保存的可比较起点，如规则、提示或未微调模型 | 方法升级后就可以丢弃的临时演示 |
| <span id="term-model-evaluation"></span>**model evaluation（模型评测）** | 在固定样本、规则、预算和版本下收集质量、成本与风险证据 | 跑一个排行榜或看几个样例就完成评测 |
| <span id="term-open-weight-model"></span>**open-weight model（开放权重模型）** | 公众可以在许可证条件下取得权重；代码、数据、配方和用途权限另行核对 | 权重可下载就等于完整开源、无使用限制或普通设备可部署 |
| <span id="term-confidence-interval"></span>**confidence interval（置信区间）** | 按规定抽样与构造方法表示有限样本估计不确定性的区间 | 95% 区间表示固定真值有 95% 概率落在本次区间内 |
| <span id="term-clopper-pearson-interval"></span>**Clopper-Pearson interval（Clopper-Pearson 区间）** | 由二项分布的精确尾概率反演比例区间；零事件时可报告单侧风险上界 | 观察到零次事件就证明总体事件率为零 |
| <span id="term-paired-evaluation"></span>**paired evaluation（成对评测）** | 让候选在同一批样本上逐题比较，以控制样本难度差异 | 两边总样本数相同就已经成对 |
| <span id="term-mcnemar-test"></span>**McNemar test（McNemar 检验）** | 比较同一批二分类样本上两个方法差异的配对检验，证据来自结果不一致的样本 | 比较两个边际区间就等价于检验配对差异 |
| <span id="term-win-rate"></span>**win rate（评测胜率）** | 在指定题目、对手、裁判和平局规则下被判优的对局比例 | 就是事实正确率，或能迁移到所有对手 |
| <span id="term-elo-rating"></span>**Elo rating（Elo 评分）** | 根据一系列成对结果更新的相对评分，依赖对手池与更新规则 | 是绝对能力分数，或不同榜单可直接横比 |
| <span id="term-benchmark"></span>**benchmark（评测基准）** | 用于可重复比较的一组固定任务、数据、指标和运行口径 | 排名能代表所有真实场景，或不同版本分数可直接比较 |
| <span id="term-ablation-study"></span>**ablation study（消融实验）** | 移除或替换一个关键因素，观察变化以缩小贡献归因 | 一次消融能证明完整因果 |
| <span id="term-ground-truth"></span>**ground truth（参考真值）** | 当前任务认可的参考答案、标签或可核验事实 | 所有开放问题都有唯一答案，或标签文件一定正确 |
| <span id="term-model-card"></span>**model card（模型卡）** | 记录模型版本、用途、训练评测信息、限制和风险 | 填写后就自动证明安全、可复现或适合上线 |
| <span id="term-data-card"></span>**data card（数据卡）** | 记录数据来源、许可、组成、处理、切分和已知偏差 | 能替代实际来源、样本和许可审查 |
| <span id="term-llm-as-a-judge"></span>**LLM-as-a-Judge（大模型裁判）** | 让大语言模型依据量表评审候选输出 | 天然无偏、等同人工真值或无需人工校准 |
| <span id="term-pass-at-k"></span>**pass@k** | 衡量同一任务允许 k 个候选时至少一个通过测试的概率 | 等于单个候选正确率 |
| <span id="term-hit-at-k"></span>**Hit@k** | 判断每个查询的前 k 个结果中是否至少出现一个相关项，再汇总命中查询比例 | 等于 Recall@k，或命中一项就表示全部必要证据齐全 |
| <span id="term-recall-at-k"></span>**Recall@k** | 前 k 个结果找回的相关项数 / 该查询全部相关项数，再按预定方式聚合 | 总能与 Hit@k 相同，或命中一个证据就表示全部必要证据已找回 |
| <span id="term-wer"></span>**WER（词错误率）** | 语音识别的替换、删除、插入错误数 / 参考词数；通常越低越好 | 跨语言、分词和规范化口径可以直接横比 |
| <span id="term-rtfx"></span>**RTFx（实时因子）** | 相对音频时长的处理速度指标；通常越高越快，需记录硬件和批处理 | 越高就代表质量越高，或不同硬件下可直接横比 |
| <span id="term-model-hallucination"></span>**model hallucination（模型幻觉）** | 缺少事实依据、违背给定证据或虚构任务状态的内容 | 只由随机采样造成 |
| <span id="term-factuality"></span>**factuality（事实性）** | 回答中的可核验主张与外部事实是否一致 | 事实正确就表示一定忠于给定证据 |
| <span id="term-faithfulness"></span>**faithfulness（证据忠实度）** | 回答中的主张是否得到当前证据或工具结果支持 | 忠于证据就证明证据本身真实且完整 |
| <span id="term-confidence-calibration"></span>**confidence calibration（置信度校准）** | 先定义置信分数，再让相近分数样本的正确率与分数匹配 | 语气肯定就是高置信，或能把未知变正确 |
| <span id="term-abstention"></span>**abstention（选择性回答/模型拒答）** | 证据或置信不足时不作答，在错误风险与覆盖率间取舍 | 拒答越多就必然越可靠 |
| <span id="term-quantization"></span>**quantization（量化）** | 用较少 bit 表示或计算权重、激活或 KV Cache 数值；它横跨校准/训练、导出格式、低精度 kernel 与硬件支持。例：将 BF16 权重转换为 4-bit 部署表示 | 位宽缩小多少就同比加速且不掉质量，或量化只属于硬件 |
| <span id="term-ptq"></span>**PTQ（训练后量化）** | 不再训练模型参数，而是在训练完成后用权重统计或校准数据确定低比特部署表示。例：将 BF16 权重转换为 4-bit 权重文件 | 不需要校准和任务评测，或所有模型都能无损量化 |
| <span id="term-pruning"></span>**pruning（剪枝）** | 删除权重、通道、头或层等部分结构 | 出现很多零就一定能在目标硬件上变快 |
| <span id="term-kv-cache"></span>**KV Cache（KV 缓存）** | 生成时按层缓存旧位置的 Key/Value，避免重复计算这些 K/V | 保存事实知识、更新参数或主要降低训练显存 |
| <span id="term-memory-bandwidth"></span>**memory bandwidth（内存/显存带宽）** | 单位时间内处理器与某级内存可传输的数据量 | 与容量、计算峰值或所有层级实际带宽相同 |
| <span id="term-arithmetic-intensity"></span>**arithmetic intensity（算术强度）** | 指定内存层级下的计算操作量与数据搬运字节数之比 | 不需说明层级，或数值越高就保证更快 |
| <span id="term-roofline-model"></span>**Roofline model（屋顶线模型）** | 同时表示计算峰值与带宽上限的性能分析模型 | 脱离真实测量也能给出唯一优化方案 |
| <span id="term-collective-communication"></span>**collective communication（集合通信）** | 多设备共同参与的规约、聚合、广播或全互换等操作 | 多卡通信成本会自动被计算完全隐藏 |
| <span id="term-allreduce"></span>**AllReduce（全规约）** | 规约各设备数据并把完整结果返回每个参与设备 | 只是把数据集中到一张卡 |
| <span id="term-zero"></span>**ZeRO** | 分片训练状态以减少数据并行中的重复显存占用 | 阶段越高就必然训练越快 |
| <span id="term-hbm"></span>**HBM（高带宽内存）** | 靠近加速器、为高吞吐数据访问设计的内存 | 容量越大就自动代表所有任务更快 |
| <span id="term-inference-latency"></span>**inference latency（推理延迟）** | 在声明测量边界后，请求从起点到产生所需结果的时长。例：应用端到端完整回答延迟为 `1.8 s`；引擎侧可能从请求到达引擎开始计时 | 一个平均值足以代表所有延迟体验，或不同测量起点的数值可以直接比较 |
| <span id="term-inference-throughput"></span>**inference throughput（推理吞吐）** | 单位时间完成的请求数或 token 数，必须注明口径。例：输出吞吐为 `8000 token/s` | 不同 token 口径可直接比较，或吞吐越高等待越短 |
| <span id="term-effective-throughput"></span>**effective throughput / goodput（有效吞吐）** | 只统计满足质量、延迟和错误率等约束的有效工作量 | 总 tokens/s 上升就必然同步上升 |
| <span id="term-slo"></span>**SLO（服务等级目标）** | 在指定负载和统计窗口内为服务指标设定的目标 | TTFT 等指标本身就是 SLO，或写“响应要快”就够 |
| <span id="term-error-budget"></span>**error budget（错误预算）** | 给定 SLO 与统计窗口内允许消耗的失败额度。例：30 天 99.9% 可用性允许约 43.2 分钟不可用 | 可以故意用完的停机时间，或能抵消安全红线的通用额度 |
| <span id="term-data-drift"></span>**data drift（数据漂移）** | 线上输入的语言、长度、主题或用户群等分布相对基准发生变化 | 检测到漂移就证明模型已失效或必须重训 |
| <span id="term-concept-drift"></span>**concept drift（概念漂移）** | 输入与正确目标之间的关系发生变化 | 输入样式或流量比例改变就算概念漂移 |
| <span id="term-canary-release"></span>**canary release（灰度发布）** | 让少量真实流量先使用新版本，并按预设条件放量或回滚 | 流量少就不需要权限、安全红线和回滚 |
| <span id="term-capability-regression"></span>**capability regression（能力回归）** | 新版本在旧版本已通过的能力、边界或安全样本上出现可重复退化 | 一个失败样例就证明整体退化，或只看总平均分就能定位原因 |
| <span id="term-ttft"></span>**TTFT（首 token 延迟）** | 在声明测量边界后，从请求起点到测量端收到第一个输出 token 的时长。例：应用端 `TTFT = 320 ms` 可能含排队、检索、模板、prefill 和网络；引擎侧通常从请求到达引擎后计时 | 能代表后续每个 token 的生成速度，或不同起点的 TTFT 可以直接比较 |
| <span id="term-tpot"></span>**TPOT（每 token 延迟）** | 在同一测量边界下，首 token 后相邻输出 token 的平均间隔；常按 `(完成时间 − 首 token 时间) ÷ 后续 token 数` 估算。例：`TPOT = 25 ms/token` | 把首 token、排队、检索和 prefill 一概算入，或把 TPOT 当成所有请求的固定速度 |
| <span id="term-prefill"></span>**prefill（预填充阶段）** | 处理输入上下文、建立各层 KV Cache 并产生首个待解码位置 logits | 会一次生成完整回答，或与逐 token decode 相同 |
| <span id="term-chunked-prefill"></span>**chunked prefill（分块预填充）** | 把长输入预填充分散到多个调度步 | 只改变调度，不必检查语义和性能权衡 |
| <span id="term-continuous-batching"></span>**continuous batching（连续批处理）** | 请求到达和结束时动态调整 batch，使设备持续处理可运行请求 | 必然同时降低单请求延迟并提高吞吐 |
| <span id="term-paged-kv-cache"></span>**paged KV cache（分页 KV Cache）** | 分块并映射 KV Cache 的物理存放，以减少碎片和支持动态分配 | 自动减少每 token 的 KV 内容，或等同所有 PagedAttention |
| <span id="term-paged-attention"></span>**PagedAttention** | vLLM 中通过块表读取非连续分页 KV Cache 的注意力实现 | 新的模型注意力语义，或分页 KV Cache 的任意同义词 |
| <span id="term-memory-wall"></span>**memory wall（内存墙）** | 数据搬运速度成为整体性能主要限制的现象 | 只是显存容量不足，换更大容量就能解决 |
| <span id="term-modality"></span>**modality（模态）** | 信息的表现与采集形式，如文本、图像、语音或视频 | 文件扩展名相同就一定是同一任务表示 |
| <span id="term-multimodal-model"></span>**multimodal model（多模态模型）** | 能联合处理或生成两种及以上模态表示的模型或系统 | 接入 OCR 就自动成为端到端多模态模型 |
| <span id="term-encoder"></span>**encoder（编码器）** | 把输入转换成主干或下游任务可处理表示的组件 | 已经完成全部理解推理，或都是 Transformer Encoder |
| <span id="term-decoder"></span>**decoder（解码器）** | 把隐藏表示还原、预测或生成到目标输出空间的组件 | 只指 Decoder-only Transformer，或必然逐 token 输出文字 |
| <span id="term-flops"></span>**FLOPs（浮点运算量）** | 完成某段计算所需浮点操作的计数。例：`1 TFLOP = 10^12 FLOPs`，不表示耗时 1 秒 | 就是每秒速度、运行时长或实际成本 |
| <span id="term-data-parallelism"></span>**data parallelism（数据并行）** | 不同设备处理不同样本或 batch 分片，并同步梯度或等价状态 | 每张设备只保存模型一部分，或设备翻倍就线性加速 |
| <span id="term-tensor-parallelism"></span>**tensor parallelism（张量并行）** | 把同一层的大张量计算切分到多个设备协同完成 | 就是数据并行，或切分后不需要通信 |
| <span id="term-pipeline-parallelism"></span>**pipeline parallelism（流水线并行）** | 把不同层或阶段分到设备，让多个微批次流水推进 | 阶段总能完全均衡，或没有气泡与激活通信 |
| <span id="term-moe"></span>**MoE（混合专家）** | 路由并组合多个专家；现代大模型常用每 token 只选部分专家的稀疏 MoE | 所有 MoE 都稀疏，或是多个完整模型投票 |
| <span id="term-multi-token-prediction"></span>**Multi-Token Prediction（MTP，多 token 预测）** | 让一个训练位置获得多个未来 token 的预测监督的一类方法，可由并行预测头、串联预测模块等实现；部分实现也能在推理时提供多 token 候选 | 所有 MTP 都采用同一种结构，或训练时预测多个位置就等于推理时一次接受多个正确 token |
| <span id="term-fixed-size-state"></span>**fixed-size state（固定状态）** | 用不随序列长度增长的状态递推压缩历史 | 与 batch、层数等都无关，或能无损记住无限历史 |
| <span id="term-linear-attention"></span>**linear attention（线性注意力）** | 把注意力改写为可递推或可重排的状态计算 | 都无损等价于 softmax 注意力 |
| <span id="term-state-space-model"></span>**state-space model（状态空间模型）** | 用状态递推处理序列的一类模型 | 自动保留任意长度历史的全部细节 |
| <span id="term-outer-product"></span>**outer product（外积）** | 把两个向量组合成矩阵 | 与得到单个标量的点积相同 |
| <span id="term-quantile"></span>**quantile（分位数）** | 按排序位置描述数据分布阈值的统计量 | 在所有软件中只有一种计算定义 |
| <span id="term-softcap"></span>**softcap（平滑封顶）** | 平滑限制数值幅度，同时保留连续梯度 | 能自动解决全部溢出和质量问题 |
| <span id="term-total-parameters"></span>**total parameters（总参数量）** | 模型全部参数元素数量，不论是否冻结。例：`70B` 表示约 700 亿个参数 | 等于可训练参数量或每 token 激活参数量 |
| <span id="term-activated-parameters"></span>**activated parameters（激活参数量）** | 稀疏模型每 token 前向使用的参数量。例：总参数 `100B` 的教学 MoE 可每 token 只激活 `10B` | 有唯一口径，或可直接当作 FLOPs、延迟或显存 |
| <span id="term-scaling-laws"></span>**Scaling Laws（缩放定律）** | 限定范围内观察到的经验缩放关系 | 参数翻倍就保证能力固定增长 |
| <span id="term-expert-parallelism"></span>**expert parallelism（专家并行）** | 分布专家并按路由跨设备交换 token | 不会引入通信和负载问题 |
| <span id="term-context-parallelism"></span>**context parallelism（上下文并行）** | 把同一长序列的片段分到多个设备 | 就是不同样本的数据并行 |
| <span id="term-prefix-cache"></span>**prefix cache（前缀缓存）** | 在模型、配置、token 与位置兼容时复用相同前缀状态 | 文本相似、模型不同或权限隔离也能复用 |
| <span id="term-model-routing"></span>**model routing（模型路由）** | 按任务复杂度、工具需求、预算或服务状态，在模型、版本或运行档位之间选择 | 用户看到一个模型名称就证明每次请求都使用同一权重，或路由器必然准确 |
| <span id="term-model-fallback"></span>**model fallback（模型回退）** | 首选模型、区域或服务不可用时，按预设条件切换到备用模型或较低成本档位 | 发生回退就一定是故意降级，或回退不会影响质量和工具能力 |
| <span id="term-speculative-decoding"></span>**speculative decoding（推测解码）** | 草稿模型提议、目标模型批量验证；特定接受规则可保持目标分布 | 所有实现都无损，或草稿模型可绕过目标模型 |
| <span id="term-test-time-compute"></span>**test-time compute（测试时/推理时计算）** | 推理阶段投入的额外计算，可包含多次采样、搜索、验证、内部思考或工具循环，范围比单次思考预算更广 | 增加预算就等于改变训练参数 |
| <span id="term-rlvr"></span>**RLVR（可验证奖励强化学习）** | 使用程序或明确验证器产生奖励训练策略 | 验证器高分必然等于真实任务完成 |
| <span id="term-reward-hacking"></span>**reward hacking（奖励投机）** | 利用奖励漏洞拿高分却未完成真实目标 | 分数提高就必然是能力提高 |
| <span id="term-agent-harness"></span>**agent harness** | 包围模型的系统提示、工具、执行循环、上下文管理与错误恢复机制 | Agent 成绩只反映基础模型权重 |
| <span id="term-qat"></span>**QAT（量化感知训练）** | 训练时模拟目标低精度效果，让参数适应部署格式。例：训练中模拟 8-bit 线性层，再导出 8-bit 权重 | 所有组件都须同精度且不会掉点 |
| <span id="term-native-multimodal-pretraining"></span>**native multimodal pretraining（原生多模态预训练）** | 本课程指基础预训练阶段让文本和其他模态共同参与主干学习 | 宣传语“原生”足以说明训练阶段、冻结策略和数据配比 |
| <span id="term-multimodal-alignment"></span>**multimodal alignment（模态对齐）** | 让不同模态表示对应同一对象、事件或任务关系 | 张量维度能连接就表示语义已经对齐 |
| <span id="term-kda"></span>**KDA** | 以门控 delta 状态更新压缩历史的注意力 | 能无损替代全部全局注意力 |
| <span id="term-gated-mla"></span>**Gated MLA** | K3 中保留 token 级全局交互的门控潜在注意力 | 与 KDA 的固定状态读写相同 |
| <span id="term-attnres"></span>**AttnRes** | 按学习权重读取多个历史层或块表示 | 只是普通残差相加改名 |
| <span id="term-stable-latent-moe"></span>**Stable LatentMoE** | 在较窄潜空间做稀疏专家计算并稳定尺度与负载 | 所有资源成本都按同一比例下降 |
| <span id="term-quantile-balancing"></span>**Quantile Balancing** | 按路由分数分位位置更新专家选择偏置 | 一步就永久保证完全均衡 |
| <span id="term-mopd"></span>**MOPD** | 把多个领域与推理努力策略蒸馏回单一模型 | 教师总能被无损合并 |
