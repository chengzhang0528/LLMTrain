# 训练故障记录速查

本页用于审阅课程提供的预生成日志、配置和环境快照。学习者只需沿证据判断故障位置；**不要求安装环境、运行命令、修改配置或训练模型**。

| 现象 | 在预生成记录中先核对什么 | 下一组对照应只改变什么 |
|---|---|---|
| 安装记录失败 | Python、操作系统、设备平台、包版本与官方构建支持范围 | 换成版本匹配的环境快照，其余条件不变 |
| CUDA 不可用 | 驱动、运行时、框架构建、设备可见性和报错层级 | 只替换驱动或框架构建之一，比较设备探测记录 |
| OOM | batch、序列长度、精度、参数、优化器状态和激活占用 | 先比较更小 batch；仍不足时再单独比较序列长度 |
| loss 不降 | 输入与目标是否错位、梯度是否存在、学习率和遮罩是否正确 | 比较“固定一个 batch”的预生成训练曲线 |
| loss 为 NaN | 首个异常 step、输入、梯度范数、学习率、精度和数值范围 | 从首个异常点出发，每次只替换一个可疑条件 |
| train 降、val 升 | 数据泄漏、训练与验证分布、训练时长和正则化 | 先复核切分；切分无误后再比较更早停止的记录 |
| 输出乱码 | tokenizer 版本、词表、文本编码和 encode/decode 往返记录 | 只换成与检查点配套的 tokenizer 快照 |
| 生成重复 | 训练/验证差距、重复语料、解码参数和停止条件 | 先保持模型不变比较解码；再判断训练数据是否仍有问题 |
| 无法复现 | seed、配置、代码版本、数据版本、依赖和硬件记录 | 对齐缺失的一项版本，再比较相同输入的结果 |

阅读顺序是：先找到**最早出现异常的位置**，再确认这一现象属于环境、数据、训练、模型、解码还是记录问题，最后比较只改变一个主要变量的两份快照。不要用后面的连锁报错替代最初原因。

一份可审查的故障档案至少保留：原始配置、环境与数据版本、首个异常 step、完整报错或关键日志、修改前后的结果。缺少这些证据时，“已经修好”既难复核，也无法证明是哪项变化起作用。
